Self-supervised learning: labels from the data itself

Labels are expensive; raw images, audio and text are nearly free. Self-supervised learning invents a task whose answer is already in the data (fill in the hidden patch, recognise two crops of the same photo) and trains a network on billions of examples of it. The network has to understand the data to do the task, and what it learns transfers to the tasks we actually care about with very few labels. This page trains a contrastive model live, shows the collapse it must avoid, works through masked autoencoding, trains DINO's student and teacher, shows why large Vision Transformers need registers, and compares the main families.

What is self-supervised learning, in plain words?

The problem

A supervised image model needs millions of labelled pictures. Most data has no labels, and labels capture only what the labeller was asked about (“dog”), not everything in the picture. Can a network learn useful features, the kind that make later tasks easy, from unlabelled data alone?

The idea

Make a pretext task from the data itself. Hide part of the input and predict it (masked modelling, as in BERT and MAE). Or take two random augmentations of the same image and train their embeddings to agree, while disagreeing with other images (contrastive learning). Then throw the task away and keep the encoder.

How it works

  1. Collect lots of unlabelled data.
  2. Define a pretext task whose answer is in the data.
  3. Pre-train an encoder on it at scale.
  4. Evaluate with a linear probe: freeze the encoder, fit a linear classifier on a few labels.
  5. Fine-tune or use the features directly for search, clustering or detection.

An everyday picture

A child shown thousands of toys from every angle, in every light, never told their names. They come to know that the red car seen from above and the red car seen from the side are the same object, and different from the blue truck. When an adult finally says “car” once, the child generalises immediately, because the hard part, knowing what makes objects the same or different, was already learnt.

Good at
  • Uses unlabelled data, which is plentiful
  • Features that transfer to many tasks with few labels
  • The basis of foundation models in vision, speech and text
Watch out for
  • Collapse: every input mapped to the same vector
  • The augmentations decide what the model ignores
  • Pre-training is expensive; evaluation needs care

1Contrastive learning: SimCLR trained live

400 unlabelled “images” are 6-number vectors: a little meaning hidden among a lot of nuisance (think viewpoint and lighting). Augmentation changes the nuisance. The network maps each input to a point on a circle; colours are hidden classes it never sees.

SimCLR takes a batch of \(N\) images and makes two random augmentations of each (crop, colour jitter, blur, flip), giving \(2N\) views. An encoder and a small projection head map every view to a vector, normalised to unit length, \(z_i\). For a view \(i\), its partner \(j\) is the positive; the other \(2N-2\) views are negatives. With cosine similarity \(s_{ik}=z_i^\top z_k\), the NT-Xent loss (normalised temperature-scaled cross-entropy, also called InfoNCE) is

$$\ell_{i}=-\log\frac{\exp(s_{ij}/\tau)}{\sum_{k\ne i}\exp(s_{ik}/\tau)},\qquad \mathcal L=\frac{1}{2N}\sum_{i=1}^{2N}\ell_i .$$

It is a softmax classification: out of \(2N-1\) candidates, pick the one that came from the same image. Solving it needs features that survive augmentation (the meaning) and ignore what augmentation changes (the nuisance). In the lab, the raw inputs are dominated by nuisance, so a nearest-neighbour classifier on them is poor; after training, the hidden classes form separate arcs on the circle and the same classifier does far better, although no label was ever used.

Algorithm: one SimCLR step
  1. input batch \(x_1..x_N\), augmentation family \(\mathcal A\), encoder \(f\), head \(g\), temperature \(\tau\)
  2. for each \(x_n\): two views \(\tilde x_{2n-1}=a(x_n),\ \tilde x_{2n}=a'(x_n)\) with \(a,a'\sim\mathcal A\)
  3. \(z_i\leftarrow g(f(\tilde x_i))/\lVert g(f(\tilde x_i))\rVert\) for all \(2N\) views
  4. similarity matrix \(s_{ik}=z_i^\top z_k\); mask the diagonal
  5. \(\mathcal L\leftarrow\) mean cross-entropy of \(\text{softmax}_k(s_{ik}/\tau)\) against the partner of \(i\)
  6. update \(f, g\) by gradient descent; after training keep \(f\), discard \(g\)

The temperature \(\tau\) sets how hard the softmax is. Small \(\tau\) focuses the loss on the hardest negatives (the most similar wrong images), which spreads embeddings out; too small and training becomes unstable. Large \(\tau\) treats all negatives alike and the classes blur together. Big batches matter too: more negatives per step make the task harder and the features better, which is why SimCLR used batches of 4,096.

Going deeper: why InfoNCE works, and the projection head

InfoNCE is a lower bound on the mutual information between the two views: \(I(v_1;v_2)\ge\log(2N-1)-\mathcal L\). Wang and Isola (2020) give a cleaner picture: the loss rewards alignment (positives close) and uniformity (embeddings spread evenly over the sphere). The projection head \(g\) is thrown away because it learns to discard information the augmentations made irrelevant, such as colour, which may still be useful downstream; the layer before it keeps more.

Adapted from: Chen et al., A Simple Framework for Contrastive Learning of Visual Representations (SimCLR, 2020); van den Oord et al., Contrastive Predictive Coding (InfoNCE, 2018); Wang and Isola (ICML 2020).

2Collapse, and five ways to avoid it

Switch the lab to “positives only” and press Retrain. Every point slides to the same spot on the circle. The loss is perfect (any two views of an image are identical, because every output is identical) and the representation is useless. This is representation collapse, the central problem of learning from agreement alone. Every self-supervised method is, in part, a trick to rule it out:

  • Negatives (SimCLR, MoCo): push other images away. MoCo keeps a queue of past embeddings from a slowly updated momentum encoder, so it gets many negatives without huge batches.
  • Asymmetry (BYOL, SimSiam): one branch has an extra predictor and the other gets no gradient (stop-gradient), often with a momentum-averaged target network. Collapse is a solution, but the training dynamics never find it.
  • Centring and sharpening (DINO): a student matches a momentum teacher's softmax output over many “prototypes”; the teacher's outputs are centred (no prototype can dominate) and sharpened (each output must be confident).
  • Variance and decorrelation (Barlow Twins, VICReg): penalise embedding dimensions that have low variance across the batch or are correlated with each other, which a collapsed solution violates.
  • Reconstruction (MAE, BEiT): predict the actual missing content. A constant output cannot reconstruct anything, so collapse is impossible by construction.

Adapted from: He et al., MoCo (2020); Grill et al., BYOL (2020); Chen and He, SimSiam (2021); Caron et al., DINO (2021); Bardes et al., VICReg (2022).

3Masked autoencoders: why 75%?

An image cut into 8 × 8 patches. Hide a share of them at random. The right panel fills the holes the cheap way, by averaging neighbouring visible pixels. If that works, the task teaches nothing.

BERT hides 15% of the words in a sentence and predicts them. Language is dense with meaning: a missing word is hard to guess without understanding the sentence. Images are the opposite, highly redundant: a missing patch can often be filled from its neighbours with no understanding at all. The chart shows this directly: at 15% masking, plain interpolation already reconstructs the image well, so a network trained on that task could get away with learning to blur.

The masked autoencoder (MAE) therefore masks 75% of the patches. Now the visible patches are scattered, neighbours are usually missing too, and filling the holes needs a model of what objects look like. The architecture is asymmetric and that makes it cheap:

  • A large ViT encoder sees only the visible 25% of patches, no mask tokens, so pre-training costs about a quarter of the compute.
  • A small decoder receives the encoded patches plus a learnt mask token at every hidden position and predicts the pixels.
  • The loss is mean squared error on the masked patches only (with each patch's pixels normalised):
$$\mathcal L=\frac{1}{|M|}\sum_{p\in M}\big\lVert \hat x_p-x_p\big\rVert^2,\qquad M=\text{masked patches}.$$

After pre-training the decoder is discarded and the encoder, now run on all patches, is fine-tuned. MAE-pretrained ViTs fine-tune to state-of-the-art accuracy, although their frozen features are weaker for linear probing than contrastive or DINO features, a recurring trade-off between reconstruction and invariance objectives.

Algorithm: one MAE training step
  1. input image cut into patches, mask ratio \(r=0.75\)
  2. shuffle the patches; keep the first \((1-r)\) share as visible, the rest form \(M\)
  3. encode the visible patches (with their position embeddings) using the ViT encoder
  4. insert a shared mask token at every position in \(M\); run the light decoder
  5. loss = MSE between predicted and true pixels on \(M\) only; update both

Adapted from: He et al., Masked Autoencoders Are Scalable Vision Learners (CVPR 2022); Devlin et al., BERT (2019); Bao et al., BEiT (2022).

4DINO: a student learns from its own average, no labels

The same 400 unlabelled 6-number “images” as section 1. A student network outputs a softmax over 8 prototypes; a teacher, the running average of the student, supplies the targets. Each dot sits at its hidden position and is coloured by the prototype the teacher assigns it. Switch centring or sharpening off to watch the two kinds of collapse.

DINO stands for self-distillation with no labels. Distillation normally means a small student network is trained to copy the output probabilities of a big, already-trained teacher. DINO has no trained teacher: the teacher is just an average of the student's own past weights, and the student is asked to give the same answer for different crops of an image as the teacher gives for the full view.

The two networks. Student \(g_{\theta_s}\) and teacher \(g_{\theta_t}\) have the same architecture (usually a ViT plus a small head). Each maps an image \(x\) to \(K\) scores, one per prototype (a learnt “pseudo-class”; DINO uses \(K=65{,}536\), the lab uses 8). The scores become probabilities with a temperature softmax:

$$P_s(x)_k=\frac{\exp\big(g_{\theta_s}(x)_k/\tau_s\big)}{\sum_{k'}\exp\big(g_{\theta_s}(x)_{k'}/\tau_s\big)},\qquad P_t(x)_k=\frac{\exp\big((g_{\theta_t}(x)_k-c_k)/\tau_t\big)}{\sum_{k'}\exp\big((g_{\theta_t}(x)_{k'}-c_{k'})/\tau_t\big)}.$$

Here \(\tau_s\) and \(\tau_t\) are the student and teacher temperatures and \(c\) is a centre vector, explained below. The loss is the cross-entropy from the teacher's distribution to the student's, \(H(P_t,P_s)=-\sum_k P_{t,k}\log P_{s,k}\), and only the student gets gradients. Because \(H(P_t,P_s)=H(P_t)+\mathrm{KL}(P_t\,\Vert\,P_s)\) and the teacher's term is fixed, minimising it pushes the student's distribution onto the teacher's.

Multi-crop. From each image DINO cuts two global crops (each covering more than half the image, 224 × 224 pixels) and several local crops (less than half, 96 × 96). The teacher sees only the global crops; the student sees all of them. With the set of views \(V\) and the global views \(G\subset V\):

$$\mathcal L=\sum_{x\in G}\ \sum_{\substack{x'\in V\\ x'\ne x}} H\big(P_t(x),\,P_s(x')\big).$$

To match the teacher from a small patch, the student has to infer what the whole image shows (“this bit of fur belongs to a dog”), which is local-to-global correspondence. In the lab a local crop is a view with more noise on the meaningful numbers, so it carries less information than a global one.

The teacher is a moving average. After every student gradient step, \(\theta_t\leftarrow\lambda\,\theta_t+(1-\lambda)\,\theta_s\) with momentum \(\lambda\) close to 1 (0.996 rising to 1 in the paper). This is an exponential moving average (EMA): the teacher is a smoothed ensemble of recent students, so it is steadier and in practice better than the student at every point of training, which is what makes it a useful target.

Centring and sharpening stop collapse. Nothing in the loss forbids a constant output, so DINO uses two opposite forces on the teacher:

  • Centring subtracts a running mean of the teacher's scores, \(c\leftarrow m\,c+(1-m)\,\frac1B\sum_{i=1}^{B}g_{\theta_t}(x_i)\) over a batch of \(B\) images (\(m=0.9\)). No prototype can win for every image, but on its own centring pushes the outputs towards uniform.
  • Sharpening uses a low teacher temperature (\(\tau_t\approx0.04\) against \(\tau_s=0.1\)), which makes each teacher output peaked, close to one-hot. On its own sharpening lets one prototype take over.

Balanced, they leave one stable solution: every image confidently assigned, and all prototypes used. The bars under the lab show the usage of each prototype (share of images the teacher assigns to it) and the stats show two entropies (see entropy), both divided by \(\log K\) so they run from 0 to 1. With centring off, usage piles onto one or two bars and the usage entropy falls. With centring on but \(\tau_t\) raised to the student's 0.1 or above, each output goes flat (per-image entropy near 1). Either way the nearest-neighbour accuracy falls.

Algorithm: one DINO step
  1. input batch of images, student \(\theta_s\), teacher \(\theta_t\), centre \(c\), temperatures \(\tau_s,\tau_t\), momenta \(\lambda, m\)
  2. for each image: 2 global crops \(G\) and several local crops; all crops form \(V\)
  3. teacher on \(G\) only: \(P_t=\text{softmax}\big((g_{\theta_t}(x)-c)/\tau_t\big)\) // no gradient
  4. student on all of \(V\): \(P_s=\text{softmax}\big(g_{\theta_s}(x')/\tau_s\big)\)
  5. \(\mathcal L\leftarrow\) mean of \(H(P_t(x),P_s(x'))\) over pairs with \(x\in G,\ x'\ne x\)
  6. update \(\theta_s\) by gradient descent on \(\mathcal L\)
  7. \(\theta_t\leftarrow\lambda\theta_t+(1-\lambda)\theta_s\); \(\ c\leftarrow mc+(1-m)\,\text{mean}\,g_{\theta_t}(G)\)

Emergent attention maps. When the network is a ViT, the [CLS] token's self-attention in the last layer, drawn as a heat map over the image patches, outlines the main object, although no label or mask was ever used. Different heads pick out different parts. Supervised ViTs show this much less cleanly. It is a side effect of the task: to match the teacher from any crop, the [CLS] token must gather the patches that belong to the object. Section 5 shows why later, larger models lost these clean maps, and how they got them back.

DINOv2 (2023) scales the recipe into a general-purpose image encoder: 142 million automatically curated images, the DINO image-level loss plus an iBOT masked-patch loss (as in MAE patches are hidden, but the student predicts the teacher's output for them rather than pixels), Sinkhorn–Knopp centring, a KoLeo regulariser that spreads features out, and distillation of a 1-billion-parameter ViT into smaller ones. Its frozen features work, with only a linear layer on top, for classification, retrieval, semantic segmentation and depth estimation.

Going deeper: why the gradient is so simple, and what centring and sharpening do to it

With logits \(u=g_{\theta_s}(x')\), \(\partial H(P_t,P_s)/\partial u_k=(P_{s,k}-P_{t,k})/\tau_s\): the student is pulled towards the teacher, prototype by prototype. Caron et al. show the collapse trade-off directly: centring alone drives the KL divergence between consecutive teacher outputs and uniform to zero, sharpening alone drives the entropy of the teacher's output to zero, and with both the entropy settles at an intermediate value. The EMA teacher behaves like Polyak–Ruppert averaging, a known way to get a better model than the latest iterate. With \(\lambda=0\) (teacher = current student) training fails.

Adapted from: Caron et al., Emerging Properties in Self-Supervised Vision Transformers (DINO, ICCV 2021); Oquab et al., DINOv2: Learning Robust Visual Features without Supervision (2023); Zhou et al., iBOT (2022); Hinton et al., distillation (2015).

5Vision Transformers need registers

A 14 × 14 grid of patches with one object on a plain background, and the [CLS] token's attention over it. This is a small hand-built model of the effect (not a trained network): its numbers are set to mirror what Darcet et al. measured in large ViTs.

The symptom. The clean DINO attention maps of section 4 do not appear in many later, larger ViTs: DINOv2, OpenCLIP and supervised DeiT-III all show bright speckles on plain background, such as sky or wall, where nothing interesting is. Darcet et al. (2023) traced the speckles to a few output tokens whose vector length (norm) is about ten times that of the others. About 2% of patch tokens become these high-norm artifact tokens, and the histogram of token norms turns bimodal (the chart under the lab).

Where and when they appear. The artifacts sit on patches that are very similar to their neighbours, that is, redundant background. They appear only in sufficiently large models (ViT-L and up), only after a good part of training, and in the middle-to-late layers. Slide “model size and training length” down and they vanish.

Why attention goes there. The [CLS] query \(q\) attends to every token \(i\) with key \(k_i\) through a softmax over scaled dot products:

$$a_i=\frac{\exp\big(q^\top k_i/\sqrt d\big)}{\sum_{j}\exp\big(q^\top k_j/\sqrt d\big)},\qquad q^\top k_i=\lVert q\rVert\,\lVert k_i\rVert\cos\angle(q,k_i).$$

Here \(d\) is the key dimension. A token whose key is ten times longer and points the same way as \(q\) gets a score ten times larger, and because the softmax exponentiates it, it takes most of the attention mass: a handful of tokens out of 196 can absorb the majority. The heat map then shows those spots instead of the object.

What the artifacts hold. Linear probes tell the story. From an artifact token you can not recover its own position or its original pixels well, so it has thrown its local content away. But a classifier fitted on artifact tokens alone predicts the image class better than one on normal patches. The model has learnt to recycle redundant patches as scratch memory for global information: a large, well-trained network finds it useful to store and process image-level information somewhere, and the only slots it has are patch tokens whose own content it can afford to lose.

The fix: registers. Give the model dedicated slots. Append \(R\) extra learnable tokens, the registers, to the input sequence, exactly like the [CLS] token but never used for any output:

$$z_0=\big[\,x_{\text{cls}};\ r_1;\dots;r_R;\ x_1E;\dots;x_NE\,\big]+E_{\text{pos}},\qquad\text{length }1+R+N,$$

where \(x_n E\) are the \(N\) embedded patches, \(r_1..r_R\) are learnt vectors shared by all images, and \(E_{\text{pos}}\) are position embeddings (none for the registers). After the last layer the register outputs are simply thrown away. The model now parks its global computation in the registers, the artifact tokens disappear, and the norms of patch tokens are unimodal again. Switch the lab to “4 registers”: the attention that went to background patches now goes to the registers (the four slots to the right of the map, outside the image; dashed and empty when there are no registers), and the map outlines the object.

Algorithm: a ViT forward pass with registers
  1. input image cut into \(N\) patches, \(R\) learnt register vectors (\(R=4\) is enough)
  2. embed the patches, add position embeddings
  3. sequence \(\leftarrow\) [CLS] \(+\) \(R\) registers \(+\) \(N\) patch tokens
  4. for each transformer layer: self-attention over all \(1+R+N\) tokens, then MLP
  5. global information can be written into registers instead of redundant patches
  6. output: [CLS] for the image, patch tokens for dense tasks; discard the registers

The effect. With registers, attention maps of DINOv2, OpenCLIP and DeiT-III become clean; dense tasks improve slightly (semantic segmentation and depth estimation from frozen features) and unsupervised object discovery, which reads the attention map directly (the LOST method), improves a lot for DINOv2. Classification accuracy is unchanged or slightly better. The cost is \(R\) extra tokens in a sequence of hundreds, under 2% more compute. Pretrained DINOv2 checkpoints with registers are released (dinov2_vitb14_reg and friends), and they are the usual choice when patch features or attention maps are used.

Going deeper: why the original DINO had no artifacts, and later work

The original DINO ViT-S/B models were small and trained on ImageNet only; the paper finds artifacts emerge with model size and long training, which is why DINO's maps were clean and DINOv2's were not. A related finding in language models is the “attention sink”: LLMs dump attention on the first token or on delimiter tokens, again a slot with little content used as a default destination, and StreamingLLM keeps a few sink tokens for the same reason. A 2025 follow-up, “Vision Transformers Don't Need Trained Registers” (Jiang et al.), traces the artifacts to a few neurons and shifts their activations into an extra token at test time, getting much of the benefit without retraining.

Adapted from: Darcet, Oquab, Mairal and Bojanowski, Vision Transformers Need Registers (ICLR 2024); Siméoni et al., LOST (2021); Xiao et al., StreamingLLM attention sinks (2023); Jiang et al., Vision Transformers Don't Need Trained Registers (2025).

7The same thing in Python

The NT-Xent loss in PyTorch, frozen DINOv2 features with a linear probe, a pretrained MAE from Hugging Face, the DINO loss with its EMA teacher, and DINOv2 with registers.

# pip install torch torchvision transformers scikit-learn pillow
import torch, torch.nn.functional as F

# ---- 1. NT-Xent (InfoNCE) for a batch of N image pairs ----
def nt_xent(z1, z2, tau=0.2):
    z = F.normalize(torch.cat([z1, z2]), dim=1)              # (2N, d) unit vectors
    sim = z @ z.T / tau                                       # cosine similarities / temperature
    sim.fill_diagonal_(float("-inf"))                         # a view is not its own candidate
    n = len(z1)
    target = torch.cat([torch.arange(n, 2 * n), torch.arange(0, n)])   # partner of each view
    return F.cross_entropy(sim, target)

# SimCLR-style augmentations
from torchvision import transforms as T
augment = T.Compose([T.RandomResizedCrop(224, scale=(0.2, 1.0)), T.RandomHorizontalFlip(),
                     T.RandomApply([T.ColorJitter(0.4, 0.4, 0.4, 0.1)], p=0.8),
                     T.RandomGrayscale(0.2), T.GaussianBlur(23), T.ToTensor()])

# ---- 2. Frozen DINOv2 features + a linear probe ----
dino = torch.hub.load("facebookresearch/dinov2", "dinov2_vits14").eval()
prep = T.Compose([T.Resize(256), T.CenterCrop(224), T.ToTensor(),
                  T.Normalize((0.485, 0.456, 0.406), (0.229, 0.224, 0.225))])

@torch.no_grad()
def embed(pil_images):
    return dino(torch.stack([prep(im) for im in pil_images])).numpy()   # (n, 384) CLS features

# from sklearn.linear_model import LogisticRegression
# probe = LogisticRegression(max_iter=2000).fit(embed(train_imgs), train_labels)
# print(probe.score(embed(test_imgs), test_labels))

# ---- 3. A pretrained masked autoencoder ----
from transformers import AutoImageProcessor, ViTMAEForPreTraining
proc = AutoImageProcessor.from_pretrained("facebook/vit-mae-base")
mae = ViTMAEForPreTraining.from_pretrained("facebook/vit-mae-base")   # mask_ratio 0.75 by default
# out = mae(**proc(images=pil_image, return_tensors="pt"))
# out.loss: MSE on the masked patches; out.mask: which patches were hidden; out.logits: predicted pixels
# ---- 4. The DINO loss, centring and the EMA teacher ----
def dino_loss(s_out, t_out, center, tau_s=0.1, tau_t=0.04, n_global=2):
    # s_out: student logits for all crops, list of (B, K); t_out: teacher logits for the global crops
    t_prob = [F.softmax((t - center) / tau_t, dim=-1).detach() for t in t_out]   # centre + sharpen
    loss, n = 0, 0
    for i, pt in enumerate(t_prob):
        for j, s in enumerate(s_out):
            if i == j: continue                                 # same view: skip
            loss += -(pt * F.log_softmax(s / tau_s, dim=-1)).sum(-1).mean(); n += 1
    return loss / n

@torch.no_grad()
def update_teacher(student, teacher, center, t_out, lam=0.996, m=0.9):
    for ps, pt in zip(student.parameters(), teacher.parameters()):
        pt.mul_(lam).add_((1 - lam) * ps)                         # EMA of the student's weights
    return m * center + (1 - m) * torch.cat(t_out).mean(0)          # running mean of teacher logits

# ---- 5. DINOv2 with registers: check the patch-token norms ----
reg = torch.hub.load("facebookresearch/dinov2", "dinov2_vitb14_reg").eval()   # 4 registers
with torch.no_grad():
    f = reg.forward_features(prep(pil_image)[None])
patch_norms = f["x_norm_patchtokens"].norm(dim=-1)                   # (1, 256): no outliers with registers
# f["x_norm_regtokens"] holds the 4 register outputs; they are discarded for downstream tasks
# try "dinov2_vitb14" (no registers) on the same image: a few background patches stand out
