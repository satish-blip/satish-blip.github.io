Convolutional networks: how a network learns to see

A photo is a grid of numbers, and the same pattern (an edge, an eye, a wheel) can turn up anywhere in it. A convolutional network slides one small set of weights over the whole grid, so it learns each pattern once and finds it everywhere. This page builds the idea from a single multiply-and-add up to the networks that won ImageNet, with every step something you can change and watch.

What is a convolutional network, in plain words?

The problem

A small 224 × 224 colour photo is 150,528 numbers. An ordinary dense layer with just 1,000 units would need 150 million weights for its first layer alone, and it would have to learn "cat ear in the top left" and "cat ear in the bottom right" as two unrelated things. Images have structure that a dense layer ignores: nearby pixels belong together, and a pattern means the same thing wherever it appears.

The idea

A convolutional neural network replaces the giant weight matrix with a small kernel (say 3 × 3) that slides across the image. At every position it computes one weighted sum, giving a feature map that says "how much of my pattern is here". The same few weights are used at every position (weight sharing), so a pattern learned once is detected anywhere. Stacking such layers, with pooling in between, lets later layers combine edges into textures, textures into parts and parts into objects.

How it works

  1. Slide each kernel over the input and record the weighted sum at every position: one feature map per kernel.
  2. Apply a non-linearity such as ReLU.
  3. Shrink the maps with stride or pooling, so later layers see a wider area.
  4. Repeat a few times, then flatten or average and finish with an ordinary classifier.
  5. Train every kernel with backpropagation, exactly like a dense network.

An everyday picture

Checking a long wall for cracks with a small cardboard window. You do not need a different window for every part of the wall: you slide the same one along and note where something crack-like shows through. A CNN does this with dozens of windows at once (one for cracks, one for corners, one for colour changes), then repeats the process on its own notes.

Good at
  • Few parameters: a 3 × 3 kernel has 9 weights whatever the image size
  • Finds a pattern wherever it appears (translation equivariance)
  • Builds a hierarchy: edges → textures → parts → objects
  • Strong on modest data; the workhorse of vision from 2012 to today
Watch out for
  • Each unit sees only a local window; global context needs depth
  • Not invariant to rotation or scale unless trained with them
  • Can latch onto texture rather than shape
  • Very deep stacks need residual connections and normalisation to train

1Why not just use a dense layer?

Let us count. Take an image of \(H\times W\) pixels with \(C\) colour channels and compare two first layers: a dense layer with 1,000 hidden units, and a convolutional layer with 64 kernels of size \(3\times3\). Drag the image size.

Weights in the first layer, log scale. The dense layer grows with the number of pixels; the convolution does not grow at all, because the same \(3\times3\times C\) kernel is reused at every position.

Counting weights

A dense layer connects every input number to every unit, so it needs \(HWC\times1000\) weights. A convolutional layer with \(C_{\text{out}}\) kernels of size \(k\times k\) needs

$$\underbrace{k\cdot k\cdot C}_{\text{one kernel}}\times C_{\text{out}}\;+\;\underbrace{C_{\text{out}}}_{\text{biases}}$$

which does not mention \(H\) or \(W\). That is weight sharing: the kernel that finds a vertical edge in the top-left corner is the same one that finds it in the bottom-right.

Two assumptions, built in

Locality. Each output looks only at a small neighbourhood. Pixels far apart are combined later, by deeper layers.

Translation equivariance. Shift the input and the feature map shifts by the same amount. Written as an equation, with \(T\) a shift: \(\text{conv}(T x)=T\,\text{conv}(x)\). A dense layer has neither property and must learn them from data, which needs far more examples.

Going deeper: a convolution is a dense layer with most weights forced to zero

Write the image as one long vector \(x\). Any linear layer is \(y=Mx\). For a convolution, \(M\) is a huge, mostly-zero matrix in which each row holds the same \(k^2C\) kernel weights, shifted along by one position per row (a doubly block-Toeplitz matrix). So a convolution is a dense layer with two constraints: most weights are zero (locality) and the non-zero ones are tied together (sharing). Those constraints are a strong inductive bias: they shrink the set of functions the layer can represent to ones that are sensible for images, which is why CNNs learn from far fewer examples than a dense network, and why the vision transformer, which drops the bias, needs much more data (see visual tokenisation).

Libraries exploit this directly: im2col copies every \(k\times k\) window into a column of a matrix, and the whole layer becomes one big matrix multiply, which GPUs are built for.

2Convolution, one multiply-and-add at a time

This step

For output row \(i\) and column \(j\), with a \(k\times k\) kernel \(w\) and bias \(b\):

$$y_{ij}=b+\sum_{u=0}^{k-1}\sum_{v=0}^{k-1}w_{uv}\,x_{i+u,\;j+v}$$

That is all a convolutional layer computes. With the vertical edge kernel (left column −1, right column +1) the output is large where the right side of the window is brighter than the left, so it marks the left edge of the shape with positive numbers and the right edge with negative ones. Flat regions, all 0s or all 1s, give 0.

Strictly, this is cross-correlation: the mathematical convolution flips the kernel first. Every deep-learning library computes the unflipped version and calls it convolution; since the kernel is learned, the flip makes no difference.

Algorithm: 2-D convolution (one kernel, stride 1, no padding)
  1. input image \(x\) (\(H\times W\)), kernel \(w\) (\(k\times k\)), bias \(b\)
  2. \(H'\leftarrow H-k+1\), \(W'\leftarrow W-k+1\) positions where the window fits
  3. for \(i=0..H'-1\) do
  4. for \(j=0..W'-1\) do
  5. \(s\leftarrow b\)
  6. for each \((u,v)\) in the window: \(s\leftarrow s+w_{uv}\,x_{i+u,j+v}\) k² multiply-adds
  7. \(y_{ij}\leftarrow s\) one number of the feature map
  8. return feature map \(y\) (\(H'\times W'\))
Going deeper: cost, and why 3 × 3 kernels won

Each output costs \(k^2\) multiply-adds per input channel, so one layer costs \(k^2\,C_{\text{in}}\,C_{\text{out}}\,H'W'\). Two stacked \(3\times3\) layers see a \(5\times5\) area for \(2\cdot9=18\) weights per channel pair, against 25 for a single \(5\times5\); three \(3\times3\) layers see \(7\times7\) for 27 weights instead of 49, with two extra non-linearities in between. That argument, from the VGG paper (2014), is why almost every modern CNN uses small kernels stacked deep.

3Stride, padding and the output size

Three settings decide where the window lands. Stride \(S\) is how far it jumps each step. Padding \(P\) adds a border of zeros so the window can sit over the edge pixels. Dilation \(D\) spreads the kernel's taps apart to see wider for the same weights. Change them and step through the positions.

Grey cells are padding (zeros). The coloured frame is the kernel's footprint for the highlighted output cell; with dilation only the dotted taps are read.

The formula. A dilated kernel covers \(D(K-1)+1\) cells. Along one side the window can start at \(0, S, 2S,\dots\) as long as it still fits inside the padded input of length \(N+2P\):

$$N_{\text{out}}=\left\lfloor\frac{N+2P-D(K-1)-1}{S}\right\rfloor+1$$

When \(S\) does not divide evenly, the floor drops the last few input rows and columns: they are never read. Frameworks will not warn you.

RecipeSettingEffect
"Valid"\(P=0\)shrinks by \(K-1\) each layer
"Same"\(P=\frac{K-1}{2}\), \(S=1\)output size = input size
Downsample\(K=3, P=1, S=2\)halves the size (rounding up)
1 × 1 convolution\(K=1\)mixes channels at each pixel; changes depth only
Dilated\(D=2\), \(P=2\) for \(K=3\)sees 5 × 5 with 9 weights (segmentation, WaveNet)

5Channels: kernels are really boxes

A colour image has 3 channels (red, green, blue) and a hidden layer may have 256. A kernel therefore spans all input channels: its shape is \(K\times K\times C_{\text{in}}\), and it still produces one number per position. A layer has \(C_{\text{out}}\) such kernels, and their maps stacked together are the next layer's channels.

Depthwise separable convolution (MobileNet, EfficientNet) splits the work in two: one \(K\times K\) kernel per input channel that never mixes channels (depthwise), then a \(1\times1\) convolution that mixes them (pointwise). It costs \(\frac{1}{C_{\text{out}}}+\frac{1}{K^2}\) of a standard convolution, about 8 to 9 times cheaper for \(3\times3\) kernels, with a small loss of accuracy. That trade is what makes phone-sized vision models possible.

6Pooling: keep the strongest, shrink the map

Max pooling slides a 2 × 2 window with stride 2 and keeps the largest value; average pooling keeps the mean. The map halves in each direction, so the next layer covers twice the distance for the same kernel. Hover an output cell to see where it came from, then shift the input by one pixel.

feature map (8 × 8)

pooled (4 × 4)

Why pool? It throws away the exact position inside each window, which buys a little invariance: if a feature moves by one pixel, the maximum over its window often stays the same. It also cuts the computation of every later layer by four. Max pooling has no weights to learn; in backpropagation the gradient flows only to the cell that won the maximum.

Not exactly invariant. Press Shift a few times: some pooled values stay, but many change, because a one-pixel shift can move the maximum across a window boundary. Pooling gives approximate, local invariance; that is one reason modern networks also train with shifted, cropped and flipped images (data augmentation).

Many recent networks replace pooling with stride-2 convolutions, and end with global average pooling: one average per channel over the whole map, which feeds the classifier and works at any input size.

Algorithm: 2 × 2 max pooling with stride 2
  1. input feature map \(a\) (\(H\times W\))
  2. for \(i=0..H/2-1\), \(j=0..W/2-1\) do
  3. look at the window \(a_{2i..2i+1,\;2j..2j+1}\) 4 numbers
  4. \(p_{ij}\leftarrow\max\) of the window; remember which cell won
  5. backward: send \(\partial L/\partial p_{ij}\) to the winning cell, 0 to the other three
  6. return \(p\) (\(H/2\times W/2\))
Going deeper: equivariance, invariance and aliasing

Convolution with stride 1 is translation equivariant: shift in, shift out. Classification wants invariance: shift in, same answer. Pooling and striding move a network from the first towards the second, but because they subsample, they break even equivariance for shifts that are not multiples of the stride. Zhang (2019) showed that standard CNNs can flip their prediction when the input moves by one pixel, and that blurring before subsampling ("anti-aliased" pooling, the same trick as in signal processing) makes them markedly more shift-stable.

7Receptive field: how much of the image a unit sees

A unit in the first layer sees only its \(3\times3\) window. A unit in the next layer sees 3 × 3 first-layer units, which together cover 5 × 5 pixels, and so on. Its receptive field grows with every layer, and grows much faster after a stride or pooling. Pick a stack and tap a unit in the top layer.

A 1-D slice of the network: each row is a layer, each dot a unit. Lines show which units feed the selected one; shaded dots are its receptive field.

$$r_\ell=r_{\ell-1}+(k_\ell-1)\,d_\ell\,j_{\ell-1},\qquad j_\ell=j_{\ell-1}\,s_\ell,\qquad r_0=j_0=1$$

\(r\): receptive field in input pixels, \(j\): the jump, how many input pixels one step in this layer corresponds to, \(k,s,d\): kernel, stride, dilation. Adapted from Araujo, Norris & Sim, Computing receptive fields of CNNs (Distill, 2019).

Why it matters. To recognise a dog, some unit must see the whole dog. ResNet-50 ends with a receptive field of several hundred pixels, larger than its 224-pixel input. In practice the effective receptive field is smaller than this theoretical one: pixels near the centre contribute far more to a unit's output than pixels at the edge, roughly like a Gaussian (Luo et al., 2016). Attention, which connects every position to every other in one step, is the other way to get global context (see self-attention).

Algorithm: one training step of a small CNN
  1. input picture \(x\), label \(y\), kernels \(w^{(f)}\), classifier \(V\)
  2. forward: \(z^{(f)}=w^{(f)}\star x+b_f\), \(a^{(f)}=\max(0,z^{(f)})\) one map per kernel
  3. \(p^{(f)}=\text{maxpool}(a^{(f)})\), \(h=\text{flatten}(p)\), \(\hat y=\text{softmax}(Vh+c)\)
  4. loss \(L=-\log\hat y_y\)
  5. backward: \(\delta=\hat y-\text{onehot}(y)\), \(\nabla V=\delta h^\top\), \(\nabla h=V^\top\delta\)
  6. route \(\nabla h\) to each pool winner; zero it where \(z\le0\) pool and ReLU
  7. \(\nabla w^{(f)}=\nabla z^{(f)}\star x\) the gradient of a convolution is a convolution
  8. update every weight: \(\theta\leftarrow\theta-\eta\nabla\theta\)
Going deeper: backpropagation through a convolution

Each weight \(w_{uv}\) is used at every output position, so its gradient adds up the contributions from all of them:

$$\frac{\partial L}{\partial w_{uv}}=\sum_{i,j}\frac{\partial L}{\partial z_{ij}}\,x_{i+u,\,j+v}$$

That is the input convolved with the output gradient. The gradient with respect to the input, which earlier layers need, is the output gradient convolved with the kernel rotated by 180° ("full" convolution, with padding). So the backward pass of a convolution is two more convolutions, and the same fast routines serve both directions.

Weight sharing shows up here: a kernel learns from every position at once, so a picture with a stroke in the corner trains the same weights as one with the stroke in the middle.

The residual block, the key to depth

Stacking more plain layers eventually made networks worse, even on training data: the gradient signal faded on its way back through dozens of layers. A ResNet block computes a correction \(F(x)\) and adds it to its input:

$$y=\text{ReLU}\big(x+F(x)\big),\qquad F(x)=\text{BN}(W_2\star\text{ReLU}(\text{BN}(W_1\star x)))$$

If the best thing a block can do is nothing, it only has to learn \(F=0\). And in the backward pass the \(+x\) gives the gradient a direct path to every earlier layer. The residual connections page trains plain and residual networks side by side.

EfficientNet: scale all three together

Given more compute, should a network be deeper, wider or fed larger images? EfficientNet scales all three with one knob \(\phi\): depth by \(\alpha^\phi\), width by \(\beta^\phi\), resolution by \(\gamma^\phi\), with \(\alpha=1.2,\beta=1.1,\gamma=1.15\) found by a small search so that \(\alpha\beta^2\gamma^2\approx2\): each step of \(\phi\) roughly doubles the compute.

The released B1 to B7 round these numbers and use the resolutions 240, 260, 300, 380, 456, 528 and 600 pixels.

10The same thing in Python (PyTorch)

import torch, torch.nn as nn

# a LeNet-style CNN for 28 x 28 grey digits
class SmallCNN(nn.Module):
    def __init__(self, n_classes=10):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 32, kernel_size=3, padding=1), nn.ReLU(),   # (32, 28, 28): "same" padding
            nn.MaxPool2d(2),                                       # (32, 14, 14)
            nn.Conv2d(32, 64, kernel_size=3, padding=1), nn.ReLU(),  # (64, 14, 14)
            nn.MaxPool2d(2))                                      # (64, 7, 7)
        self.head = nn.Sequential(nn.Flatten(), nn.Linear(64 * 7 * 7, 128), nn.ReLU(),
                                  nn.Dropout(0.3), nn.Linear(128, n_classes))
    def forward(self, x):
        return self.head(self.features(x))

model = SmallCNN()
x = torch.randn(8, 1, 28, 28)                          # batch, channels, height, width
print(model(x).shape)                                    # torch.Size([8, 10])
print(sum(p.numel() for p in model.parameters()))        # 421,642 weights, 84% of them in the first Linear

# output size of one layer: floor((N + 2P - D(K-1) - 1) / S) + 1
conv = nn.Conv2d(3, 64, kernel_size=7, stride=2, padding=3)
print(conv(torch.randn(1, 3, 224, 224)).shape)            # (1, 64, 112, 112): the ResNet stem

# one training step
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
y = torch.randint(0, 10, (8,))
loss = nn.functional.cross_entropy(model(x), y)
opt.zero_grad(); loss.backward(); opt.step()

# a pre-trained ResNet-18 from torchvision
from torchvision.models import resnet18, ResNet18_Weights
w = ResNet18_Weights.IMAGENET1K_V1
