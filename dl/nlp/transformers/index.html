What is a transformer, in plain words?

The problem

RNNs read one word at a time, so they are slow to train (step 100 must wait for step 99) and still struggle with long-range links. Attention solves the long-range problem, but on its own it is just a weighted average: it has no notion of word order, and no place to do per-token computation. We want an architecture that keeps attention's direct connections, adds the missing pieces, and can be stacked a hundred layers deep without falling apart.

The idea

A transformer is a stack of identical blocks. Each block has a self-attention layer (tokens exchange information) and an MLP (each token is processed on its own), wrapped with residual connections and normalisation. Language models like GPT are trained to predict the next token (autoregressive); then they generate by sampling one token at a time, controlled by temperature.

How it works

  1. Tokenise and embed the text, add position information.
  2. Pass it through L blocks: attention then MLP, each with a residual add.
  3. Turn the final vector into a probability for every vocabulary token.
  4. Train on huge text (pretraining), then adapt (fine-tuning).

An everyday picture

A relay of editors each reading the whole draft and adding notes in the margin. Nobody erases anyone else’s notes; by the last editor the margin says what comes next.

Good at
  • Scales to billions of parameters and very long training
  • One design for text, code, images and audio
  • Parallel training on GPUs
Watch out for
  • Quadratic attention cost limits context length
  • Needs enormous data and compute
  • Generation is one token at a time

2Where am I? Positional encodings

Rows: positions 0 (top) to . Columns: the first of the \(d\) dimensions. Purple positive, orange negative. Left columns spin fast, right columns slowly, like the hands of a clock.

Attention by itself ignores order: shuffle the words and every token gets the same set of scores, just permuted. So position has to be written into the vectors. The 2017 transformer added a fixed pattern of sines and cosines:

$$\mathrm{PE}(t,2i)=\sin\!\frac{t}{10000^{2i/d}},\qquad \mathrm{PE}(t,2i+1)=\cos\!\frac{t}{10000^{2i/d}}$$

Dot product \(\mathrm{PE}(20)\cdot\mathrm{PE}(t)\): highest at \(t=20\) and falling with distance, so attention can tell near from far. Shifting by \(k\) is the same rotation at every position, which makes relative offsets easy to learn (see the "previous word" head on the self-attention page).

GPT-2 and BERT learn one position vector per slot instead. Most recent models use RoPE (rotary embeddings), which rotate the query and key vectors by an angle proportional to position, so \(q_t^\top k_j\) depends only on \(t-j\).

3Counting parameters: where the numbers live

Presets reproduce the published sizes: GPT-2 small 124 M, BERT-base 110 M, LLaMA-7B 6.74 B. The MLP holds about two thirds of the weights in a big model; the vocabulary table dominates a small one.

4Generating text: temperature, top-k, top-p

A language model outputs a probability for every token in the vocabulary; the text you see depends on how you pick from it. To keep it in the browser this model is a word bigram counted from a few paragraphs (it only looks at the previous word, where a transformer looks at the whole context), but the decoding rules are exactly the ones used with GPT-style models.

Temperature divides the logits before the softmax: \(p_i\propto e^{z_i/\tau}\). Below 1 sharpens, above 1 flattens. Greedy always takes the top word and soon loops. Top-k and top-p cut off the long tail of unlikely words so a high temperature does not produce nonsense. Grey bars are cut.
Algorithm: generating text with a decoder-only transformer
  1. input prompt tokens \(t_1..t_n\), \(L\) blocks, temperature \(\tau\)
  2. repeat until an end token or the length limit
  3. \(x\leftarrow\operatorname{Embed}(t)+\operatorname{Pos}\) one vector per token
  4. for each block \(l=1..L\) do
  5. \(x\leftarrow x+\operatorname{CausalAttn}(\operatorname{LN}(x))\) tokens exchange information
  6. \(x\leftarrow x+\operatorname{MLP}(\operatorname{LN}(x))\) each token thinks on its own
  7. \(z\leftarrow W_{\text{out}}\operatorname{LN}(x_{\text{last}})\) logits over the whole vocabulary
  8. \(p\leftarrow\operatorname{softmax}(z/\tau)\); sample \(t_{n+1}\sim p\) or top-k / top-p
  9. append \(t_{n+1}\) to the tokens the output becomes input
  10. return the generated tokens
Going deeper: the KV cache, and where the compute goes

Because of the causal mask, the keys and values of earlier tokens never change when a new token is appended. So a real implementation stores them (the KV cache) and, at each new step, runs the blocks only for the newest token: one query row attending over the cached keys. That turns generation from quadratic work per step into linear, at the price of memory \(2\times L\times n\times d\) numbers per sequence, which is why long contexts are expensive to serve.

Inside each block, the MLP (usually \(d\to4d\to d\)) holds about two thirds of the parameters, and attention holds the rest. A useful rule of thumb: a forward pass costs about \(2N\) floating-point operations per token for a model with \(N\) parameters, and training about \(6N\) (forward plus a backward pass twice as expensive).

6The same thing in Python

from transformers import AutoTokenizer, AutoModelForCausalLM

tok = AutoTokenizer.from_pretrained("gpt2")
model = AutoModelForCausalLM.from_pretrained("gpt2")
print(sum(p.numel() for p in model.parameters()))     # 124,439,808

ids = tok("The river was quiet and", return_tensors="pt").input_ids
out = model.generate(ids, max_new_tokens=30, do_sample=True,
                     temperature=0.8, top_k=50, top_p=0.95)
print(tok.decode(out[0]))

# one pre-norm block written out
import torch.nn as nn
class Block(nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.n1, self.n2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.attn = nn.MultiheadAttention(d, h, batch_first=True)
        self.mlp = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d))
    def forward(self, x, mask):
        a = self.n1(x)
        x = x + self.attn(a, a, a, attn_mask=mask, need_weights=False)[0]
        return x + self.mlp(self.n2(x))
