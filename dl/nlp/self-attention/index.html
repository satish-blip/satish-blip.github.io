Self-attention: every word looks at every word

In self-attention a sentence attends to itself. Each word makes a query ("what am I looking for?"), a key ("what do I offer?") and a value ("what I pass on"). Every word scores every other word, and its new vector is a mix of the values of the words that matched. One layer replaces the slow step-by-step reading of an RNN with a single parallel operation.

What is self-attention, in plain words?

The problem

In "The animal didn't cross the street because it was too tired", what does "it" mean? The answer depends on a word five positions away, and in another sentence it could be twenty. An RNN has to carry that information step by step through its hidden state. We want every word to be able to look directly at every other word in one step, decide which ones are relevant, and pull in their information.

The idea

In self-attention a sequence attends to itself: every token makes a query, a key and a value, and every token looks at every other token. Several heads run in parallel, each free to look for something different (the previous word, the noun a pronoun refers to). A causal mask stops a token seeing the future when the model generates text.

How it works

  1. Multiply each token vector by three learned matrices to get Q, K and V.
  2. Score every pair, divide by √d, mask the future if generating, softmax by row.
  3. Each token’s output is the weighted mix of all values.
  4. Do this in several heads and concatenate.

An everyday picture

A meeting where everyone can hear everyone at once. Each person decides whom to listen to, and different people listen for different things.

Good at
  • Every pair of tokens is one step apart
  • Fully parallel, so fast to train on GPUs
  • Heads specialise into readable patterns
Watch out for
  • Cost grows with the square of the length
  • Has no sense of order without positional encodings
  • Needs lots of data to learn good heads

2The causal mask: no peeking at the future

A model that generates text one token at a time (GPT and every chat model) is trained to predict word \(t+1\) from words \(1\dots t\). If word \(t\) could attend to word \(t+1\) during training, it would just copy the answer. The causal mask sets those scores to \(-\infty\) before the softmax, so their weights become exactly 0:

$$s_{tj}\leftarrow -\infty\quad\text{for } j>t\qquad\Rightarrow\qquad a_{tj}=0$$

BERT-style encoders see the whole sentence in both directions, which is better for understanding but cannot generate left to right. Flip the toggle in section 1: the upper triangle greys out, and the "previous word" head still works (it only looks back), but the adjective head breaks for any adjective whose noun comes later.

A bonus of the mask: one forward pass over a sentence of \(n\) tokens trains \(n\) predictions at once, and at generation time the keys and values of earlier tokens never change, so they are cached (the KV cache).

The mask itself for the current sentence: purple cells may attend, grey cells are blocked.

Algorithm: causal multi-head self-attention
  1. input token vectors \(X\) (\(n\times d\)), \(H\) heads, weights \(W_Q^h,W_K^h,W_V^h,W_O\)
  2. for each head \(h=1..H\) do heads run in parallel
  3. \(Q\leftarrow XW_Q^h\); \(K\leftarrow XW_K^h\); \(V\leftarrow XW_V^h\) every token makes q, k, v
  4. \(S\leftarrow QK^\top/\sqrt{d_h}\) n × n: every token scores every token
  5. \(S_{ij}\leftarrow-\infty\) for \(j>i\) causal mask: no peeking ahead
  6. \(A\leftarrow\operatorname{softmax}(S)\) row by row; \(Z_h\leftarrow AV\)
  7. \(Y\leftarrow[Z_1\,\cdots\,Z_H]\,W_O\) concatenate heads, mix them
  8. return \(Y\) same shape as X
Going deeper: why the mask lets a model train on every position at once

A language model is trained to predict token \(i+1\) from tokens \(1..i\). Without the mask, position \(i\) could simply look at token \(i+1\) and copy it. With the mask, row \(i\) of \(A\) is zero beyond column \(i\), so output \(i\) depends only on the past. That means one forward pass over a sequence of length \(n\) gives \(n\) honest training examples at once, which is the main reason transformers train so much faster than RNNs.

Setting the score to \(-\infty\) (in practice a large negative number) before the softmax, rather than zeroing weights afterwards, keeps each row a proper distribution that sums to 1. Note also that self-attention by itself is permutation-equivariant: shuffle the tokens and the outputs shuffle the same way. It has no idea of order, which is why positional encodings must be added to \(X\).

3Why divide by \(\sqrt{d}\)?

If the \(d\) numbers in a query and a key are independent with mean 0 and variance 1, their dot product has variance \(d\), so its typical size grows like \(\sqrt d\). With \(d=128\) raw scores are around ±11, and softmax of numbers that far apart puts almost all the weight on one key. Its gradient is then nearly zero (saturation) and the layer stops learning.

$$\operatorname{Var}(q^\top k)=\sum_{i=1}^{d}\operatorname{Var}(q_ik_i)=d\quad\Rightarrow\quad \operatorname{Var}\!\Big(\frac{q^\top k}{\sqrt d}\Big)=1$$

4Multi-head attention: several questions at once

One head can only produce one mixing pattern per word. Running \(h\) heads in parallel, each with its own smaller \(W_Q, W_K, W_V\), lets one head track the previous word while another resolves pronouns. Their outputs are concatenated and mixed by \(W_O\).

$$\operatorname{head}_i=\operatorname{softmax}\!\Big(\frac{XW_Q^{(i)}(XW_K^{(i)})^\top}{\sqrt{d/h}}\Big)XW_V^{(i)},\qquad \operatorname{MHA}(X)=[\operatorname{head}_1;\dots;\operatorname{head}_h]\,W_O$$

Splitting into heads does not add parameters: \(h\) heads of width \(d/h\) cost the same \(4d^2\) as one head of width \(d\). Default: GPT-2 small (\(d=768\), 12 heads of 64).

5The price: \(n^2\)

Every token scores every other token, so a sequence of \(n\) tokens makes an \(n\times n\) weight matrix per head per layer. Double the context, quadruple the work. This is why long context windows were hard and why there is so much research on cheaper attention.

  • FlashAttention computes the same result in tiles and never stores the full matrix: memory becomes linear in \(n\), the arithmetic stays \(n^2\).
  • Sliding-window and sparse attention only score nearby or selected pairs.
  • Grouped-query attention shares keys and values across heads to shrink the KV cache.

Memory to store all weight matrices of one layer (32 heads, 2 bytes per number), log-log axes. The slope of 2 is the \(n^2\).

6The same thing in Python

import torch, torch.nn.functional as F

n, d, h = 13, 64, 4
X = torch.randn(n, d)
Wq, Wk, Wv, Wo = (torch.randn(d, d) / d**0.5 for _ in range(4))
split = lambda M: M.view(n, h, d // h).transpose(0, 1)            # (h, n, d/h)
Q, K, V = split(X @ Wq), split(X @ Wk), split(X @ Wv)
mask = torch.ones(n, n).tril().bool()                                # causal
A = (Q @ K.transpose(-1, -2) / (d // h)**0.5).masked_fill(~mask, float("-inf")).softmax(-1)
out = (A @ V).transpose(0, 1).reshape(n, d) @ Wo

fast = F.scaled_dot_product_attention(Q, K, V, is_causal=True)    # fused, FlashAttention when available
assert torch.allclose((A @ V), fast, atol=1e-5)
