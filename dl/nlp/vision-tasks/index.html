Core vision tasks: what is in the picture, where, and which pixels

Classifying a whole image is only the first question. Self-driving cars need a box around every pedestrian, doctors need the exact outline of a tumour, and robots need to know which pixels belong to which object. This page walks through object detection and segmentation on pictures generated in your browser, where the true answer is known exactly, and ends with the trick that makes all of it practical: reusing a network trained on someone else's data.

What are the core vision tasks, in plain words?

The problem

A classifier answers "is there a dog in this photo?". Most real uses need more: where each dog is, how many there are, and which pixels are dog and which are sofa. The answer is no longer one label but a variable-length list of objects, each with a position and a shape, and a model has to produce that list in one go and be scored fairly when its boxes are slightly off.

The idea

Object detection outputs a bounding box, a class and a confidence for every object. Semantic segmentation gives every pixel a class; instance segmentation also separates one object from the next. All of them reuse a CNN (or a vision transformer) as a backbone that turns the image into feature maps, and add a small head for the task. Because backbones trained on millions of images transfer well, most projects start from a pre-trained one (transfer learning).

How it works

  1. A backbone turns the picture into feature maps.
  2. A detection head predicts, for many candidate places, a class score and a box adjustment.
  3. Non-maximum suppression removes duplicate boxes for the same object.
  4. A segmentation head upsamples the features back to full resolution and labels every pixel.
  5. Quality is measured by overlap with the truth: IoU for boxes and masks, mean average precision over a dataset.

An everyday picture

A teacher marking a class photo. Classification is writing "class 7B" on the back. Detection is drawing a rectangle round each child's face and writing their name. Segmentation is colouring in every child, the background and the bench with felt-tip pens; instance segmentation uses a different pen for each child.

Good at
  • Counting and locating objects, not just naming them
  • Pixel-exact outlines for measurement (medicine, satellite images)
  • Pre-trained backbones make small datasets workable
  • Real-time detectors (YOLO) run at video speed
Watch out for
  • Labels are expensive: a box takes seconds, a mask minutes
  • Small, crowded or overlapping objects are hard
  • Scores depend on the IoU threshold: always say which
  • Classes never seen in training are missed entirely (unless the model is open-vocabulary)

2Boxes, and how much two boxes agree

A box is four numbers. To score a prediction we need one number that says how well it matches the truth: intersection over union. Drag the dashed prediction box (drag inside to move it, drag its bottom-right corner to resize) and watch IoU change.

$$\text{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}=\frac{|A\cap B|}{|A|+|B|-|A\cap B|}$$

Three common ways to write the same box: corners (Pascal VOC, torchvision), corner plus size (COCO), and centre plus size as fractions of the image (YOLO). Mixing them up is the classic detection bug.

Reading IoU. 1 means identical boxes, 0 means no overlap. Pascal VOC counts a detection as correct when IoU ≥ 0.5; COCO averages over ten thresholds from 0.5 to 0.95, which rewards tight boxes. Notice how harsh IoU is for small objects: shifting a box by half its width already drops IoU to 0.33. IoU also has no gradient when boxes do not overlap, so detectors train with smoother variants (GIoU, DIoU, CIoU) or with direct regression of the box offsets.

3How a detector predicts boxes: grids and anchors

A network has a fixed number of outputs, but an image can contain any number of objects. Detectors solve this by predicting at many fixed places at once and letting most of them say "nothing here". YOLO cuts the image into an \(S\times S\) grid: the cell that contains an object's centre is responsible for it. Change the grid and see which cells must fire.

What each cell predicts

For each of its \(B\) anchor boxes a cell outputs an objectness score, \(C\) class scores and four numbers that nudge the anchor into the right box. The network does not output the box directly; it outputs offsets \((t_x,t_y,t_w,t_h)\) relative to the cell and the anchor:

$$b_x=c_x+\sigma(t_x),\quad b_y=c_y+\sigma(t_y),\quad b_w=p_w\,e^{t_w},\quad b_h=p_h\,e^{t_h}$$

where \((c_x,c_y)\) is the cell's corner and \((p_w,p_h)\) the anchor's size. The sigmoid keeps the centre inside its cell; the exponential keeps widths positive and makes "twice as big" and "half as big" symmetric. In total the head outputs an \(S\times S\times B(5+C)\) tensor, from a single forward pass: that is why YOLO ("you only look once") is fast.

Anchors are a few preset box shapes (tall, wide, square, several sizes), usually found by k-means on the training boxes using \(1-\text{IoU}\) as the distance. Switch to "Anchor boxes" to see which preset shape fits each object best.

Newer designs predict an object's centre and its distances to the four sides (FCOS, CenterNet), or treat detection as set prediction with a transformer: DETR learns 100 "object queries" that cross-attend to the image, each producing one box or "no object", and is trained with a one-to-one matching loss, so it needs no anchors and no NMS.

4Non-maximum suppression: one box per object

Neighbouring cells and anchors all see the same object, so a raw detector reports it several times. NMS keeps the most confident box and deletes the others that overlap it too much. The boxes here come from a pretend detector: jittered guesses around each true object, better guesses scoring higher, plus a few false alarms. Step through the algorithm.

Algorithm: greedy non-maximum suppression
  1. input boxes \(b_i\) with scores \(s_i\) and classes; thresholds \(\tau_{\text{score}}\), \(\tau_{\text{IoU}}\)
  2. drop boxes with \(s_i<\tau_{\text{score}}\); sort the rest by score, highest first
  3. while boxes remain do
  4. take the top box \(b^\ast\) and keep it
  5. for every other box \(b\) of the same class: if \(\text{IoU}(b,b^\ast)>\tau_{\text{IoU}}\) delete \(b\) a duplicate
  6. return the kept boxes

The threshold is a trade-off. Too low (say 0.2) and two real objects standing close together get merged into one. Too high (0.8) and duplicates survive, each counted as a false positive. 0.45 to 0.6 is typical. Soft-NMS lowers the scores of overlapping boxes instead of deleting them, which helps in crowds.

Going deeper: why greedy, and what it costs

NMS is a hand-written rule, not learned, and it runs after the network, so the network cannot learn to work around its mistakes. With \(n\) boxes it is \(O(n^2)\) in the worst case, which is why detectors first drop low scores and keep at most a few hundred candidates per class. Removing NMS entirely was one motivation for DETR, whose matching loss teaches the network itself to output each object once; recent YOLO versions (v10) use the same one-to-one idea.

5Precision, recall and mean average precision

How good is a detector over a whole dataset? Sort all its detections by confidence and walk down the list: each one is a true positive if it overlaps an unmatched true box with IoU above the threshold, otherwise a false positive. Precision and recall after each step trace a curve; the area under it is the average precision (AP) for that class, and mAP averages AP over classes. Here the pretend detector runs on 40 scenes.

Precision against recall for each class (circle, square, triangle). Dotted: the curve as measured; solid: the interpolated "envelope" whose area is AP.

Algorithm: average precision for one class
  1. input all detections of the class over the dataset, the true boxes, IoU threshold \(\tau\)
  2. sort the detections by score, highest first
  3. for each detection do
  4. if it overlaps a not-yet-matched true box with IoU ≥ \(\tau\): TP, mark that box matched; else FP
  5. precision \(=\frac{TP}{TP+FP}\), recall \(=\frac{TP}{\#\text{true boxes}}\)
  6. make precision non-increasing: \(p(r)\leftarrow\max_{r'\ge r}p(r')\) the envelope
  7. \(\text{AP}\leftarrow\) area under the envelope

Three numbers you will see quoted. AP50 or mAP@0.5 uses \(\tau=0.5\) (Pascal VOC). AP75 uses 0.75. COCO mAP, written AP or mAP@[.5:.95], averages AP over \(\tau=0.50,0.55,\dots,0.95\) and over classes; it is the headline number on detection leaderboards and is much lower than AP50 for the same model.

Try the raw setting: duplicates become false positives, so precision falls. Raise the IoU threshold: the loose boxes stop counting and AP drops, most of all for a poor detector.

Adapted from: the Pascal VOC (Everingham et al., 2010) and COCO detection evaluation definitions. This page uses all-point interpolation; COCO samples the envelope at 101 recall points, which gives nearly the same value.

6Segmentation: a label for every pixel

A classifier shrinks the image to a single vector. A segmenter must also come back up to full size. The U-Net does both: an encoder that shrinks and deepens, a decoder that grows back, and skip connections that hand fine detail straight across. Below it, try promptable segmentation: click any object and a mask grows from your click.

U-Net with a 256 × 256 input and four levels. Boxes: feature maps (height ∝ size, width ∝ channels). Down arrows: 2 × 2 max pooling. Up arrows: 2 × 2 transposed convolution. Dashed: skip connections, concatenated onto the decoder.

Why the U shape works

Going down, each level halves the resolution and doubles the channels, so deep features know what is in a large area but have lost where exactly. Going up, transposed convolutions double the resolution, and the skip connection concatenates the encoder's feature map of the same size, which still has sharp edges. The last layer is a \(1\times1\) convolution giving \(C\) class scores per pixel, trained with per-pixel cross-entropy, often plus a Dice loss.

$$\text{Dice}=\frac{2|A\cap B|}{|A|+|B|},\qquad \text{IoU}=\frac{|A\cap B|}{|A\cup B|},\qquad \text{Dice}=\frac{2\,\text{IoU}}{1+\text{IoU}}$$

U-Net was designed in 2015 for microscope images with only 30 labelled training pictures, and is still the default for medical images; it is also the denoising network inside diffusion models such as Stable Diffusion.

Segment Anything (SAM)

SAM (Meta, 2023) is a promptable segmenter: give it a click, a box or a rough mask and it returns the matching object's mask, for objects and categories it was never explicitly taught. Three parts:

  1. Image encoder: a large vision transformer (MAE pre-trained) runs once per image and gives a 64 × 64 grid of embeddings.
  2. Prompt encoder: points and boxes become small positional embeddings.
  3. Mask decoder: a light two-layer transformer cross-attends between the prompt and the image embedding and outputs three candidate masks (whole, part, sub-part) with a predicted IoU for each, because a single click is ambiguous.

The heavy encoder runs once; each new click costs only the tiny decoder, which is why SAM feels interactive. It was trained on SA-1B: 11 million images with 1.1 billion masks, most produced by SAM itself in a model-in-the-loop data engine. SAM 2 (2024) extends this to video.

Instance masks: Mask R-CNN

Mask R-CNN (2017) adds a third head to Faster R-CNN: for every detected box, a small fully convolutional network predicts a 28 × 28 mask inside the box, which is resized to the box. It also replaced RoI pooling's rounding with RoIAlign, bilinear sampling at exact positions, which matters for pixel-accurate masks. Detect first, then segment inside each box: that is still how most instance-segmentation systems work, and "a detector's boxes as SAM prompts" is a popular modern version.

Adapted from: Ronneberger, Fischer & Brox, U-Net (2015), Kirillov et al., Segment Anything (2023) and He et al., Mask R-CNN (2017).

Which strategy when?

Three ways to reuse a network. Feature extraction: freeze every pre-trained layer and train only a new classifier on top; cheap and hard to overfit. Fine-tuning: start from the pre-trained weights and keep training all (or the top few) layers on the new data, usually with a learning rate 10 times smaller so the useful features are adjusted, not erased. From scratch: random weights; only sensible with a lot of data or images unlike anything the backbone has seen. Yosinski et al. (2014) showed that features from the first layers transfer almost perfectly between tasks, and the last layers least.

Practical recipe. Load an ImageNet backbone, replace the final layer with one for your classes, freeze the backbone for a few epochs to train the new head, then unfreeze and fine-tune everything with a small learning rate, with data augmentation (flips, crops, colour jitter) and the same input normalisation the backbone was trained with.

import torch, torchvision
from torchvision.ops import box_iou, nms

# IoU and NMS (boxes as x0, y0, x1, y1)
boxes  = torch.tensor([[10, 10, 60, 60], [12, 14, 62, 58], [100, 100, 150, 140]], dtype=torch.float)
scores = torch.tensor([0.9, 0.75, 0.6])
print(box_iou(boxes, boxes))                 # 3 x 3 matrix of IoUs
print(nms(boxes, scores, iou_threshold=0.5))  # tensor([0, 2]): box 1 was a duplicate of box 0
