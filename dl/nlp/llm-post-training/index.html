Post-training: from text predictor to helpful assistant

A pre-trained base model has read the internet, but ask it a question and it may answer with three more questions, because that is what text on the internet often does next. Post-training teaches it to follow instructions, to be helpful and honest, and to refuse what it should refuse. This page walks through the recipe used for today's assistants: supervised fine-tuning, parameter-efficient LoRA and QLoRA, a reward model learnt from human preferences, reinforcement learning from human feedback, and Direct Preference Optimization, which gets the same answer without the reinforcement learning.

What is post-training, in plain words?

The problem

After pre-training, a base model is very good at continuing text, and that is all. It does not know it is supposed to answer you, it has no sense of which of many plausible continuations a person would prefer, and it will happily continue harmful text. How do we turn knowledge into helpful behaviour, cheaply, without starting over?

The idea

Two kinds of extra data, both far smaller than the pre-training corpus. First, demonstrations: good conversations written by people, used for supervised fine-tuning. Second, comparisons: two answers to the same prompt and a judgement of which is better. Comparisons are easier to give than perfect answers, and they drive RLHF or DPO, which push the model towards answers people prefer without drifting too far from what it already knows.

How it works

  1. SFT: train on example conversations, scoring only the assistant's words.
  2. Collect preference pairs: for a prompt, which of two answers is better?
  3. Either fit a reward model and run RL against it (RLHF), or optimise the preferences directly (DPO).
  4. Evaluate, red-team, and repeat; often with LoRA so only a sliver of the weights is trained.

An everyday picture

A brilliant graduate who knows a lot but has never worked with customers. First they shadow experienced staff and copy what good replies look like (SFT). Then a manager reads pairs of their draft replies and says “this one is better” (preferences). Over time they learn what good service means, while their knowledge stays the same; a good manager also stops them from changing their whole personality to please one difficult customer (the KL leash).

Good at
  • Huge change in behaviour from a small amount of data
  • LoRA and QLoRA make it possible on one GPU
  • Preferences capture “better” when “correct” is hard to write down
Watch out for
  • Reward hacking: the model exploits flaws in the reward
  • Preference data carries labeller biases (for example, liking long answers)
  • Fine-tuning can erase skills or safety behaviour if done carelessly

1Supervised fine-tuning: learn to answer, not to ask

A training conversation laid out the way the model sees it, with its special tokens. Choose which tokens the loss is computed on, then see how SFT shifts what the model writes after a question.

Green tokens contribute to the loss. The bars are a toy illustration of what comes after “What is the capital of France?”, not measurements of a real model.

SFT is the same next-token loss as pre-training, on a different dataset: conversations between a user and an ideal assistant, written or checked by people. Each conversation is turned into one token sequence with a chat template, which wraps every turn in special tokens that mark who is speaking (<|user|>, <|assistant|>, <|end|>, or similar; each model family has its own).

Write a training example as a prompt \(x\) (system message and user turns) and the response \(y=(y_1,\dots,y_T)\). We want the model to produce \(y\) given \(x\), not to learn to write user questions, so the loss covers only the response:

$$\mathcal L_{\text{SFT}}(\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log\pi_\theta\big(y_t\mid x,\,y_{<t}\big).$$

In code this is a loss mask: the targets at prompt positions are set to an ignore value (−100 in PyTorch) so they add nothing to the gradient. Switch the lab to “every token” and the count of loss tokens grows, but most of the extra ones teach the model to imitate users.

How much data? Surprisingly little. The LIMA paper fine-tuned a 65B model on 1,000 carefully chosen examples and got an assistant that people often preferred to ones trained on far more data. The authors' conclusion, the superficial alignment hypothesis, is that almost all knowledge comes from pre-training, and SFT mainly teaches the format and style of a helpful answer. Quality and diversity of the demonstrations matter more than their number.

Going deeper: packing, multi-turn data and catastrophic forgetting

Packing. Conversations vary in length, so short ones are concatenated into one long training sequence to avoid wasting computation on padding; attention masks or position resets keep them from seeing each other.

Multi-turn. In a conversation with several assistant turns, each assistant turn is a target and each user turn is masked. The model learns to use the whole history as context.

Forgetting. Fine-tuning all weights on a narrow dataset with a high learning rate can erase abilities learnt in pre-training. Small learning rates (around 1e-5 for full fine-tuning), few epochs, mixing in general data, and LoRA (next section) all reduce it.

The 1,000-example result is from Zhou et al., LIMA: Less Is More for Alignment (NeurIPS 2023).

2LoRA and QLoRA: fine-tune 0.1% of the weights

Pick a model, a LoRA rank and which weight matrices get adapters. The calculator counts trainable parameters and the GPU memory for weights, gradients and optimiser state in three set-ups.

Memory for weights + gradients + AdamW state only. Activations come on top and depend on batch size and sequence length; gradient checkpointing trims them.

Full fine-tuning updates every weight. For an 8B model that means 8 billion gradients and 16 billion Adam moments, about 16 bytes per parameter in mixed precision: over 120 GB before any activations. Most of us do not have that.

Hu et al. (2021) observed that the change fine-tuning makes to a weight matrix tends to have low intrinsic rank: it lives in a few directions. LoRA (low-rank adaptation) builds that in. Freeze the pre-trained matrix \(W_0\in\mathbb R^{d\times k}\) and learn the update as a product of two thin matrices:

$$h=W_0x+\Delta W x=W_0x+\frac{\alpha}{r}\,B A x,\qquad B\in\mathbb R^{d\times r},\;A\in\mathbb R^{r\times k},\;r\ll\min(d,k).$$

The trainable parameters drop from \(dk\) to \(r(d+k)\). For a \(4096\times4096\) projection with \(r=16\), that is 131k instead of 16.8M, 128 times fewer. \(A\) starts random and \(B\) starts at zero, so at step 0 the model is exactly the pre-trained one; \(\alpha/r\) is a fixed scale so the learning rate does not need retuning when you change \(r\). After training, \(BA\) can be added into \(W_0\), so inference costs nothing extra; or adapters can be kept separate and swapped per task. The SVD page shows why a rank-\(r\) product is the best way to store “a few directions”.

QLoRA (Dettmers et al., 2023) goes further: store the frozen \(W_0\) in 4 bits using the NF4 data type (quantile levels designed for normally distributed weights), quantise the quantisation constants too (“double quantisation”), and backpropagate through the 4-bit weights into bf16 LoRA adapters. A 65B model could then be fine-tuned on one 48 GB GPU with no measured loss against 16-bit fine-tuning on their benchmarks.

Going deeper: which rank, which layers, and LoRA's relatives

Ranks of 8 to 64 are typical. The QLoRA paper found that putting adapters on all linear layers mattered more than the rank. Variants include DoRA (separates magnitude and direction of the update), LoRA+ (different learning rates for \(A\) and \(B\)), and prefix tuning and adapters, which add parameters elsewhere. The LLM adaptation map compares all of these with RAG and prompting.

LoRA is not free: on tasks far from pre-training (a new language, lots of new knowledge) low-rank updates learn less than full fine-tuning, though they also forget less.

Adapted from: Hu et al., LoRA: Low-Rank Adaptation of Large Language Models (2021); Dettmers et al., QLoRA: Efficient Finetuning of Quantized LLMs (2023). Model shapes from the Llama 2 and Llama 3 model cards.

3A reward model, trained live from preferences

Simulated labellers compare pairs of answers described by four features. A linear reward model learns from “A is better than B” alone. Compare its weights with the hidden truth.

People find it hard to give an answer a score out of 10, but easy to say which of two answers is better. So the data is a set of triples \((x, y_w, y_l)\): a prompt, the preferred (“winning”) answer and the other one. How do we turn comparisons into a number?

Assume each answer has a hidden quality \(r(x,y)\), and that the chance a person prefers \(y_w\) grows with the gap in quality. The Bradley–Terry model (1952), the same model behind chess ratings, says

$$P(y_w\succ y_l\mid x)=\sigma\big(r(x,y_w)-r(x,y_l)\big)=\frac{1}{1+e^{-(r_w-r_l)}} .$$

A reward model \(r_\phi\), usually the SFT model with its output layer replaced by a single number, is fitted by maximum likelihood on the comparisons:

$$\mathcal L_{\text{RM}}(\phi)=-\,\mathbb E_{(x,y_w,y_l)}\Big[\log\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)\Big].$$

This is logistic regression on differences. In the lab each answer is four numbers (helpfulness, correctness, harmfulness, length) and \(r_\phi\) is linear in them, so you can read the learnt weights. Two things to notice:

  • Only differences are learnt, so rewards have no natural zero; adding a constant changes nothing. With few pairs the weights are noisy, and accuracy on new pairs is capped by the labellers' own randomness.
  • Raise “liking for length”. The reward model faithfully learns that longer is better, even though length is not what anyone wants. A policy optimised against this reward will learn to pad. This is a well-documented real effect: RLHF models' answers get longer.

Adapted from: Ouyang et al., Training language models to follow instructions with human feedback (InstructGPT, 2022), section 3.5; on length, Singhal et al., A Long Way to Go: Investigating Length Correlations in RLHF (2023).

4RLHF: maximise reward, on a KL leash

Eight candidate answers to one prompt. The reference (SFT) model's probabilities are grey; the reward model's scores are on the right. Loosen the leash β and watch the optimal policy, the proxy reward and the true quality.

With a reward model in hand, we want a policy \(\pi_\theta\) (the language model) that writes answers with high reward. But the reward model is only an approximation, trained on a limited set of answers; far from those, its scores are unreliable. So RLHF maximises reward while penalising how far the policy moves from the reference model \(\pi_{\text{ref}}\) (the SFT model), measured by KL divergence:

$$\max_{\pi}\;\mathbb E_{x,\;y\sim\pi(\cdot\mid x)}\big[r(x,y)\big]\;-\;\beta\,\mathrm{KL}\big(\pi(\cdot\mid x)\,\big\|\,\pi_{\text{ref}}(\cdot\mid x)\big).$$

For one prompt, this objective has an exact solution. Write the KL as \(\sum_y\pi(y)\log\frac{\pi(y)}{\pi_{\text{ref}}(y)}\), add a Lagrange multiplier for \(\sum_y\pi(y)=1\), and set the derivative to zero:

$$r(y)-\beta\Big(\log\frac{\pi(y)}{\pi_{\text{ref}}(y)}+1\Big)-\lambda=0\;\;\Longrightarrow\;\;\pi^*(y)=\frac{1}{Z}\,\pi_{\text{ref}}(y)\,\exp\!\Big(\frac{r(y)}{\beta}\Big).$$

The optimal policy re-weights the reference by the exponentiated reward. Large \(\beta\): stay close to the SFT model. Small \(\beta\): pile all probability onto the highest-reward answer. The lab computes \(\pi^*\) exactly.

Now the catch. Answer H was written to game the reward model: long, confident and flattering, it scores highest under the proxy reward but its true quality is poor. As β shrinks, proxy reward keeps rising while true quality first rises, then collapses. This is reward hacking, an instance of Goodhart's law (“when a measure becomes a target, it ceases to be a good measure”). Gao et al. (2023) measured exactly this curve on real models: gold-standard reward peaks and then falls as KL from the start grows.

Algorithm: RLHF with PPO
  1. input SFT model \(\pi_{\text{ref}}\), reward model \(r_\phi\), prompts, KL weight \(\beta\)
  2. \(\pi_\theta\leftarrow\pi_{\text{ref}}\) plus a value head for PPO
  3. repeat
  4. sample prompts \(x\) and answers \(y\sim\pi_\theta(\cdot\mid x)\)
  5. score: \(R\leftarrow r_\phi(x,y)-\beta\log\frac{\pi_\theta(y\mid x)}{\pi_{\text{ref}}(y\mid x)}\) reward minus KL penalty
  6. estimate advantages of each token with the value head
  7. update \(\theta\) with PPO's clipped objective for a few epochs on this batch
  8. return \(\pi_\theta\)
Going deeper: PPO, GRPO, and rewards you can verify

PPO (proximal policy optimisation) is a policy-gradient method that limits each update by clipping the probability ratio \(\pi_\theta/\pi_{\text{old}}\) to \([1-\epsilon,1+\epsilon]\). It needs four models in memory at once (policy, reference, reward, value), which is part of why RLHF is expensive and finicky.

GRPO (group relative policy optimisation, used for DeepSeek's reasoning models) drops the value model: sample a group of answers per prompt and use each answer's reward minus the group mean, divided by the group's standard deviation, as its advantage.

Verifiable rewards. For maths and code, the reward can be a checker (is the final answer right, do the tests pass) instead of a learnt model, which is much harder to hack. Training with such rewards is how recent reasoning models learn long chains of thought. RLAIF and Constitutional AI replace human labellers with an AI judge guided by written principles.

Adapted from: Ouyang et al., InstructGPT (2022); the closed-form optimum as derived in Rafailov et al., Direct Preference Optimization (2023), appendix A.1; Gao, Schulman and Hilton, Scaling Laws for Reward Model Overoptimization (2023); Schulman et al., PPO (2017); Shao et al., DeepSeekMath (GRPO) (2024).

5DPO: preferences straight into the policy

The same eight answers. Simulated people compare random pairs using the true quality; DPO trains the policy on those comparisons directly, with no reward model and no RL. Does it reach the KL-optimal policy?

Rafailov et al. (2023) noticed that the closed form in section 4 can be turned around. If \(\pi^*(y)=\pi_{\text{ref}}(y)\,e^{r(y)/\beta}/Z\), then taking logs and rearranging expresses the reward through the policy:

$$r(x,y)=\beta\log\frac{\pi^*(y\mid x)}{\pi_{\text{ref}}(y\mid x)}+\beta\log Z(x).$$

Put this into the Bradley–Terry model. The awkward \(Z(x)\) is the same for both answers to a prompt, so it cancels in the difference \(r_w-r_l\). What remains is a loss on the policy alone, the DPO loss:

$$\mathcal L_{\text{DPO}}(\theta)=-\,\mathbb E\Big[\log\sigma\Big(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)}-\beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\Big)\Big].$$

Read it as: raise the log-probability of the winner and lower that of the loser, each measured relative to the reference, and push harder on pairs the model currently gets wrong. The quantity \(\beta\log\frac{\pi_\theta}{\pi_{\text{ref}}}\) is the implicit reward: the policy is secretly its own reward model.

In the lab, train and compare the bars with the dashed outline, the exact KL-optimal policy for the true qualities. With enough comparisons DPO lands on it; and because the comparisons come from people judging true quality, not from a hackable proxy, answer H is pushed down. DPO is simple (one model plus a frozen reference, an ordinary supervised loss) and is now one of the most used alignment methods, with many variants (IPO, KTO, SimPO, ORPO).

Algorithm: one DPO training step
  1. input a batch of \((x, y_w, y_l)\), policy \(\pi_\theta\), frozen \(\pi_{\text{ref}}\), \(\beta\)
  2. for each pair: sum token log-probs \(\log\pi_\theta(y\mid x)\) and \(\log\pi_{\text{ref}}(y\mid x)\) for \(y_w\) and \(y_l\)
  3. \(\hat r_w\leftarrow\beta(\log\pi_\theta(y_w)-\log\pi_{\text{ref}}(y_w))\); \(\hat r_l\) likewise implicit rewards
  4. \(\ell\leftarrow-\log\sigma(\hat r_w-\hat r_l)\)
  5. \(\theta\leftarrow\theta-\eta\,\nabla_\theta\,\text{mean}(\ell)\) weight on each pair is σ(r̂_l − r̂_w)
  6. return \(\theta\)
Going deeper: the gradient, and when DPO goes wrong

Differentiating gives \(\nabla_\theta\mathcal L=-\beta\,\mathbb E\big[\sigma(\hat r_l-\hat r_w)\,(\nabla\log\pi_\theta(y_w)-\nabla\log\pi_\theta(y_l))\big]\). The weight \(\sigma(\hat r_l-\hat r_w)\) is large when the implicit reward ranks the pair the wrong way, so DPO concentrates on its mistakes, just like logistic regression.

DPO only sees the answers in the dataset (it is offline). If the preference data was generated by a different model, the policy can drift towards answers nobody ever judged. Online or iterative DPO, which regenerates and re-labels answers from the current policy, fixes much of this. Both answers in a pair can also lose probability at once; methods such as adding an SFT term on the winners counter this.

Adapted from: Rafailov, Sharma, Mitchell, Ermon, Manning and Finn, Direct Preference Optimization: Your Language Model is Secretly a Reward Model (NeurIPS 2023), equations 4–7.

7The same thing in Python

Hugging Face TRL and PEFT: QLoRA-style SFT, then DPO on preference pairs. Dataset names are examples from the Hugging Face Hub.

# pip install torch transformers datasets peft trl bitsandbytes
import torch
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig
from trl import SFTConfig, SFTTrainer, DPOConfig, DPOTrainer

base = "meta-llama/Llama-3.1-8B"                 # any causal LM you have access to
tok = AutoTokenizer.from_pretrained(base)

# QLoRA: load the frozen base model in 4-bit NF4 with double quantisation
bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=torch.bfloat16)
model = AutoModelForCausalLM.from_pretrained(base, quantization_config=bnb, device_map="auto")

lora = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05, task_type="CAUSAL_LM",
                  target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                                  "gate_proj", "up_proj", "down_proj"])

# 1) SFT on conversations ("messages" column); the chat template is applied for you,
#    and assistant_only_loss masks the user turns out of the loss
sft = SFTTrainer(model=model, processing_class=tok, peft_config=lora,
                 train_dataset=load_dataset("HuggingFaceH4/ultrachat_200k", split="train_sft[:5%]"),
                 args=SFTConfig(output_dir="sft-out", learning_rate=2e-4, num_train_epochs=1,
                                per_device_train_batch_size=4, gradient_accumulation_steps=4,
                                assistant_only_loss=True, bf16=True))
sft.train()

# 2) DPO on (prompt, chosen, rejected) pairs; the frozen reference is the SFT model
dpo = DPOTrainer(model=sft.model, processing_class=tok,
                 train_dataset=load_dataset("trl-lib/ultrafeedback_binarized", split="train"),
                 args=DPOConfig(output_dir="dpo-out", beta=0.1, learning_rate=5e-6, bf16=True))
dpo.train()

print(sft.model.print_trainable_parameters())   # e.g. ~0.5% of weights are trainable

Argument names follow recent TRL releases and change between versions; check the TRL documentation for the one you install. For a reward model and PPO, TRL provides RewardTrainer and PPOTrainer; for GRPO, GRPOTrainer.
