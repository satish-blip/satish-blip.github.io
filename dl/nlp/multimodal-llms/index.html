Multimodal LLMs: teaching a language model to see

CLIP (part 4) learned to match pictures and captions. It cannot talk about a picture. A large language model can talk, but it has never seen a pixel. From 2021 to 2023 a run of models joined the two, and almost all of them use the same trick: keep a strong vision encoder and a strong language model, freeze most of both, and train a small bridge that turns image features into something the language model can read as if it were words. This page walks through eight of them. Each diagram is animated: press Play to watch features and tokens move between the blocks.

One recipe, three blocks

The three blocks

1. A vision encoder. Usually a Vision Transformer (ViT) taken from CLIP or a similar model. It cuts the image into patches and returns one feature vector per patch, for example 256 vectors of length 1024. It already knows a lot about what is in pictures, so it is usually frozen: its weights are not changed.

2. A bridge (also called a connector, adapter or projector). The language model expects vectors of its own size and its own "meaning space", for example 4096 numbers per token. The bridge maps patch features into that space. It can be a single linear layer (LLaVA, MiniGPT-4), a small transformer with learned query vectors that pulls a fixed number of tokens out of the image (BLIP-2's Q-Former, Flamingo's Perceiver Resampler, mPLUG-Owl's visual abstractor), or new cross-attention layers inside the language model (Flamingo). The bridge is almost always trained.

3. A large language model (LLM), such as LLaMA, Vicuna, OPT or Chinchilla. It reads the visual tokens followed by the text prompt and writes the answer one token at a time. It is often frozen too, or tuned lightly at the end.

Why freeze so much?

Training a 7-billion-parameter language model from scratch costs millions of dollars. Freezing it keeps its language skill and its knowledge intact, and the bridge has only a few million parameters, so it can be trained on a few million image–caption pairs in a day or two. The danger of tuning everything on a small image dataset is catastrophic forgetting: the model gets better at captions and worse at everything else.

1Frozen (2021): the language model stays frozen, the image becomes a prompt

Tsimpoukelli et al., DeepMind. The first to show that a frozen language model can read images if the image is turned into a few "word-like" vectors.

Idea. Take a pre-trained 7-billion-parameter language model and do not touch it. Train only a vision encoder (an NF-ResNet-50) whose output is reshaped into two vectors of the language model's embedding size. These two vectors are placed in front of the caption, like a prefix of two extra "words". The training task is captioning: predict the caption tokens.

The surprising part. The gradient of the captioning loss flows back through the frozen language model into the vision encoder. So the vision encoder learns to speak the language model's internal language, without the language model changing at all.

Why it mattered. Because the language model is untouched, it keeps its in-context learning. Show it two (image, word) examples, and it can name a new object in a third image: few-shot learning across modalities, from a model trained only on captions.

Trained: vision encoder + prefix projection. Frozen: the whole LM.

2Flamingo (2022): new cross-attention layers inside a frozen LLM

Alayrac et al., DeepMind. Handles many images interleaved with text, and learns new tasks from a few examples in the prompt.

Perceiver Resampler. The frozen vision encoder (NFNet) returns a different number of features for each image or video. The resampler has 64 learned query vectors; they cross-attend to all the features and come out as exactly 64 visual tokens per image. Fixed size in, whatever the input size.

Gated cross-attention. Between the frozen blocks of the Chinchilla language model, Flamingo inserts new GATED XATTN-DENSE layers. In them, the text tokens are the queries and the 64 visual tokens are the keys and values: the text "looks at" the image. The result is multiplied by tanh(α), with α starting at 0. At the start of training tanh(0) = 0, so the new layers add nothing and the LM behaves exactly as before; the gate opens slowly as training finds useful visual information. This keeps training stable.

Interleaving. Each text token attends only to the image that came just before it, so a prompt like "<img> a cat. <img> a dog. <img>" works as a few-shot prompt.

Trained: resampler + gated cross-attention layers. Frozen: vision encoder and LM.

3BLIP (2022): one model, three jobs, and cleaner data

Li et al., Salesforce. Bootstrapping Language-Image Pre-training. Everything is trained here; the new ideas are the shared model and the data cleaning.

Three jobs, three losses. A ViT encodes the image. A BERT-like text model is used in three modes that share most weights:

• ITC, image–text contrastive: a plain text encoder; pull matching image and text vectors together, push others apart (like CLIP).
• ITM, image–text matching: the text encoder with cross-attention to the image patches, answering "does this caption match this image?" (yes/no).
• LM, language modelling: a text decoder with cross-attention and causal masking that writes the caption.

CapFilt. Web captions are noisy ("IMG_2041.jpg", "best price!"). BLIP fine-tunes a Captioner to write a new caption for each web image and a Filter (the ITM head) to drop pairs that do not match. The cleaned dataset is used to pre-train again, and the model gets better: the model cleans its own data.

Trained: everything (no frozen LLM; BLIP is a few hundred million parameters).

4BLIP-2 (2023): the Q-Former bridges two frozen models

Li et al., Salesforce. Uses about 54× fewer trainable parameters than Flamingo-80B and beats it on zero-shot visual question answering.

Q-Former. A small transformer (188 M parameters) with 32 learned query vectors. The queries self-attend to each other, cross-attend to the frozen ViT's patch features, and come out as 32 vectors that hold the visual information most useful for language. A linear layer maps them to the LLM's embedding size, and they are put in front of the prompt as a soft visual prompt.

Stage 1, representation learning (no LLM yet): the Q-Former is trained with BLIP's three jobs (ITC, ITM, and image-grounded text generation) against the frozen ViT. This forces the 32 queries to pick out what text can describe.

Stage 2, generative learning: connect the Q-Former output to a frozen LLM (OPT or Flan-T5) through the linear layer, and train on captioning, so the LLM learns nothing new; only the bridge learns to speak to it.

Trained: Q-Former + linear layer. Frozen: ViT and LLM.

5LLaVA (2023): a linear layer and good instruction data

Liu et al. Large Language and Vision Assistant: shows that a very simple bridge works if the training data teaches the model to follow instructions.

Architecture. A frozen CLIP ViT-L/14 gives 256 patch features. One trainable matrix W maps each to the LLM's word-embedding size: Hv = W·Zv. All 256 visual tokens go in front of the instruction, and the Vicuna LLM writes the answer. (LLaVA-1.5 swaps W for a two-layer MLP.)

Data. The new ingredient. Text-only GPT-4 was given the captions and object boxes of COCO images and asked to write conversations, detailed descriptions and reasoning questions about them: 158 K instruction-following examples.

Stage 1, feature alignment: 595 K image–caption pairs; train only W (ViT and LLM frozen). Stage 2, end-to-end fine-tuning: the 158 K instruction data; train W and the LLM, ViT still frozen.

Trained: W (stage 1), W + LLM (stage 2). Frozen: ViT.

6MiniGPT-4 (2023): BLIP-2's eyes, Vicuna's voice, one linear layer

Zhu et al., KAUST. Shows that aligning a frozen visual encoder to a strong chat LLM gives many GPT-4-like abilities, such as writing a story or a recipe from a photo.

Architecture. The frozen ViT and the frozen Q-Former are taken straight from BLIP-2, so the 32 query outputs already carry language-friendly visual information. A single linear projection maps them into Vicuna's embedding space. Vicuna is frozen. That linear layer is the only thing trained.

Stage 1: about 5 M image–caption pairs. The model learns to describe images, but its answers are often repetitive or broken.

Stage 2: just 3,500 high-quality, detailed image descriptions in a chat template ("###Human: <Img>…</Img> Describe this image in detail. ###Assistant:"). A few minutes of training fixes the fluency: quality of data beats quantity.

Trained: one linear layer. Frozen: ViT, Q-Former, Vicuna.

7Video-LLaMA (2023): frames over time, plus sound

Zhang et al., Alibaba DAMO. Extends the BLIP-2 recipe to video and audio with two parallel branches.

Vision branch. Each sampled frame goes through BLIP-2's frozen ViT + Q-Former, giving 32 vectors per frame. A learned frame position embedding is added so the model knows the order of the frames. A Video Q-Former (trained) then mixes information across frames and outputs a fixed set of video tokens, and a linear layer maps them into the LLM.

Audio branch. The sound track is cut into short clips and encoded by the frozen ImageBind audio encoder, whose features already live in a space shared with images and text. An Audio Q-Former (trained) with position embeddings summarises them, and a linear layer maps them into the LLM.

Language. Video tokens, audio tokens and the question are concatenated and the frozen LLaMA/Vicuna answers. Training: video–caption data, then instruction data; the audio branch is trained with image/video–text data, relying on ImageBind's shared space.

Trained: both Q-Formers, position embeddings, linear layers. Frozen: encoders and LLM.

8mPLUG-Owl (2023): train the eyes first, then tune the LLM with LoRA

Ye et al., Alibaba DAMO. Builds on mPLUG (2022), which used cross-modal skip-connections so that the long visual sequence skips most text layers to save compute.

Visual abstractor. Like Flamingo's resampler and BLIP-2's Q-Former: 64 learnable queries cross-attend to the ViT patch features and return 64 visual tokens. Fewer tokens means a cheaper LLM pass.

Stage 1, multimodal pre-training: unlike BLIP-2 and MiniGPT-4, the vision encoder is trained too, together with the abstractor, on image–caption pairs, while LLaMA stays frozen. The argument: a frozen CLIP-style encoder was trained on matching, not on the fine detail that language generation needs.

Stage 2, joint instruction tuning: freeze the vision side and tune the LLM through LoRA adapters (small low-rank weight updates), on a mix of text-only and multimodal instruction data, so it keeps its pure-text skills.

Trained: ViT + abstractor (stage 1), LoRA on LLM (stage 2). Frozen: LLM in stage 1, vision in stage 2.

Linear projection or learned queries?

A linear layer keeps every patch (256 or more tokens), so the LLM sees fine detail but each image costs many tokens of context. Learned queries (Q-Former, resampler, abstractor) squeeze the image into 32–64 tokens: cheaper, and the number does not grow with resolution, but small details can be lost. Later models (LLaVA-1.5, Qwen-VL, InternVL) mostly went back to MLP projectors with more patches.

Prefix tokens or cross-attention?

Frozen, BLIP-2, LLaVA, MiniGPT-4, Video-LLaMA and mPLUG-Owl put visual tokens in the input sequence (a prefix), so the LLM is unchanged. Flamingo adds new layers that cross-attend to the image, so the sequence stays short and many images fit, at the cost of changing the LLM's architecture.

10Python: asking BLIP-2 and LLaVA about a picture

With the Hugging Face transformers library. Each model downloads several gigabytes the first time; a GPU is needed for reasonable speed.

from transformers import Blip2Processor, Blip2ForConditionalGeneration, AutoProcessor, LlavaForConditionalGeneration
from PIL import Image
img = Image.open("cat.jpg")

# BLIP-2: frozen ViT + Q-Former (32 queries) + frozen OPT-2.7B
proc = Blip2Processor.from_pretrained("Salesforce/blip2-opt-2.7b")
model = Blip2ForConditionalGeneration.from_pretrained("Salesforce/blip2-opt-2.7b")
x = proc(images=img, text="Question: what is the cat doing? Answer:", return_tensors="pt")
print(proc.decode(model.generate(**x, max_new_tokens=20)[0], skip_special_tokens=True))

# LLaVA-1.5: CLIP ViT-L/14 + 2-layer MLP projector + Vicuna-7B
proc = AutoProcessor.from_pretrained("llava-hf/llava-1.5-7b-hf")
model = LlavaForConditionalGeneration.from_pretrained("llava-hf/llava-1.5-7b-hf")
prompt = "USER: <image>\nDescribe this picture in one sentence. ASSISTANT:"
x = proc(images=img, text=prompt, return_tensors="pt")
print(proc.decode(model.generate(**x, max_new_tokens=40)[0], skip_special_tokens=True))
