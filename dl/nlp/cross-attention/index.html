Cross-attention: one sequence reads another

In cross-attention the questions and the answers come from different places. The queries come from the sequence being produced (a translation, an image being drawn); the keys and values come from the input it should consult (the source sentence, the text prompt). It is the bridge between an encoder and a decoder.

What is cross-attention, in plain words?

The problem

When a model writes a French translation, generates speech from text, or paints an image from a prompt, it is producing one sequence while consulting another. Self-attention only lets a sequence look at itself. We need a way for each piece of the output being written to ask the input a question, "which part of the source should I use right now?", and get back the relevant information.

The idea

Cross-attention is attention between two different sequences. The queries come from the one being produced (a translation, a transcript, an image); the keys and values come from the input it should consult. It is how an decoder reads an encoder, and how a text prompt steers an image model.

How it works

  1. Encode the input once into vectors (keys and values).
  2. At each output position, form a query from the output so far.
  3. Attend over the input: score, softmax, weighted average.
  4. Combine the result with the rest of the decoder layer.

An everyday picture

An interpreter with the speech transcript in front of them: for each word they say, their eyes jump to the part of the transcript that matters, which is not always the next word in order.

Good at
  • Inputs and outputs can differ in length and kind (audio to text, text to image)
  • Input keys and values are computed once and reused
  • Learns alignments without labels
Watch out for
  • Needs a separate encoder
  • Decoder-only models do not use it
  • Weights over a long input can be diffuse

1Self-attention versus cross-attention

Self-attention: one sequence \(X\) provides queries, keys and values, so every token looks at the others in the same sequence.

Cross-attention: two sequences. The decoder states \(Y\) provide the queries; the encoder outputs \(X\) provide the keys and values:

$$Q=YW_Q,\qquad K=XW_K,\qquad V=XW_V$$

The weight matrix has one row per output position and one column per input position, so the two sequences can have different lengths (8 English words, 11 French words). In the original transformer every decoder layer has a self-attention block, then a cross-attention block, then an MLP.

Cross-attention weights

Rows: French word being produced (query). Columns: English words (keys and values). Each row sums to 100%.

The model (about 1,500 numbers): each English word gets an embedding plus a learned position vector, \(x_j=E[w_j]+p_j\). Keys and values are \(k_j=W_Kx_j\), \(v_j=W_Vx_j\). Output position \(t\) has a learned query \(q_t\). Then \(a_t=\operatorname{softmax}(q_t^\top k_j/\sqrt{16})\), \(c_t=\sum_j a_{tj}v_j\), and a linear layer plus softmax picks the French word. Trained with cross-entropy and Adam, gradients written out by hand.

What to look for. At first every row is flat (about 14% everywhere). Within about a hundred steps the anti-diagonal swaps appear (rouge looks at "red" one place to the left), and the article rows split their weight between the article and the noun: to write la it needs "the" and the gender of "car". Nobody labelled any of these links.

Simplification: real decoders also run self-attention over the French words written so far; here the queries depend only on position, which is enough because every sentence has the same shape.

3Text guiding an image: cross-attention maps

In text-to-image diffusion models (Stable Diffusion and its relatives) the image patches are the queries and the prompt's words are the keys and values. Each patch asks "which words describe me?". Plotting one word's column of the attention matrix over the image shows where that word acts.

A 6 × 6 grid of patches. Each patch is described by colour and shape features; prompt words have matching key vectors. Weights are hand-set to show the mechanism, not learned.

Edit the prompt (words it knows: red, blue, green, circle, square, triangle). Click a word to see its map.

Patches that match nothing put their weight on filler words like "a" and "to". Real models do the same with the start token, which soaks up attention that has nowhere better to go. Editing these maps (strengthening one word's column) is how prompt-editing methods change one object without redrawing the scene.

4The maths and the shapes

$$\operatorname{CrossAttn}(Y,X)=\operatorname{softmax}\!\Big(\frac{(YW_Q)(XW_K)^\top}{\sqrt{d_k}}\Big)\,XW_V$$
  • \(Y\): \(m\times d\) (decoder side, \(m\) positions); \(X\): \(n\times d\) (encoder side).
  • Weights: \(m\times n\). Output: \(m\times d_v\), one vector per decoder position.
  • No causal mask: the whole input is known, so every query may look at every key.
  • \(K\) and \(V\) depend only on the input, so during generation they are computed once and reused for every new output token.

Default: Whisper-sized audio input (1,500 encoder frames for 30 s) and a 30-token transcript. Cost of one layer's scores grows with \(m\times n\), not \(n^2\).

Algorithm: cross-attention in an encoder–decoder
  1. input source tokens \(x_1..x_m\), target tokens so far \(y_1..y_n\)
  2. \(E\leftarrow\operatorname{Encoder}(x)\) m × d, computed once
  3. \(D\leftarrow\) masked self-attention over \(y\) the decoder reads its own past
  4. \(Q\leftarrow DW_Q\) questions come from the target
  5. \(K\leftarrow EW_K\); \(V\leftarrow EW_V\) answers come from the source
  6. \(A\leftarrow\operatorname{softmax}(QK^\top/\sqrt d)\) n × m: target word × source word
  7. \(D\leftarrow D+AV\) residual: add what was found
  8. return \(D\) to the MLP and the next decoder layer
Going deeper: shapes, and why the source is encoded only once

The only difference from self-attention is where \(Q\) and \(K,V\) come from, and so the attention matrix is \(n\times m\) instead of \(n\times n\): one row per target position, one column per source position. No causal mask is needed here, because the whole source is known before decoding starts. Row \(i\) is an alignment: it shows which source words were consulted while writing target word \(i\).

When generating word by word, \(K=EW_K\) and \(V=EW_V\) do not change from step to step, so a real implementation computes them once and reuses them, and each new step only costs one query row. In text-to-image diffusion models, the image patches are the queries and the prompt's token embeddings are the keys and values, which is why attention maps for a word like "dog" light up the region where the dog is painted.

Decoder-only models such as GPT have no cross-attention: the prompt and the answer sit in one sequence and causal self-attention does both jobs.

6The same thing in Python

import torch, torch.nn as nn

enc = torch.randn(1, 8, 64)    # 8 source tokens (keys / values)
dec = torch.randn(1, 11, 64)   # 11 target tokens (queries)
xattn = nn.MultiheadAttention(embed_dim=64, num_heads=4, batch_first=True)
out, w = xattn(query=dec, key=enc, value=enc)
print(out.shape, w.shape)   # (1, 11, 64)  (1, 11, 8): one row per target token

# a full encoder-decoder layer stack: self-attn, cross-attn, MLP in each decoder layer
model = nn.Transformer(d_model=64, nhead=4, batch_first=True)
