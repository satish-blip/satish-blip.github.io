CLIP: one space for pictures and words

VisualBERT and ViLBERT fuse an image and a caption inside one network to answer questions about them. CLIP (Radford et al., OpenAI, 2021) does something simpler and, it turned out, far more widely useful: it trains an image encoder and a text encoder separately, so that a picture and a sentence describing it land on the same point of a shared space. On this page you train a small CLIP yourself, then use it to classify images it was never trained to classify.

What is CLIP, in plain words?

The problem

An image classifier trained on ImageNet knows exactly 1,000 labels. To teach it "golden retriever puppy on a beach", someone must collect and label thousands of new photos. Meanwhile the web holds hundreds of millions of images that already come with free, rich descriptions: their captions and alt-text. They are too noisy and varied to use as class labels. Can we learn from them anyway, and end up with a model that understands any description we write, not just a fixed list?

The idea

CLIP (Contrastive Language–Image Pre-training) has two encoders: one turns an image into a vector, the other turns a piece of text into a vector of the same size. Training uses a contrastive loss on a batch of image–caption pairs: make each image's vector most similar to its own caption's vector and less similar to every other caption in the batch, and the same the other way round. The result is a multimodal embedding space where meaning, not modality, decides where things land.

How it works

  1. Encode a batch of B images and their B captions into unit vectors.
  2. Compute all \(B\times B\) cosine similarities.
  3. Cross-entropy pushes the diagonal (true pairs) up and everything else down.
  4. Afterwards, classify or search by comparing an image vector with text vectors you write, with no further training (zero-shot).

An everyday picture

A party game with a pile of photos and a pile of captions, all shuffled. Your job is to deal them out in matching pairs. You get good at it by learning what words go with what looks, and once you are good, you can match a photo to a caption you have never seen before.

Good at
  • Learns from free, noisy web captions: no labels to annotate
  • Zero-shot classification with any class names
  • Fast search: embed a million images once, query with text
Watch out for
  • Weak at counting, spatial relations ("left of") and fine details
  • Inherits the biases of web data
  • Needs very large batches and datasets to work well

1Two encoders, one space

An image \(x\) goes through an image encoder \(f\) (a ResNet or a ViT); a caption \(y\) goes through a text encoder \(g\) (a transformer). Each output is multiplied by a projection matrix to a common width \(d\) and scaled to length 1:

$$u=\frac{W_If(x)}{\lVert W_If(x)\rVert},\qquad t=\frac{W_Tg(y)}{\lVert W_Tg(y)\rVert}$$

Because both have length 1, their dot product is the cosine similarity \(u^\top t=\cos\theta\in[-1,1]\): 1 when they point the same way, 0 when unrelated.

Unlike VisualBERT and ViLBERT, the two encoders never look at each other. That makes CLIP a bi-encoder, like the dense retrievers on the RAG page: every image can be encoded once and stored, and any text query is compared with all of them by a single matrix product.

The shared space of the tiny CLIP trained on this page, flattened to 2-D. Contrastive loss on the training batch (purple) and the best possible value 0. With random weights the loss is about \(\ln 12\approx2.5\): picking the right caption out of 12 by chance.

Similarity matrix for one batch

Rows: the batch's images. Columns: their captions, in the same order. Cell = cosine similarity. Training wants a bright diagonal and dark everywhere else.

The model (about 1,900 numbers): the image encoder looks at which of the 100 pixels are not background (the shape) and at their average colour, a stand-in for the edge and colour detectors in the first layers of a real vision network, and maps those 103 numbers linearly to 16; the text encoder averages a 16-number vector per word (a bag of words). Both are normalised to length 1, and the loss uses temperature \(\tau=0.1\). Real CLIP uses a 300-million-parameter ViT and a 12-layer transformer, but the training signal is exactly this one.

3The loss, step by step

Take a batch of \(B\) pairs \((x_i,y_i)\). Encode them to unit vectors \(u_i\) and \(t_i\), and form the \(B\times B\) matrix of scaled similarities

$$S_{ij}=\frac{u_i^\top t_j}{\tau}.$$

Image to text. Treat row \(i\) as the scores of a \(B\)-way classifier whose right answer is caption \(i\). The usual softmax cross-entropy is

$$\mathcal L_{I\to T}=-\frac1B\sum_{i=1}^B\log\frac{e^{S_{ii}}}{\sum_{j=1}^Be^{S_{ij}}}$$

Text to image. The same for columns: caption \(j\) must pick out image \(j\) among the \(B\) images, \(\mathcal L_{T\to I}=-\frac1B\sum_j\log\frac{e^{S_{jj}}}{\sum_ie^{S_{ij}}}\).

Total. \(\mathcal L=\tfrac12(\mathcal L_{I\to T}+\mathcal L_{T\to I})\). The gradient of each cross-entropy with respect to a score is "softmax probability minus 1 if correct": the true pair is pulled together with force \(1-p_{ii}\), and each wrong pair is pushed apart with force \(p_{ij}\), so the most confusing negatives get pushed hardest.

Algorithm: CLIP training step
  1. input a batch of \(B\) (image, caption) pairs, encoders \(f,g\), projections \(W_I,W_T\), temperature \(\tau\)
  2. \(U\leftarrow\operatorname{normalise}(f(\text{images})W_I)\) B × d, one row per image
  3. \(T\leftarrow\operatorname{normalise}(g(\text{captions})W_T)\) B × d, one row per caption
  4. \(S\leftarrow UT^\top/\tau\) B × B, true pairs on the diagonal
  5. \(\mathcal L_{I\to T}\leftarrow\operatorname{CE}(\text{rows of }S,\;\text{labels }1..B)\) each image finds its caption
  6. \(\mathcal L_{T\to I}\leftarrow\operatorname{CE}(\text{columns of }S,\;\text{labels }1..B)\) each caption finds its image
  7. \(\mathcal L\leftarrow\tfrac12(\mathcal L_{I\to T}+\mathcal L_{T\to I})\); update \(f,g,W_I,W_T,\tau\)
Going deeper: temperature, batch size, and what the loss estimates

Temperature. Cosines live in \([-1,1]\), so without scaling the softmax over a batch would be almost flat. Dividing by \(\tau\) (CLIP learns \(\log(1/\tau)\), starting at \(\tau=0.07\) and capping \(1/\tau\) at 100) sharpens it. Too large a \(\tau\) and the loss barely separates pairs; too small and training becomes unstable, with gradients only from the single hardest negative.

Batch size. Each row is a \(B\)-way classification, so the batch is the set of negatives. More negatives make the task harder and the embedding sharper; CLIP used \(B=32{,}768\), spread across hundreds of GPUs. SigLIP (2023) replaces the softmax with an independent sigmoid "match or not" for every cell of \(S\), which removes the need to normalise across the whole batch and works well with smaller batches.

What it estimates. This loss is the InfoNCE objective. Its minimum value bounds the mutual information between images and captions: \(I(X;Y)\ge\log B-\mathcal L_{I\to T}\). Minimising it therefore makes the embeddings keep as much information as possible about which caption goes with which image, which is exactly what a good shared space needs. The same loss trains dense retrievers (DPR), SimCLR (with two views of one image instead of image and text), and sentence embedders.

4Zero-shot classification

To classify with CLIP you don't train a classifier. You write the class names into a sentence ("a photo of a {class}"), encode every sentence once, and pick the one whose vector is closest to the image's. Here the classes are the 12 colour–shape pairs, including the two the model never saw.

Algorithm: zero-shot classification with CLIP
  1. input an image \(x\), class names \(c_1..c_K\), a template such as "a photo of a {}"
  2. for each class \(k\): \(t_k\leftarrow\operatorname{normalise}(g(\text{template}(c_k))W_T)\) once, then reuse
  3. \(u\leftarrow\operatorname{normalise}(f(x)W_I)\)
  4. for each class \(k\): \(s_k\leftarrow u^\top t_k/\tau\)
  5. \(p\leftarrow\operatorname{softmax}(s)\) probabilities over the K classes
  6. return \(\arg\max_kp_k\) no training on these classes
Going deeper: why it generalises to unseen combinations, and prompt engineering

"Yellow" and "triangle" each appeared many times in training, just never together. Because the text encoder builds a caption's vector from its words, and the image encoder sees shape and colour as separate features, the model learns a direction for "yellow" and a direction for "triangle" separately, and adds them. A yellow triangle then lands near "a yellow triangle" even though that pair was never in a batch. Real CLIP relies on the same compositionality at a far larger scale, which is why it can recognise "a corgi wearing sunglasses".

Prompts matter. A bare class name ("crane") is ambiguous; "a photo of a crane, a type of bird" is not. The CLIP paper gained several points of ImageNet accuracy by using the template "a photo of a {}." and more by averaging the text vectors of 80 templates per class (prompt ensembling). The classifier is literally a matrix whose rows are text embeddings, so changing the prompts is changing the classifier's weights without any training.

5Search by text

The same trick in reverse: embed a gallery of images once, then rank them by similarity to any query. Type a query using the words the toy model knows: red, green, blue, yellow, circle, square, triangle, small, big.

6The real CLIP, and where it is used

  • Data: 400 million (image, text) pairs collected from the web (the WIT dataset).
  • Encoders: image side a ResNet-50 up to a ViT-L/14; text side a 12-layer, 512-wide transformer reading up to 76 tokens; the [EOS] token's output is the text vector.
  • Training: batch 32,768, 32 epochs. The largest ViT model took 12 days on 256 GPUs.
  • Result: zero-shot ImageNet accuracy of 76.2%, matching a ResNet-50 trained on the 1.28 million labelled ImageNet images, without using any of them; and much more robust when the images change style (sketches, renditions).

Limits. It struggles with counting ("three apples"), spatial relations, reading small text, and fine-grained classes, and it can be fooled by a written label stuck on an object (a "typographic attack": an apple with a paper saying "iPod").

Where CLIP is usedWhich part
Stable Diffusion and other image generatorsthe text encoder turns the prompt into the vectors that cross-attention reads
LLaVA and many vision–language assistantsthe ViT image encoder supplies the visual tokens
Image search and photo appsboth encoders, as a bi-encoder index
Data filtering (LAION)keep only image–caption pairs whose CLIP similarity is high
Open re-implementations: OpenCLIP, SigLIPthe same recipe on open data, or with a sigmoid loss

Fusion models (VisualBERT, ViLBERT) are better at reasoning about one image and one question; CLIP is better at matching and searching at scale. Modern assistants combine them: a CLIP-style image encoder feeding a language model.

7The same thing in Python

import torch, torch.nn.functional as F
# the loss, given image features I_f (B x di) and text features T_f (B x dt)
def clip_loss(I_f, T_f, W_i, W_t, log_scale):
    U = F.normalize(I_f @ W_i, dim=-1)            # B x d
    T = F.normalize(T_f @ W_t, dim=-1)            # B x d
    S = log_scale.exp() * U @ T.t()                   # B x B, scale = 1 / tau
    labels = torch.arange(S.shape[0])
    return (F.cross_entropy(S, labels) + F.cross_entropy(S.t(), labels)) / 2
