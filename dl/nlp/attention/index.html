Attention: look back at what matters

A recurrent network has to squeeze everything it has read into one hidden vector. Attention removes that squeeze: at every step the model keeps all the earlier vectors and, for the job at hand, takes a weighted average of them, with the weights computed on the fly from how well each one matches what it is looking for.

What is attention, in plain words?

The problem

An encoder–decoder translator squeezes the whole source sentence into one fixed vector, then writes the translation from that vector alone. For a five-word sentence that works; for a fifty-word one, the vector is a bottleneck and early words get forgotten. A human translator does something smarter: while writing each word, they glance back at the part of the source that matters right now. We want a network that can do that glance, and learn where to look.

The idea

Attention lets a model look back at all the vectors it has, instead of a single summary, and take a weighted average of them. The weights come from comparing a query (what I am looking for) with each key (what each item offers), then passing the scores through a softmax so they are positive and add up to 1.

How it works

  1. Score each key against the query (for example a dot product).
  2. Divide by \(\sqrt d\) (scaled dot product) and apply softmax to get weights.
  3. Output the weighted average of the values.
  4. Everything is differentiable, so the model learns what to look for.

An everyday picture

Searching a library: your question is the query, the catalogue cards are the keys, the books are the values. Instead of picking one book, you take a blend, mostly from the best matches.

Good at
  • Removes the one-vector bottleneck
  • Direct path between any two positions
  • Weights are visible and often interpretable
Watch out for
  • Cost grows with (queries × keys)
  • Weights are not a full explanation of the model
  • Needs position information added separately

1The bottleneck: one vector cannot hold a whole sentence

In a 2014 sequence-to-sequence translator, the encoder RNN reads the sentence and hands the decoder only its final hidden state. Long sentences were translated badly, because one fixed-size vector has to carry every word.

This experiment measures that squeeze. Store \(N\) random "facts" (a key vector and a value vector, 16 numbers each), then try to read back fact 1 using a noisy copy of its key.

  • One summary vector (the bottleneck): keep only the average of the values. Whatever you ask, you get the same blend back.
  • Attention: keep all \(N\) values; score each key against the query, turn the scores into weights with softmax, return the weighted average.

3Alignment: what a translator looks at

Illustrative weights in the style of the first attention paper (Bahdanau, Cho and Bengio, 2015, Figure 3). Rows: the French word being written. Columns: the English words it attends to. Click a row.

Each time the decoder writes a word, it attends over every encoder state. Plotting the weights gives an alignment: mostly a diagonal, because English and French mostly share word order, with a reversed block where they do not ("European Economic Area" becomes "zone économique européenne").

Nobody told the model which words correspond. The alignment is a side effect of minimising translation loss: attending to the right word is simply the cheapest way to predict the next one.

4Queries, keys and values, step by step

The general recipe works on whole matrices at once: 3 queries attend over 4 stored items. Keys and queries have \(d_k=3\) numbers, values have \(d_v=2\). Press "New numbers" and follow one row through.

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\Big(\frac{QK^\top}{\sqrt{d_k}}\Big)V$$
Click a row of the weight matrix to follow that query.

\(Q\) (3 × 3)

\(K\) (4 × 3)

\(V\) (4 × 2)

Scores \(S=QK^\top/\sqrt{3}\) (3 × 4)

Weights \(A=\operatorname{softmax}(S)\) by row

Output \(O=AV\) (3 × 2)

Every row of \(A\) sums to 1, so each output row is a convex combination of the value rows: attention can only mix what is stored, never invent new values. Costs: \(n_q\times n_k\) scores, which becomes \(n^2\) when a sequence attends to itself (see self-attention).
Algorithm: scaled dot-product attention
  1. input queries \(Q\) (\(n\times d\)), keys \(K\) (\(m\times d\)), values \(V\) (\(m\times d_v\))
  2. for each query \(q_i\) do
  3. for each key \(k_j\) do \(s_{ij}\leftarrow q_i^\top k_j/\sqrt d\) how well does item j match?
  4. \(a_{ij}\leftarrow e^{s_{ij}}/\sum_{j'}e^{s_{ij'}}\) softmax: positive, sums to 1
  5. \(o_i\leftarrow\sum_ja_{ij}v_j\) weighted average of the values
  6. return \(O\) all at once: softmax(QKᵀ/√d)V
Going deeper: attention as a soft dictionary lookup

A Python dictionary does a hard lookup: compare the query with every key, return the value of the one exact match. Attention makes every step smooth. The comparison is a dot product (large when the vectors point the same way), the "pick one" becomes a softmax (mostly the best match, a little of the others), and the result is a blend of values. Because every step is differentiable, backprop can teach the network what to ask for (\(W_Q\)), how to advertise each item (\(W_K\)) and what to hand over (\(W_V\)).

Why \(\sqrt d\)? If the entries of \(q\) and \(k\) are independent with mean 0 and variance 1, then \(q^\top k\) is a sum of \(d\) such products and has variance \(d\). For \(d=64\) the scores have spread 8, the softmax becomes almost one-hot, and its gradients almost vanish. Dividing by \(\sqrt d\) brings the variance back to 1, whatever the dimension.

6The same thing in Python

import torch, torch.nn.functional as F

Q = torch.randn(3, 3); K = torch.randn(4, 3); V = torch.randn(4, 2)
A = torch.softmax(Q @ K.T / K.shape[-1] ** 0.5, dim=-1)   # 3 x 4, rows sum to 1
O = A @ V                                                    # 3 x 2

# the fused, memory-efficient version used inside transformers
O2 = F.scaled_dot_product_attention(Q[None], K[None], V[None])[0]
assert torch.allclose(O, O2, atol=1e-6)
