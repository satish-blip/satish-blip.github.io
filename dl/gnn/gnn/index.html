Graph neural networks: learning from connections

Images are grids and sentences are sequences, but much of the world's data is a network: people and friendships, accounts and payments, atoms and bonds, users and the items they buy. A graph neural network learns from both what each node is and whom it is connected to. This page builds the idea from one sentence, "a node's new representation is a summary of its neighbours", and trains a network live on a famous real graph.

What is a graph neural network, in plain words?

The problem

A table treats every row as independent, but a fraudulent account is suspicious partly because of whom it pays, and a molecule's behaviour depends on how its atoms are bonded. Graphs also have no fixed size and no natural order of nodes, so a CNN or an MLP cannot be applied directly.

The idea

Give every node a vector. In each layer, every node collects messages from its neighbours, combines them with its own vector, and passes the result through a small neural network. After \(k\) layers a node's vector summarises its \(k\)-hop neighbourhood. The same weights are used at every node, so the model works on graphs of any size and shape.

How it works

  1. Write the graph as an adjacency matrix \(A\) plus a feature vector per node.
  2. Each layer: aggregate neighbour vectors (sum, mean or attention-weighted), transform with shared weights, apply a non-linearity.
  3. GCN uses fixed degree-based weights; GAT learns how much to listen to each neighbour.
  4. Read out node vectors (node tasks), pairs (link prediction) or a pooled summary (graph-level tasks).

An everyday picture

Guessing someone's political views from their friends. You know little about a person, but you know their friends, and their friends' friends. Asking around once (one layer) tells you about the immediate circle; asking your friends to ask theirs (two layers) widens it. Ask too many rounds and everyone sounds like the average of the whole town: that is over-smoothing.

Good at
  • Data where relationships carry signal: fraud rings, molecules, citations
  • Learning from very few labels, because labels spread along edges
  • Graphs of any size, with no fixed node order
Watch out for
  • Over-smoothing: deep GNNs make all nodes look alike
  • Assumes neighbours are informative (homophily); not always true
  • Huge graphs need neighbour sampling or mini-batching tricks

1A graph, and the matrix behind it

Zachary's karate club (1977): 34 members, 78 friendships. The club later split in two; colour shows which side each member joined. Click a member to highlight their row of \(A\).

A graph \(G=(V,E)\) is a set of \(n\) nodes and a set of edges between them. The karate club is a classic: a sociologist recorded who socialised with whom outside the club; after a dispute between the instructor (node 1) and the president (node 34) the club split, and the question ever since has been whether the network alone predicts who went where.

To compute with a graph we write it as matrices:

  • The adjacency matrix \(A\in\{0,1\}^{n\times n}\), with \(A_{ij}=1\) if \(i\) and \(j\) are connected. For an undirected graph it is symmetric. The right panel draws it: each row is one member.
  • The degree matrix \(D=\operatorname{diag}(d_1,\dots,d_n)\), with \(d_i=\sum_j A_{ij}\), the number of friends.
  • A feature matrix \(X\in\mathbb R^{n\times f}\), one row of features per node. The karate club has none, so we use the identity: each node is just "itself".
  • The graph Laplacian \(L=D-A\). For any signal \(x\) on the nodes, \(x^\top Lx=\sum_{(i,j)\in E}(x_i-x_j)^2\): it measures how much \(x\) changes across edges, the graph's notion of roughness.

One property matters above all: relabelling the nodes permutes the rows and columns of \(A\) and the rows of \(X\), but it is the same graph. Any model on graphs must give the same answer however the nodes are numbered. That rules out simply flattening \(A\) into an MLP, and it is exactly what message passing guarantees.

Three kinds of task: predict something about each node (which side did each member join?), about a pair (will these two become friends? link prediction), or about the whole graph (is this molecule toxic?).

2Message passing and the receptive field

Click a member. After \(k\) layers its vector depends on every node within \(k\) hops (shaded). Arrows: the messages it receives in the last layer.

Almost every GNN is an instance of one template, the message-passing neural network (Gilmer et al., 2017). Each node \(v\) holds a vector \(h_v^{(\ell)}\); layer \(\ell+1\) computes

$$h_v^{(\ell+1)}=\phi\Big(h_v^{(\ell)},\ \bigoplus_{u\in\mathcal N(v)}\psi\big(h_v^{(\ell)},h_u^{(\ell)},e_{uv}\big)\Big),$$

where \(\psi\) makes a message from a neighbour \(u\) (and the edge's features \(e_{uv}\), if any), \(\bigoplus\) aggregates the messages, and \(\phi\) updates the node. The aggregator must not care about the order of the neighbours, so it is a sum, a mean, a max, or an attention-weighted sum. Because \(\psi\) and \(\phi\) are shared by all nodes, the layer is permutation-equivariant and works on any graph.

Move the slider. With \(k=1\) the member sees only its friends; with \(k=2\), friends of friends. In this small club almost everyone is within 3 hops of everyone else, which is why GNNs are usually only 2 to 4 layers deep: a node's receptive field grows exponentially with depth.

Algorithm: one message-passing layer
  1. input graph \(G\), node vectors \(h_v\), shared networks \(\psi,\phi\)
  2. for each node \(v\) all nodes in parallel
  3. for each neighbour \(u\in\mathcal N(v)\): \(m_{u\to v}\leftarrow\psi(h_v,h_u,e_{uv})\)
  4. \(m_v\leftarrow\bigoplus_{u}m_{u\to v}\) sum, mean, max or attention
  5. \(h_v'\leftarrow\phi(h_v,m_v)\)
  6. return all \(h_v'\) stack L layers to see L hops

3A graph convolutional network, trained live from two labels

Only the starred members are labelled. Left: the graph coloured by the model's prediction (ring = the side they really joined). Right: each member's 2-number output.

Model

The graph convolutional network (Kipf and Welling, 2017) is message passing with the simplest sensible choices: the message is the neighbour's vector, the aggregate is a weighted average that includes the node itself, and the update is a linear layer plus a non-linearity. In matrix form one layer is

$$H^{(\ell+1)}=\sigma\big(\hat A\,H^{(\ell)}\,W^{(\ell)}\big),\qquad \hat A=\tilde D^{-1/2}(A+I)\,\tilde D^{-1/2}.$$

Read it right to left. \(H W\) transforms every node's vector with the same weights. Multiplying by \(\hat A\) replaces each row by a weighted sum of its own row and its neighbours' rows. Adding \(I\) gives every node a self-loop, so it keeps its own information, and the symmetric normalisation, weight \(1/\sqrt{\tilde d_i\tilde d_j}\) on edge \((i,j)\), stops high-degree nodes from blowing up the scale.

Our model: \(Z=\hat A\,\tanh(\hat A X W^{(1)})\,W^{(2)}\) with \(X=I\), 16 hidden units and 2 outputs, trained with cross-entropy on the starred members only. This is semi-supervised learning: the loss sees 2 labels, but the edges carry their influence to everyone. Press Train: the two factions pull apart and almost every member is classified correctly. Switch to the MLP, which sees the same features but no edges. It fits the two labelled members perfectly and knows nothing about anyone else.

Going deeper: why "convolution"? The spectral view

On a grid, a convolution is a multiplication in the Fourier basis. On a graph, the eigenvectors of the Laplacian \(L=U\Lambda U^\top\) play the role of Fourier modes (small eigenvalue = smooth across edges), and a spectral graph convolution is \(g_\theta\star x=U\,g_\theta(\Lambda)\,U^\top x\). That needs an eigendecomposition and is not localised. ChebNet (2016) approximates \(g_\theta\) by a polynomial of degree \(K\) in \(L\), which only mixes \(K\)-hop neighbours. Kipf and Welling took \(K=1\), tied the two coefficients and renormalised, which leaves exactly \(\hat A\). A GCN layer is a first-order low-pass filter on the graph: it smooths features along edges.

4Over-smoothing: when depth hurts

Random 2-number features for each member, propagated \(K\) times with \(\hat A\) and rescaled. Colour = side they joined.

Why not stack 50 GCN layers, like a 50-layer CNN? Ignore the weights and non-linearities for a moment and just apply \(\hat A\) again and again. Each application averages neighbours, so features become smoother. A little smoothing helps: after 2 or 3 steps, members of the same faction (which are densely connected) have moved together, and the factions separate even from random features. That is why an untrained GCN already clusters the karate club.

Keep going and every node converges to the same direction. \(\hat A\) has largest eigenvalue 1, with eigenvector proportional to \(\tilde D^{1/2}\mathbf 1\); all other eigenvalues have magnitude below 1 and die away, so

$$\hat A^{K}X\ \xrightarrow{K\to\infty}\ \tilde D^{1/2}\mathbf 1\,c^\top\quad\text{(each node's features depend only on its degree).}$$

This is over-smoothing: depth erases exactly the differences we wanted to learn. The ratio in the stats (spread between factions relative to spread within them) peaks at small \(K\) and then falls. Remedies include residual connections and jumping-knowledge (combine all layers' outputs), normalisation layers such as PairNorm, and, most commonly, simply keeping GNNs shallow and wide.

5Graph attention: learn whom to listen to

Click a member. Edge thickness and the bars show the weight it gives each neighbour: fixed GCN weights (grey) versus attention computed from the features of a trained GCN (violet).

A GCN listens to each neighbour with a weight fixed by the degrees, \(1/\sqrt{\tilde d_i\tilde d_j}\). But not all friends are equally informative: a member with one friend in each faction should listen to the one more like itself. A graph attention network (Veličković et al., 2018) learns the weights from the node vectors, exactly as attention does for words, except that each node attends only to its neighbours:

$$\begin{aligned}e_{ij}&=\operatorname{LeakyReLU}\big(a^\top[\,Wh_i\,\|\,Wh_j\,]\big),\\ \alpha_{ij}&=\frac{\exp(e_{ij})}{\sum_{k\in\mathcal N(i)\cup\{i\}}\exp(e_{ik})},\\ h_i'&=\sigma\Big(\sum_{j}\alpha_{ij}Wh_j\Big).\end{aligned}$$

Several heads run in parallel and are concatenated, as in a transformer. The lab scores neighbours by the similarity of their features in a GCN trained as in section 3, \(e_{ij}=\beta\cos(h_i,h_j)\), a common dot-product variant (GATv2 and graph transformers use similar forms); β plays the role of the learned scale. Pick a member on the boundary between the factions and raise the sharpness: attention concentrates on the neighbours from its own side, while the GCN weights stay put.

Algorithm: one graph attention layer (one head)
  1. input node vectors \(h\), weights \(W\), attention vector \(a\)
  2. for each node \(i\)
  3. for each \(j\in\mathcal N(i)\cup\{i\}\): \(e_{ij}\leftarrow\operatorname{LeakyReLU}(a^\top[Wh_i\|Wh_j])\)
  4. \(\alpha_{i\cdot}\leftarrow\operatorname{softmax}_j(e_{ij})\) over the neighbourhood only
  5. \(h_i'\leftarrow\sigma\big(\sum_j\alpha_{ij}Wh_j\big)\)
  6. return \(h'\) K heads: concatenate or average

Graph-level tasks pool node vectors into one, for example \(h_G=\sum_v h_v^{(L)}\), then apply an MLP. Sum is the most expressive simple readout: Xu et al. (2019) showed that a GNN with sum aggregation (GIN) is as powerful as the Weisfeiler–Lehman graph isomorphism test, while mean and max cannot tell some different neighbourhoods apart.

Big graphs do not fit in memory. GraphSAGE samples a fixed number of neighbours per node per layer, which turns training into ordinary mini-batches; Cluster-GCN trains on dense subgraphs. Watch for heterophily: when connected nodes tend to differ (fraudsters pay honest people), plain averaging hurts, and models that keep the node's own vector separate from the neighbours' do better.

7The same thing in Python

import torch, torch.nn.functional as F
from torch_geometric.datasets import KarateClub, Planetoid
from torch_geometric.nn import GCNConv, GATConv

data = Planetoid(root="data", name="Cora")[0]          # 2,708 papers, 5,429 citations, 7 topics

class GCN(torch.nn.Module):
    def __init__(self, d_in, d_hid, n_cls):
        super().__init__(); self.c1 = GCNConv(d_in, d_hid); self.c2 = GCNConv(d_hid, n_cls)
    def forward(self, x, edge_index):
        x = F.dropout(F.relu(self.c1(x, edge_index)), p=0.5, training=self.training)
        return self.c2(x, edge_index)

model = GCN(data.num_features, 16, 7)
opt = torch.optim.Adam(model.parameters(), lr=0.01, weight_decay=5e-4)
for epoch in range(200):
    model.train(); opt.zero_grad()
    out = model(data.x, data.edge_index)
    F.cross_entropy(out[data.train_mask], data.y[data.train_mask]).backward(); opt.step()
model.eval(); pred = model(data.x, data.edge_index).argmax(1)
print("test accuracy", (pred[data.test_mask] == data.y[data.test_mask]).float().mean().item())   # about 0.81

# graph attention: 8 heads of 8 units, concatenated
gat1 = GATConv(data.num_features, 8, heads=8, dropout=0.6)
