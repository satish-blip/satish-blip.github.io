Residual connections: x + F(x)

Stacking more layers should never hurt: the extra layers could just learn to copy their input. Yet before 2015, deep plain networks trained worse than shallow ones. A residual connection adds the input back to the output of each block, so copying becomes the default and gradients get a highway straight to the early layers.

What is a residual connection, in plain words?

The problem

Depth should only help: a 56-layer network can copy a 20-layer one and set its extra 36 layers to "do nothing". Yet in 2015 the deeper network trained to a worse training error. The extra layers could not even learn to do nothing, because "do nothing" means learning an exact identity map through weights and non-linearities, and the gradient reaching the early layers had faded away. The fix is almost embarrassingly simple: give every block a free copy of its input.

The idea

In a plain deep network each layer must rebuild the whole signal from scratch. A residual connection (or skip connection) adds the block’s input straight to its output: \(x + F(x)\). The block now only has to learn a correction to its input, and doing nothing (the identity) is the easy default.

During training the gradient also gets a direct path back through the "+" to the early layers, so it does not vanish. This is what made 100+ layer ResNets and every transformer trainable.

How it works

  1. Compute the block’s usual output \(F(x)\) (layers and activations).
  2. Add the untouched input: \(y = x + F(x)\).
  3. Stack many such blocks.
  4. On the way back, the gradient flows through both the block and the shortcut.

1The idea

Left: a plain block must learn the whole mapping \(H(x)\). Right: a residual block only learns the change \(F(x)=H(x)-x\); the skip line carries \(x\) through untouched.

$$x_{l+1}=x_l+F(x_l;\,W_l)$$

Easy to do nothing. If the best thing a block can do is pass its input through, a plain block has to learn \(W\approx I\) through a non-linearity, which is hard. A residual block just drives \(F\to0\), which weight decay and small initial weights already push towards. So adding blocks can no longer make the training loss worse.

Gradients get a shortcut. Unrolling from block \(l\) to the last block \(L\):

$$x_L=x_l+\sum_{i=l}^{L-1}F(x_i)\quad\Rightarrow\quad \frac{\partial\mathcal L}{\partial x_l}=\frac{\partial\mathcal L}{\partial x_L}\Big(I+\frac{\partial}{\partial x_l}\sum_{i=l}^{L-1}F(x_i)\Big)$$

The identity term \(I\) means part of the gradient reaches layer \(l\) without being multiplied by any weight matrix or activation slope. In a plain network every path is a product of \(L-l\) Jacobians, which shrinks or explodes exponentially (see vanishing gradients).

He, Zhang, Ren and Sun (2015): on CIFAR-10 a 56-layer plain network had higher training error than a 20-layer one (the degradation problem, not overfitting). With residual connections they trained 110 layers, then 152 on ImageNet, and later 1001.

3Gradient flow at initialisation

plainresidual

Gradient norm \(\lVert\partial\mathcal L/\partial W^{(l)}\rVert\) in every layer of the two networks from section 2, before any training (log scale, averaged over 3 seeds). Uses the depth, width and activation chosen above.

In the plain network the gradient at layer \(l\) is a product of \(L-l\) factors \(W^{(k)\top}\operatorname{diag}\phi'(z^{(k)})\). If those factors are a bit smaller than 1 the product collapses geometrically, and the first layers receive almost nothing.

In the residual network each factor becomes \(I+W^{(k)\top}\operatorname{diag}\phi'(z^{(k)})\). Even if the second part is small, the product stays near \(I\), so the curve stays flat: every layer learns at a similar rate.

Algorithm: forward and backward through residual blocks
  1. input \(x_0\), blocks \(F_1,\dots,F_L\) (each e.g. norm → linear → ReLU → linear)
  2. for \(l=1\) to \(L\) do \(x_l\leftarrow x_{l-1}+F_l(x_{l-1})\) skip: add the input back
  3. \(\mathcal L\leftarrow\) loss on \(x_L\); \(g\leftarrow\partial\mathcal L/\partial x_L\)
  4. for \(l=L\) down to 1 do
  5. backprop \(g\) through \(F_l\) to get its weight gradients and \(g_F=J_{F_l}^\top g\)
  6. \(g\leftarrow g+g_F\) identity path: g passes through untouched
  7. return all weight gradients
Going deeper: a residual network as an ensemble of paths

Expand \(x_L\) for three blocks: \(x_3=x_0+F_1+F_2(x_0+F_1)+F_3(\dots)\). Every block is either used or skipped, so there are \(2^L\) paths from input to output, of every length from 0 to \(L\). Veit, Wilber and Belongie (2016) measured that most of the gradient in a 110-layer ResNet flows through paths only 10 to 34 blocks long, and that deleting a single block at test time barely hurts (unlike a plain network, where it is fatal). Section 5 on this page lets you try that. The effective depth is far smaller than the nominal depth, which is one reason why such networks are easy to train.

In a transformer, the stream \(x_l\) is called the residual stream: every attention and MLP block reads from it and writes an update back into it, and pre-norm (normalise the input of \(F\), never the stream itself) keeps the identity path perfectly clean.

Residuals alone can let activations grow with depth (each block adds variance). That is why real ResNets pair them with normalisation, and why some initialisations (Fixup, "zero-init the last layer of each block") start every \(F\) at zero.

4An ensemble of paths

Three residual blocks unrolled: \(x_3=(1+F_3)(1+F_2)(1+F_1)\,x_0\). Every block can be taken or skipped, so there are \(2^3=8\) paths from input to output.

Expanding the product shows a residual network is a collection of \(2^L\) paths of different lengths. The number of paths that pass through exactly \(k\) blocks is \(\binom{L}{k}\), so most paths have length about \(L/2\), and gradients along the long paths vanish anyway. Veit, Wilber and Belongie (2016) found the gradient in a 110-layer ResNet comes mostly from paths only 10 to 34 blocks long: the network behaves like an ensemble of shallow networks.

5Delete a layer

If a residual network is an ensemble, removing one block should only remove some paths, and the rest should still work. In a plain network every input goes through every layer, so removing one breaks the only path.

6Variants, and where you meet them

Projection shortcut

$$x_{l+1}=W_sx_l+F(x_l)$$

When \(F\) changes the shape (more channels, smaller image), the skip uses a \(1\times1\) convolution or linear map \(W_s\) to match. Used only where needed; elsewhere the skip is the pure identity.

Highway networks

$$x_{l+1}=T\odot F(x_l)+(1-T)\odot x_l$$

Srivastava et al. (2015): a learned gate \(T=\sigma(W_Tx+b)\) decides how much to transform. The same idea as the LSTM cell state (see memory in RNNs), which is why LSTMs fight vanishing gradients too.

DenseNet

$$x_{l+1}=\big[x_0,x_1,\dots,x_l,F(\cdot)\big]$$

Huang et al. (2017) concatenate every earlier output instead of adding. More reuse of features, more memory.

In every transformer

Each transformer layer has two residual sub-blocks: attention, then a feed-forward MLP. The residual stream \(x\) runs straight from the embeddings to the output, and every sub-block reads from it and adds its result back:

$$\begin{aligned}x&\leftarrow x+\operatorname{Attn}(\operatorname{LN}(x))\\x&\leftarrow x+\operatorname{MLP}(\operatorname{LN}(x))\end{aligned}$$

This is pre-LN (GPT-2 onwards): normalise the input to the block, keep the skip path clean. The original 2017 transformer was post-LN, \(x\leftarrow\operatorname{LN}(x+\operatorname{Attn}(x))\), which puts a normalisation on the highway and needs careful learning-rate warm-up. See normalisation and transformers.

7The same thing in Python (PyTorch)

class ResBlock(nn.Module):
    def __init__(self, d):
        super().__init__()
        self.norm = nn.LayerNorm(d)
        self.f = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d))
        nn.init.zeros_(self.f[2].weight)          # start as the identity map
    def forward(self, x):
        return x + self.f(self.norm(x))            # pre-norm residual

model = nn.Sequential(nn.Linear(2, 64), *[ResBlock(64) for _ in range(50)], nn.Linear(64, 1))
# torchvision.models.resnet50() uses the same pattern with convolutions + BatchNorm
