Model compression: same skill, fewer bits

A trained network is a large pile of numbers, usually stored with far more precision and far more redundancy than it needs. Compression removes the excess so a model fits on a phone, answers faster and costs less to run, while keeping almost all of its accuracy. Four ideas do most of the work: fewer bits per weight, fewer weights, a smaller student network, and cheaper matrix shapes.

What is model compression, in plain words?

The idea

Training needs high precision and lots of spare capacity to find good weights. Using the model afterwards needs much less. Compression keeps the behaviour and throws away the slack:

  1. Quantisation: store each weight in 8 or 4 bits instead of 32.
  2. Pruning: set the least important weights to zero and skip them.
  3. Distillation: train a small student to imitate a large teacher.
  4. Factorisation and efficient design: replace big matrices with products of thin ones, or build the network cheap from the start.

An everyday picture

A photo straight from a camera might be 25 MB; the JPEG you send is 2 MB and looks the same. JPEG rounds away detail the eye does not notice (quantisation), drops near-zero frequency components (pruning) and keeps a compact description (low rank). Model compression does the same to weights, with accuracy playing the role of the eye.

Buys you
  • 2–8× less memory, so bigger models fit on smaller devices
  • Faster inference, since memory bandwidth is usually the bottleneck
  • Lower cost and energy per prediction
Costs you
  • Some accuracy, more at very low bit-widths
  • Speed-ups only if the hardware supports the format
  • Extra steps: calibration data, fine-tuning, evaluation

1How big is a model? Parameters × bits

Memory needed just to hold the weights, at four precisions. The dashed lines are typical devices.

Memory for the weights is simply \(\text{parameters}\times\text{bits per weight}/8\) bytes. A 7-billion-parameter model needs 28 GB in 32-bit floats, 14 GB in 16-bit, 7 GB in 8-bit and about 3.5 GB in 4-bit: the difference between a data-centre GPU and a laptop.

Memory also sets speed. Generating each token of text reads every weight once, so a model that is half the size can produce tokens almost twice as fast on the same hardware. Running needs more than the weights (activations and the KV cache, section 6), so leave headroom.

2Quantisation: round every weight to a small grid

A layer's 4,096 weights (histogram) and the grid of values they are rounded to (ticks). Fewer bits, fewer grid points, bigger rounding errors.

Scale

To store a weight in \(b\) bits, choose a scale \(s\) and keep only the integer \(q=\operatorname{round}(w/s)\), limited to the \(2^b\) values that fit. Using the weight means multiplying back: \(\hat w=s\,q\). The simplest scale makes the largest weight land on the largest integer:

$$s=\frac{\max_i|w_i|}{2^{b-1}-1},\qquad q_i=\operatorname{clip}\!\big(\operatorname{round}(w_i/s),\,-(2^{b-1}-1),\,2^{b-1}-1\big),\qquad \hat w_i=s\,q_i .$$

Each weight then moves by at most \(s/2\). Halving the bits roughly squares the number of grid points lost, so error grows fast below 4 bits. Now switch on the outliers. One huge weight stretches the scale, so the grid spacing becomes coarse for the thousands of ordinary weights. This is the central problem in quantising large language models, which have a few very large values. Two fixes: give each small group of weights its own scale (try “one scale per 64 weights”), or keep the outliers in higher precision (LLM.int8()).

Algorithm: symmetric k-bit quantisation of a weight matrix
  1. input weights \(W\), bits \(b\), group size \(g\) g = whole row, or e.g. 64 or 128
  2. for each group \(G\) of \(g\) weights do
  3. \(s_G\leftarrow\max_{w\in G}|w|\,/\,(2^{b-1}-1)\) one scale per group, kept in 16 bits
  4. \(q\leftarrow\operatorname{clip}(\operatorname{round}(w/s_G))\) for each \(w\in G\) small integers
  5. store the integers \(q\) and the scales \(s\)
  6. at inference: \(\hat W\leftarrow s\cdot q\), or multiply in integers and rescale once
  7. return \(q, s\) memory ≈ b/32 of the original, plus the scales
Going deeper: PTQ vs QAT, GPTQ and AWQ, and number formats

Post-training quantisation (PTQ) quantises a finished model, using a few hundred calibration examples to set the scales for activations. Quantisation-aware training (QAT) simulates rounding during training so the weights adapt to it; the rounding has zero gradient almost everywhere, so training uses the straight-through estimator, which treats it as the identity in the backward pass. QAT holds up better at 4 bits and below.

For LLMs, GPTQ (2022) quantises one column at a time and adjusts the remaining columns to cancel the error, using second-order information from calibration data. AWQ (2023) protects the 1% of weight channels that see the largest activations by scaling them before rounding. Both give usable 4-bit models; QLoRA (2023) fine-tunes on top of a 4-bit “NF4” base.

Formats. int8 and int4 are uniform grids. FP8 (E4M3, E5M2) keeps an exponent, so it has fine steps near zero and coarse ones far away, matching bell-shaped weights; recent GPUs compute in FP8 and FP4 directly. Activations are harder to quantise than weights because their outliers change from input to input.

3Pruning: delete the weights that matter least

A 2-16-16-1 network trained live on the moons data. Left: its decision regions on test points. Right: its three weight matrices; grey cells are pruned. Raise the sparsity, then fine-tune to win back accuracy.

Trained networks are full of weights near zero that barely affect the output. Magnitude pruning removes the smallest ones by absolute value. At moderate sparsity accuracy hardly moves; push further and it drops, but a short fine-tune with the zeros held fixed lets the remaining weights compensate. Repeating prune-then-fine-tune in small steps reaches higher sparsity than pruning all at once.

Algorithm: iterative magnitude pruning
  1. input trained weights \(W\), target sparsity \(S\), steps \(T\)
  2. mask \(M\leftarrow\) all ones
  3. for \(t=1\) to \(T\) do
  4. \(\tau\leftarrow\) the \((tS/T)\)-quantile of \(|W|\) over unpruned weights raise sparsity gradually
  5. \(M\leftarrow M\cdot\mathbb 1[|W|>\tau]\); \(W\leftarrow W\odot M\)
  6. fine-tune for a few epochs, keeping \(W\odot M\) pruned weights stay zero
  7. return sparse \(W\) and mask \(M\)
Going deeper: structured sparsity and the lottery ticket

Unstructured pruning zeroes individual weights. It compresses well but speeds things up only with sparse kernels, because GPUs prefer dense blocks. Structured pruning removes whole neurons, attention heads, channels or layers, so the result is simply a smaller dense network. NVIDIA GPUs also support a middle way, 2:4 sparsity: in every group of four weights two are zero, which doubles matrix-multiply throughput.

The lottery ticket hypothesis (Frankle and Carbin, 2019) found that if you prune a trained network and then retrain the surviving weights from their original initial values, the small network matches the big one. Large networks seem to train well partly because they contain many such lucky subnetworks.

4Knowledge distillation: learn from the teacher's doubts

A large teacher network's output for one photo of a cat. Grey: the hard label a dataset provides. Purple: the teacher's probabilities at temperature \(T\). Raise \(T\) to reveal what else the teacher thinks the image resembles.

A hard label says only “cat”. The teacher's full distribution says “cat, quite like a dog, a little like a fox, nothing like a car”. Those relative probabilities, which Hinton called dark knowledge, tell the student how the classes relate, so it learns more per example. Dividing the logits by a temperature \(T>1\) softens the distribution so the small probabilities become visible. The student is trained on a mix of both:

$$\mathcal L=\alpha\,\operatorname{CE}\big(y,\ \operatorname{softmax}(z_s)\big)+(1-\alpha)\,T^2\,\operatorname{KL}\Big(\operatorname{softmax}\big(\tfrac{z_t}{T}\big)\,\Big\|\,\operatorname{softmax}\big(\tfrac{z_s}{T}\big)\Big).$$

The \(T^2\) keeps the soft term's gradients at a comparable size as \(T\) changes. DistilBERT (2019) kept about 97% of BERT's language-understanding score with 40% fewer parameters and 60% faster inference this way. Many small open language models are now trained on text or probabilities produced by larger ones.

Algorithm: knowledge distillation training step
  1. input a batch \((x,y)\), frozen teacher \(f_t\), student \(f_s\), temperature \(T\), weight \(\alpha\)
  2. \(z_t\leftarrow f_t(x)\) teacher logits, no gradient
  3. \(z_s\leftarrow f_s(x)\) student logits
  4. \(\mathcal L_{\text{soft}}\leftarrow T^2\,\operatorname{KL}(\operatorname{softmax}(z_t/T)\,\|\,\operatorname{softmax}(z_s/T))\)
  5. \(\mathcal L_{\text{hard}}\leftarrow\operatorname{CE}(y,\operatorname{softmax}(z_s))\)
  6. update the student on \(\alpha\mathcal L_{\text{hard}}+(1-\alpha)\mathcal L_{\text{soft}}\)

5Low-rank factorisation: two thin matrices instead of one big one

The singular values of a 1,024 × 1,024 weight matrix (bars). Keeping the largest \(r\) (purple) replaces \(W\) by \(UV^\top\) with \(U,V\) of width \(r\).

The SVD writes any matrix as a sum of rank-one pieces, ordered by importance: \(W=\sum_k\sigma_ku_kv_k^\top\). If the singular values fall quickly, the first \(r\) pieces capture almost all of \(W\), and storing \(U\) (\(m\times r\)) and \(V\) (\(n\times r\)) costs \(r(m+n)\) numbers instead of \(mn\). The best possible rank-\(r\) error is set by the values you drop: \(\|W-W_r\|_F^2=\sum_{k>r}\sigma_k^2\).

The same idea powers LoRA for fine-tuning: freeze \(W\) and learn only a low-rank change \(\Delta W=BA\), with rank 8 or 16. A 4,096 × 4,096 matrix has 16.8 million weights; a rank-16 update has 131,072, under 1%.

6Efficient by design

A depthwise-separable convolution (MobileNet) does one small filter per channel, then a 1×1 mix across channels. Compare its parameters with a standard convolution.

A standard \(k\times k\) convolution from \(C_{\text{in}}\) to \(C_{\text{out}}\) channels has \(k^2C_{\text{in}}C_{\text{out}}\) weights. Splitting it into a per-channel spatial filter and a 1×1 channel mixer needs \(k^2C_{\text{in}}+C_{\text{in}}C_{\text{out}}\), about \(k^2\) times fewer for wide layers.

Other design-level savings, mostly for transformers:

  • Mixture of experts: each feed-forward layer has many experts and a router sends each token to only one or two. The model stores many parameters but uses a fraction per token, so it computes like a much smaller model.
  • KV cache: when generating, keys and values of earlier tokens are stored, costing \(2\times\text{layers}\times\text{KV heads}\times d_{\text{head}}\times\text{tokens}\times\text{bytes}\). For long contexts this can exceed the weights, so models share keys and values across heads (multi-query and grouped-query attention) and caches are quantised too.
  • FlashAttention computes exact attention in tiles that stay in fast on-chip memory, cutting memory traffic.
  • Speculative decoding: a small draft model proposes several tokens and the large model checks them in one pass, giving the same output faster.

8The same thing in Python

import torch, torch.nn as nn, torch.nn.functional as F

# dynamic int8 quantisation of the Linear layers (CPU inference)
qmodel = torch.ao.quantization.quantize_dynamic(model, {nn.Linear}, dtype=torch.qint8)

# load an LLM with 4-bit weights (bitsandbytes NF4), ready for QLoRA
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
llm = AutoModelForCausalLM.from_pretrained("model-name",
        quantization_config=BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4"))

# magnitude pruning: remove 50% of the smallest weights in every Linear layer
import torch.nn.utils.prune as prune
for m in model.modules():
    if isinstance(m, nn.Linear): prune.l1_unstructured(m, name="weight", amount=0.5)

# knowledge distillation loss
def kd_loss(z_s, z_t, y, T=4.0, alpha=0.5):
    soft = F.kl_div(F.log_softmax(z_s / T, -1), F.softmax(z_t / T, -1), reduction="batchmean") * T * T
    return alpha * F.cross_entropy(z_s, y) + (1 - alpha) * soft
