Music recommender with word2vec

Treat each playlist as a sentence and each song as a word. Word2vec learns a vector per song so that songs sharing playlists sit close together; the nearest vectors become recommendations. Everything trains in your browser in a few seconds.

Play: word2vec on words →Learn: recommender systems →

The same thing in Python

gensim trains the same skip-gram model; the radio playlist files are linked in the credits below.

# pip install gensim numpy
from gensim.models import Word2Vec

# train.txt: two header lines, then one playlist per line as song ids
playlists = [line.split() for line in open("yes_big/train.txt").read().split("\n")[2:] if len(line.split()) >= 2]
songs = {i: line.split("\t")[1:] for i, line in enumerate(open("yes_big/song_hash.txt", encoding="utf8").read().splitlines())}

model = Word2Vec(playlists, vector_size=32, window=5, negative=5, sg=1,   # sg=1 skip-gram, sg=0 CBOW
                 min_count=2, sample=1e-3, alpha=0.025, epochs=5, workers=4, seed=11)

seed = "1"                      # a song id
for sid, cos in model.wv.most_similar(seed, topn=10):
    print(f"{cos:.3f}  {songs[int(sid)]}")

# several seeds: average their unit vectors (what this page does)
print(model.wv.most_similar(positive=["1", "5", "9"], topn=10))

Data: Shuo Chen, Josh L. Moore, Douglas Turnbull and Thorsten Joachims, “Playlist Prediction via Metric Embedding”, KDD 2012 (Cornell yes.com playlist dataset, yes_big; radio playlists collected from yes.com, tags from Last.fm). Used here for teaching; subjective tags such as “favourites” removed and genres grouped into seven colours. Method: Mikolov et al., 2013; applied to playlists as “item2vec” / “prod2vec”.

RAG builder

Build a retrieval-augmented QA system step by step: pick Wikipedia articles, cut them into chunks, embed them, store the vectors in a FAISS-style index, retrieve the best chunks for a question and let a small open model (Flan-T5, DistilBERT, SmolLM2, Qwen2.5) write the answer. Then score the whole pipeline on a real QA test set. Everything runs in your browser.

6 · Evaluate on the QA test set

Run many test questions through the pipeline. Retrieval is scored by whether a chunk containing the reference answer comes back; answers by SQuAD exact match and token F1.

Change one setting at a time (chunking, embedding model, index, k) and run again: every run is kept in a table so you can compare.

7 · Compare strategies

Line up several RAG set-ups and score them on the same test questions. What happens if you chunk differently, pass the top 2 chunks instead of the top 1, or swap the embedding model or the index?
