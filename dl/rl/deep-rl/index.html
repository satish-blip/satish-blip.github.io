Deep RL: from Q-tables to PPO

The foundations page solved MDPs when the rules were known. Real agents do not get the rules; they learn from what happens when they act. This page follows the two great families of model-free RL, learning action values and learning policies directly, from a table you can watch fill up to the neural-network methods that play Atari, control robots and fine-tune chatbots.

What is deep reinforcement learning, in plain words?

The problem

Value iteration needs the transition probabilities and a table entry for every state. A video game has more screen states than atoms in the universe, and nobody gives you its rules. We need methods that learn from sampled experience and generalise between states they have never seen.

The idea

Two routes. Value-based: learn the Q-function from experience with Q-learning, then act greedily; replace the table with a neural network and you have DQN. Policy-based: make the policy itself a network and push up the probability of actions that led to high return (policy gradient). Actor–critic methods such as PPO combine both.

How it works

  1. Act in the environment, collect transitions \((s,a,r,s')\).
  2. Value route: nudge \(Q(s,a)\) towards the target \(r+\gamma\max_{a'}Q(s',a')\) (the TD target).
  3. Policy route: nudge \(\log\pi_\theta(a\mid s)\) up in proportion to how much better than expected the outcome was (the advantage).
  4. Stabilise with tricks: replay buffers, target networks, baselines and clipped updates.

An everyday picture

Learning to ride a bike. Nobody gives you the equations of balance. You try, wobble, fall (negative reward) or glide (positive reward), and gradually your body learns which small corrections work in which situations, including situations slightly different from any you practised.

Good at
  • Huge or continuous state spaces (pixels, joint angles)
  • Problems where only a simulator or a score is available
  • Superhuman play in Go, Atari and StarCraft; aligning LLMs
Watch out for
  • Unstable training and high variance between random seeds
  • Millions of interactions needed; simulators help
  • Reward hacking: the agent optimises what you wrote, not what you meant

1Q-learning and SARSA on the cliff

Walk from S to G. Each step costs −1; stepping onto the cliff costs −100 and sends you back to S. Both agents explore with ε-greedy. Lines: each agent's current greedy route.

Without a model we cannot compute \(\sum_{s'}P(s'\mid s,a)[\dots]\), but every step of experience gives one sample of it. Q-learning keeps a table \(Q(s,a)\) and, after each transition \((s,a,r,s')\), moves the entry a fraction α towards a sampled Bellman optimality target:

$$Q(s,a)\leftarrow Q(s,a)+\alpha\Big[\underbrace{r+\gamma\max_{a'}Q(s',a')}_{\text{TD target}}-Q(s,a)\Big].$$

The bracket is the TD error. Note the \(\max\): the target assumes we will act greedily from \(s'\) on, even though the agent actually explores. That makes Q-learning off-policy: it learns the value of the greedy policy while following a different, exploratory one. With enough exploration and a suitably shrinking α it converges to \(Q^*\).

SARSA differs in one symbol. It uses the action \(a'\) it really takes next, so it learns the value of the policy it follows, exploration included (on-policy):

$$Q(s,a)\leftarrow Q(s,a)+\alpha\big[r+\gamma\,Q(s',a')-Q(s,a)\big].$$

Train 500 episodes and compare the routes. Q-learning (violet) learns the shortest path, right along the cliff edge: optimal if you never slip. SARSA (cyan) knows that it explores 10% of the time, so it takes the safe route one row up, and its returns during training are better. Set ε to 0 and both converge to the edge. This is the classic example from Sutton and Barto, and the whole difference between on- and off-policy learning.

Algorithm: tabular Q-learning
  1. input step size α, discount γ, exploration ε
  2. \(Q(s,a)\leftarrow 0\) for all \(s,a\)
  3. for each episode: \(s\leftarrow\) start state
  4. repeat until \(s\) is terminal
  5. \(a\leftarrow\) ε-greedy action from \(Q(s,\cdot)\)
  6. take \(a\), observe \(r, s'\)
  7. \(Q(s,a)\leftarrow Q(s,a)+\alpha\,[\,r+\gamma\max_{a'}Q(s',a')-Q(s,a)\,]\) SARSA: \(Q(s',a')\) with the next action actually chosen
  8. \(s\leftarrow s'\)

2DQN, and why the max is too optimistic

All actions are truly worth 0. Each estimate is the truth plus noise. Histogram of the target value over 4,000 trials: the plain max (orange) versus the Double-DQN estimate (cyan).

A table needs one entry per state; Atari screens make that impossible. DQN (Mnih et al., 2015) replaces the table by a network \(Q_\theta(s,a)\) that takes the screen and outputs one value per action, and trains it by gradient descent on the squared TD error:

$$L(\theta)=\mathbb E_{(s,a,r,s')\sim\mathcal D}\Big[\big(r+\gamma\max_{a'}Q_{\bar\theta}(s',a')-Q_\theta(s,a)\big)^2\Big].$$

Naively this is unstable, because the target moves every time \(\theta\) moves and consecutive frames are almost identical. Two fixes made it work:

  • Experience replay: store transitions in a buffer \(\mathcal D\) of the last million steps and train on random minibatches, which breaks the correlation between consecutive samples and reuses each experience many times.
  • Target network: compute targets with a frozen copy \(\bar\theta\), refreshed every few thousand steps, so the network is not chasing its own tail.

A third problem is in the lab. The target uses \(\max_{a'}\) of noisy estimates, and the maximum of noisy numbers is biased upwards: \(\mathbb E[\max_a\hat Q(a)]\ge\max_a\mathbb E[\hat Q(a)]\). Errors compound through bootstrapping. Double DQN picks the action with the online network but evaluates it with the target network, \(Q_{\bar\theta}(s',\arg\max_{a'}Q_\theta(s',a'))\); because the two sets of errors are independent, the bias disappears. Increase the number of actions and watch the orange histogram slide right while the cyan one stays at 0.

Algorithm: DQN with replay and a target network
  1. initialise \(Q_\theta\), target \(\bar\theta\leftarrow\theta\), empty buffer \(\mathcal D\)
  2. for step \(t=1,2,\dots\)
  3. act ε-greedily on \(Q_\theta(s,\cdot)\); store \((s,a,r,s')\) in \(\mathcal D\)
  4. sample a random minibatch from \(\mathcal D\)
  5. \(y\leftarrow r+\gamma\max_{a'}Q_{\bar\theta}(s',a')\) 0 if s′ is terminal
  6. gradient step on \((y-Q_\theta(s,a))^2\)
  7. every \(C\) steps: \(\bar\theta\leftarrow\theta\)
Going deeper: the deadly triad and the Rainbow upgrades

Sutton and Barto call the combination of function approximation, bootstrapping (targets built from estimates) and off-policy learning the deadly triad: with all three, value estimates can diverge to infinity even on tiny problems (Baird's counterexample). DQN has all three; replay and target networks make divergence rare in practice, not impossible.

Rainbow (Hessel et al., 2018) stacked six improvements on DQN: Double DQN; prioritised replay (sample transitions with large TD error more often); duelling networks (separate heads for \(V(s)\) and the advantage \(A(s,a)\)); multi-step returns; distributional RL (learn the whole distribution of returns, not its mean); and noisy networks for exploration.

3Policy gradients: REINFORCE, with and without a baseline

A softmax policy over 3 actions with true mean rewards 1.0, 1.2 and 0.8 (plus noise), trained by REINFORCE. 40 seeds; thick line = their average probability of choosing the best action.

Baseline

Value methods learn \(Q\) and act greedily; that is awkward for continuous actions (a max over infinitely many torques) and for policies that should be random. Policy-gradient methods instead parameterise the policy \(\pi_\theta(a\mid s)\), for example a network with a softmax output, and climb the expected return \(J(\theta)=\mathbb E_{\tau\sim\pi_\theta}[G(\tau)]\) directly.

The problem is that \(J\) depends on \(\theta\) through which trajectories happen, and we cannot differentiate through the environment. The log-derivative trick fixes that. Since \(\nabla_\theta p_\theta=p_\theta\nabla_\theta\log p_\theta\), and the environment's own probabilities do not depend on \(\theta\):

$$\nabla_\theta J(\theta)=\mathbb E_{\pi_\theta}\Big[\sum_{t}\nabla_\theta\log\pi_\theta(a_t\mid s_t)\,\big(G_t-b(s_t)\big)\Big].$$

Read it as: make actions more likely in proportion to how good their outcome was. REINFORCE (Williams, 1992) estimates this expectation from sampled episodes. The baseline \(b(s)\) can be any function of the state: it leaves the expectation unchanged (because \(\mathbb E[\nabla\log\pi]=0\)) but can cut the variance enormously.

Try it. With no baseline and rewards offset by +5, every action gets reinforced after every pull, just by different amounts, so the policy wanders and the seeds disagree. A running-mean baseline turns rewards into "better or worse than usual" and learning becomes fast and consistent. Raise the offset to 20 without a baseline and it barely learns at all.

Algorithm: REINFORCE with a baseline
  1. input policy \(\pi_\theta\), learning rate η
  2. repeat
  3. run one episode with \(\pi_\theta\): \(s_0,a_0,r_1,\dots,s_T\)
  4. for \(t=0,\dots,T-1\): \(G_t\leftarrow\sum_{k\ge t}\gamma^{k-t}r_{k+1}\)
  5. \(\theta\leftarrow\theta+\eta\sum_t\nabla_\theta\log\pi_\theta(a_t\mid s_t)\,(G_t-b(s_t))\)
  6. update the baseline \(b\) towards the observed returns
Going deeper: the gradient of a softmax policy

For a softmax over action preferences \(h_\theta(s,a)\), \(\pi(a\mid s)=e^{h(s,a)}/\sum_b e^{h(s,b)}\), and \(\nabla\log\pi(a\mid s)=\nabla h(s,a)-\sum_b\pi(b\mid s)\nabla h(s,b)\). With one preference per action (the lab), the update on the chosen action \(a\) is \(+\eta(1-\pi_a)(G-b)\) and on every other action \(b\) it is \(-\eta\,\pi_b\,(G-b)\): the chosen action is pushed up exactly when its return beats the baseline.

4Actor–critic and generalised advantage estimation

How much weight GAE puts on the TD error \(k\) steps ahead, \((\gamma\lambda)^k\). λ = 0 trusts the critic after one step; λ = 1 uses the whole Monte Carlo return.

The best baseline is close to the state's value, \(b(s)\approx V(s)\), and then \(G_t-V(s_t)\) estimates the advantage \(A(s,a)=Q(s,a)-V(s)\): how much better this action was than the policy's average. An actor–critic learns both at once: the actor is the policy \(\pi_\theta\), the critic is a value network \(V_\phi\) trained by regression on returns.

The critic also lets us replace the noisy full return by a bootstrapped one. The one-step TD error \(\delta_t=r_{t+1}+\gamma V(s_{t+1})-V(s_t)\) is itself an advantage estimate: low variance, but biased if \(V\) is wrong. Generalised advantage estimation blends all horizons with a single knob λ:

$$\hat A_t^{\text{GAE}(\gamma,\lambda)}=\sum_{k=0}^{\infty}(\gamma\lambda)^k\,\delta_{t+k}.$$

λ = 0 gives the one-step TD error; λ = 1 gives the Monte Carlo advantage \(G_t-V(s_t)\). Values around 0.9 to 0.97 work well in practice. A2C runs several environments in parallel and averages their gradients synchronously; A3C did the same asynchronously on CPU threads. SAC (soft actor–critic) adds an entropy bonus to keep the policy random and is a strong default for continuous control.

5PPO: take a big step, but not too big

The PPO objective for one action as a function of the probability ratio \(r=\pi_\theta/\pi_{\text{old}}\). Shaded: where the clip makes the gradient zero.

Advantage

Policy gradients are on-policy: each batch of experience supports one small step, then it is stale. Taking many gradient steps on the same batch is tempting but dangerous: the policy drifts far from the one that collected the data, and one bad update can destroy it. Trust-region methods (TRPO) bound the change with a KL-divergence constraint. Proximal policy optimisation (Schulman et al., 2017) gets the same effect with a simple clip.

Write the probability ratio \(r_t(\theta)=\pi_\theta(a_t\mid s_t)/\pi_{\text{old}}(a_t\mid s_t)\). The plain surrogate \(r_t\hat A_t\) has the same gradient as the policy gradient at \(r=1\). PPO maximises

$$L^{\text{CLIP}}(\theta)=\mathbb E_t\Big[\min\big(r_t(\theta)\hat A_t,\ \operatorname{clip}(r_t(\theta),1-\varepsilon,1+\varepsilon)\,\hat A_t\big)\Big].$$

For a good action (\(\hat A>0\)) the objective rises with \(r\) until \(r=1+\varepsilon\), then goes flat: no reward for making it even more likely in this update. For a bad action it stops paying to push \(r\) below \(1-\varepsilon\). The min makes it a pessimistic bound, so moving the other way (making a bad action more likely) is never clipped. Move the ratio slider into the shaded region: the gradient becomes zero and that sample stops pulling.

Algorithm: PPO with clipping (actor–critic)
  1. for iteration \(=1,2,\dots\)
  2. run \(\pi_{\theta_{\text{old}}}\) in \(N\) environments for \(T\) steps
  3. compute advantages \(\hat A_t\) with GAE and returns for the critic
  4. for \(K\) epochs, over minibatches
  5. \(r_t\leftarrow\pi_\theta(a_t\mid s_t)/\pi_{\theta_{\text{old}}}(a_t\mid s_t)\)
  6. ascend \(L^{\text{CLIP}}-c_1(V_\phi(s_t)-\hat G_t)^2+c_2\,\mathcal H[\pi_\theta(\cdot\mid s_t)]\)
  7. \(\theta_{\text{old}}\leftarrow\theta\)

6RL for language models: RLHF, DPO and verifiable rewards

A language model is a policy: the state is the text so far, an action is the next token, and an episode is one response. Reinforcement learning from human feedback fine-tunes it in three stages:

  1. Supervised fine-tuning on good example responses.
  2. Reward model: people compare two responses; a network \(r_\phi(x,y)\) is trained so that \(\Pr(y_w\succ y_l)=\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)\) (the Bradley–Terry model).
  3. RL: PPO maximises the reward minus a KL penalty that keeps the model close to the supervised one, \(\max_\theta\ \mathbb E[r_\phi(x,y)]-\beta\,\mathrm{KL}(\pi_\theta\,\|\,\pi_{\text{ref}})\). Without the penalty the model learns to exploit the reward model.

DPO (direct preference optimisation, 2023) shows that the optimum of that KL-regularised objective can be written in closed form, so the reward model and the RL loop can be skipped: train directly on preference pairs with \(-\log\sigma\big(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)}-\beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\big)\).

For maths and code, rewards can be checked automatically (did the answer match, did the tests pass?). Reinforcement learning with verifiable rewards, often with GRPO (which replaces the critic by the average reward of a group of sampled answers to the same prompt), is how recent reasoning models learn to write long chains of thought.

7The same thing in Python

import gymnasium as gym, numpy as np

# tabular Q-learning on CliffWalking
env = gym.make("CliffWalking-v0")
Q = np.zeros((env.observation_space.n, env.action_space.n)); alpha, gamma, eps = 0.5, 1.0, 0.1
for episode in range(500):
    s, _ = env.reset(); done = False
    while not done:
        a = env.action_space.sample() if np.random.rand() < eps else int(Q[s].argmax())
        s2, r, term, trunc, _ = env.step(a); done = term or trunc
        Q[s, a] += alpha * (r + gamma * Q[s2].max() * (not term) - Q[s, a]); s = s2

# deep RL with a maintained library: PPO and DQN in a few lines
from stable_baselines3 import PPO, DQN
ppo = PPO("MlpPolicy", "CartPole-v1", clip_range=0.2, gae_lambda=0.95, verbose=0).learn(100_000)
dqn = DQN("MlpPolicy", "CartPole-v1", buffer_size=50_000, target_update_interval=500).learn(100_000)

# REINFORCE with a baseline in PyTorch (one update from one episode)
import torch
def reinforce_step(policy, opt, log_probs, rewards, gamma=0.99):
    G, returns = 0.0, []
    for r in reversed(rewards): G = r + gamma * G; returns.insert(0, G)
    returns = torch.tensor(returns); adv = returns - returns.mean()      # mean return as the baseline
    loss = -(torch.stack(log_probs) * adv).sum()
    opt.zero_grad(); loss.backward(); opt.step()
