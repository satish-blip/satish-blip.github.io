Reinforcement learning: learning from rewards

Every model so far learned from examples with the right answer attached. Reinforcement learning has no answer key. An agent acts, the world responds with a reward, and the agent must work out which of its many past choices earned it. This page builds the foundations: the Markov decision process that describes the problem, the Bellman equations that every RL algorithm tries to solve, and the exploration dilemma at its heart.

What is reinforcement learning, in plain words?

The problem

Some tasks are a sequence of decisions where nobody can tell you the right move, only how well things went in the end: playing a game, steering a robot, choosing which advert to show, deciding when to restock a warehouse. A good early move may only pay off many steps later, and a bad one may look fine at first.

The idea

In reinforcement learning an agent observes a state, picks an action, and receives a reward and a new state. Its goal is a policy, a rule for choosing actions, that maximises the total future reward, the return.

How it works

  1. Describe the problem as a Markov decision process: states, actions, transition probabilities, rewards and a discount factor.
  2. Define how good each state is under a policy: the value function.
  3. Use the Bellman equation, which links the value of a state to the values of its neighbours, to compute or learn values.
  4. Act greedily with respect to the values, while still exploring enough to find better options.

An everyday picture

Learning to cook without a recipe. You try a dish, your family's faces are the reward, and you slowly learn which choices (more salt, less time in the oven) lead to good dinners. You also face the explorer's dilemma: cook the favourite again, or risk something new that might be better.

Good at
  • Sequential decisions with delayed consequences
  • Problems with a clear score but no labelled examples
  • Games, control, recommendation, and fine-tuning LLMs from feedback
Watch out for
  • Needs many trials, often far more than supervised learning
  • Agents exploit badly designed rewards in surprising ways
  • Exploring in the real world can be costly or unsafe

1A Markov decision process you can edit

A robot on a grid. Green is the goal (+1), red is a pit (−1), grey cells are walls. Click a cell to cycle it: empty → wall → pit → goal. The robot is S.

Let us make the robot precise. A Markov decision process is a tuple \((\mathcal S,\mathcal A,P,R,\gamma)\):

  • \(\mathcal S\): the states, here the 35 cells.
  • \(\mathcal A\): the actions, here up, right, down, left.
  • \(P(s'\mid s,a)\): the probability of landing in \(s'\) after taking \(a\) in \(s\). With slip probability \(p\) the robot goes where it intended with probability \(1-p\) and veers left or right with probability \(p/2\) each. Bumping into a wall leaves it where it was.
  • \(R(s')\): the reward for arriving in \(s'\): +1 at the goal, −1 in a pit, and a small step reward everywhere else.
  • \(\gamma\in[0,1)\): the discount factor.

The word Markov means the next state depends only on the current state and action, not on how we got there. The robot's position is all it needs to know.

A policy \(\pi(a\mid s)\) says what to do in each state. Following it from time \(t\) produces rewards \(r_{t+1},r_{t+2},\dots\), and we score the whole future by the discounted return:

$$G_t=r_{t+1}+\gamma r_{t+2}+\gamma^2 r_{t+3}+\dots=\sum_{k=0}^{\infty}\gamma^k r_{t+k+1}.$$

Why discount? A reward now is worth more than the same reward later (it is certain, and it can be used sooner), and with \(\gamma<1\) the sum stays finite even if the episode never ends. A useful rule of thumb: the agent effectively looks about \(1/(1-\gamma)\) steps ahead, so \(\gamma=0.95\) means about 20 steps.

Press Run an episode: the robot follows the best policy found in section 2 and the slip makes each run different. Now make the step reward very negative (−0.4): life is so painful that the robot takes the shortest route even past the pit, and with a step reward above 0 it stops wanting to finish at all. The reward you write down is the behaviour you get.

2The Bellman equation and value iteration

The same grid. Colour and number show the current value estimate \(V(s)\); arrows show the greedy action. Sweep and watch values flow out from the goal.

How good is a state? Under a policy \(\pi\), the value of \(s\) is the return we expect when we start there and follow \(\pi\):

$$V^\pi(s)=\mathbb E_\pi\big[G_t\mid s_t=s\big],\qquad Q^\pi(s,a)=\mathbb E_\pi\big[G_t\mid s_t=s,\ a_t=a\big].$$

\(Q^\pi\), the action-value, also fixes the first action. Now split the return into the first reward and everything after it: \(G_t=r_{t+1}+\gamma G_{t+1}\). Taking expectations gives the Bellman expectation equation, a link between a state's value and its neighbours' values:

$$V^\pi(s)=\sum_a\pi(a\mid s)\sum_{s'}P(s'\mid s,a)\big[R(s')+\gamma V^\pi(s')\big].$$

We want the best policy, not just any. The optimal value \(V^*(s)=\max_\pi V^\pi(s)\) satisfies the Bellman optimality equation, where the average over the policy becomes a max:

$$V^*(s)=\max_a\sum_{s'}P(s'\mid s,a)\big[R(s')+\gamma V^*(s')\big],\qquad \pi^*(s)=\arg\max_a\sum_{s'}P(s'\mid s,a)\big[R(s')+\gamma V^*(s')\big].$$

Value iteration turns this equation into an update: start from any guess, and replace every \(V(s)\) by the right-hand side. Each sweep pushes information one more step away from the rewards. Press One sweep a few times: after the first sweep only the cells next to the goal and pit know about them; after ten the whole grid does. The lower chart is the biggest change per sweep on a log scale. It falls along a straight line, because each sweep shrinks the error by at least a factor \(\gamma\).

Algorithm: value iteration
  1. input MDP \((\mathcal S,\mathcal A,P,R)\), discount \(\gamma\), tolerance \(\theta\)
  2. \(V(s)\leftarrow 0\) for every state terminal states stay 0
  3. repeat
  4. \(\Delta\leftarrow 0\)
  5. for each non-terminal state \(s\)
  6. \(V_{\text{new}}(s)\leftarrow\max_a\sum_{s'}P(s'\mid s,a)\,[R(s')+\gamma V(s')]\)
  7. \(\Delta\leftarrow\max(\Delta,\ |V_{\text{new}}(s)-V(s)|)\)
  8. \(V\leftarrow V_{\text{new}}\)
  9. until \(\Delta<\theta\)
  10. return greedy policy \(\pi(s)=\arg\max_a\sum_{s'}P(s'\mid s,a)[R(s')+\gamma V(s')]\)
Going deeper: why value iteration always converges

Write one sweep as an operator, \((\mathcal T V)(s)=\max_a\sum_{s'}P(s'\mid s,a)[R(s')+\gamma V(s')]\). For any two value tables \(U,V\), the max of a difference is at most the difference of maxes, and the probabilities sum to one, so

$$\|\mathcal T U-\mathcal T V\|_\infty\le\gamma\,\|U-V\|_\infty .$$

\(\mathcal T\) is a contraction. By Banach's fixed-point theorem it has exactly one fixed point, \(V^*\), and repeating it from any start converges there geometrically: after \(k\) sweeps the error is at most \(\gamma^k\|V_0-V^*\|_\infty\). This is the straight line in the log chart. It also explains why \(\gamma\) close to 1 is slow: with \(\gamma=0.99\) you need about 460 sweeps to shrink the error 100-fold.

3Policy iteration and dynamic programming

Value iteration improves values and only reads off a policy at the end. Policy iteration alternates two clean steps instead:

  1. Policy evaluation. For the current policy \(\pi\), solve the Bellman expectation equation. For a fixed policy it is linear in \(V\): \(V^\pi=R_\pi+\gamma P_\pi V^\pi\), so \(V^\pi=(I-\gamma P_\pi)^{-1}R_\pi\) (or sweep it to convergence).
  2. Policy improvement. Make the policy greedy with respect to \(V^\pi\): \(\pi'(s)=\arg\max_a Q^\pi(s,a)\).

The policy improvement theorem says \(\pi'\) is at least as good as \(\pi\) in every state, and strictly better somewhere unless \(\pi\) is already optimal. There are finitely many deterministic policies, so policy iteration stops after a finite number of rounds, usually very few (often under ten, even for large problems).

Both methods are dynamic programming: they solve a big problem (the best plan from every state) by reusing answers to smaller ones (the values of the next states). Both also need the model, \(P\) and \(R\), written down. That is called planning.

In between sits generalised policy iteration: evaluate a little, improve a little, repeat. Almost every RL algorithm, including the deep ones on the next page, is a version of this loop where the evaluation is learned from experience instead of computed from a model.

4Exploration versus exploitation: the multi-armed bandit

1,000 ten-armed bandit problems, 1,000 pulls each, averaged. Each strategy faces the same problems.

Show

Before sequences, strip RL down to a single decision repeated many times. A multi-armed bandit has \(k\) slot machines (arms). Arm \(a\) pays a random reward with unknown mean \(q_*(a)\). You have 1,000 pulls. Which arms do you pull?

Keep an estimate for each arm, the average of the rewards it has paid so far, \(Q_t(a)\), updated incrementally after a pull: \(Q\leftarrow Q+\tfrac1N(r-Q)\). Always pulling the current best (greedy) is tempting but fragile: an arm that was unlucky on its first pull may never be tried again. The cost of not knowing is measured by regret, the reward lost against always pulling the best arm:

$$\text{Regret}_T=T\,q_*(a^*)-\sum_{t=1}^{T}q_*(a_t).$$

Three ways to explore:

  • ε-greedy: with probability ε pull a random arm, otherwise the best estimate. Simple, but it keeps exploring at rate ε forever, so regret grows linearly.
  • UCB (upper confidence bound): optimism in the face of uncertainty. Pull the arm with the highest plausible mean, \(Q_t(a)+c\sqrt{\ln t/N_t(a)}\). Rarely tried arms get a big bonus; the bonus shrinks as evidence comes in.
  • Thompson sampling: keep a Bayesian posterior for each arm's mean, draw one sample from each, and pull the arm whose sample is highest. Each arm is pulled with the probability that it is the best.

Switch to Total regret: greedy and ε-greedy rise in straight lines, while UCB and Thompson bend over, growing only like \(\log T\), which Lai and Robbins proved is the best possible rate.

5One bandit, close up

Dashes: the true mean of each arm (hidden from the agent). Bars: the agent's estimate. Under each bar: how often it was pulled.

Strategy

Pull a few times with each strategy on the same bandit. Greedy locks onto whichever arm looked good first. ε-greedy finds the best arm but keeps spending pulls on obviously bad ones. UCB tries everything once, then focuses, returning to an arm only when its bonus has grown. Thompson sampling behaves similarly but more smoothly: its random draws explore exactly as much as the uncertainty justifies.

Algorithm: ε-greedy and UCB bandit
  1. input \(k\) arms, budget \(T\), ε or \(c\)
  2. \(Q(a)\leftarrow 0,\ N(a)\leftarrow 0\) for every arm
  3. for \(t=1,\dots,T\)
  4. choose \(a_t\): random arm with prob. ε, else \(\arg\max_a Q(a)\) ε-greedy
  5. or \(a_t=\arg\max_a Q(a)+c\sqrt{\ln t/N(a)}\) UCB; untried arms first
  6. pull \(a_t\), observe reward \(r_t\)
  7. \(N(a_t)\leftarrow N(a_t)+1\)
  8. \(Q(a_t)\leftarrow Q(a_t)+\frac{1}{N(a_t)}\,(r_t-Q(a_t))\) running mean

Bandits are not only a toy. They choose which news headline to show, which drug dose to try next in adaptive trials, and which hyperparameters to evaluate next. Adding a context (features about the user) gives contextual bandits, the workhorse of online recommendation.

Going deeper: where the UCB bonus comes from

For rewards in \([0,1]\), Hoeffding's inequality bounds how far a sample mean of \(n\) pulls can be from the truth: \(\Pr\big(q_*(a)>Q(a)+u\big)\le e^{-2nu^2}\). Choose \(u\) so this probability is a small \(t^{-4}\), and you get \(u=\sqrt{2\ln t/n}\): the UCB1 bonus with \(c=\sqrt2\). With high probability every arm's true mean is below its upper bound, so a bad arm can only keep winning while its bonus is large, that is, while it has been pulled fewer than about \(\ln T/\Delta_a^2\) times, where \(\Delta_a\) is its gap to the best arm. Summing over arms gives regret \(O\big(\sum_a \ln T/\Delta_a\big)\).

6From planning to learning

Sections 2 and 3 assumed we know \(P\) and \(R\). Usually we do not: we can only act and see what happens. Model-free RL learns values or policies directly from sampled experience \((s,a,r,s')\). Two ways to estimate a value from experience:

  • Monte Carlo: play a whole episode, then move \(V(s)\) towards the actual return \(G_t\). Unbiased, but noisy and must wait for the end.
  • Temporal difference: after one step, move \(V(s)\) towards \(r+\gamma V(s')\), a target that uses the current estimate of the next state. It learns online and with less noise, at the cost of some bias. The difference \(\delta=r+\gamma V(s')-V(s)\) is the TD error.

7The same thing in Python

import numpy as np

# value iteration for a tabular MDP: P[s, a, s'] probabilities, R[s'] rewards
def value_iteration(P, R, gamma=0.95, tol=1e-8, terminal=()):
    V = np.zeros(P.shape[0])
    while True:
        Q = P @ (R + gamma * V)            # shape (S, A): expected reward + discounted next value
        V_new = Q.max(axis=1); V_new[list(terminal)] = 0
        if np.abs(V_new - V).max() < tol: return V_new, Q.argmax(axis=1)
        V = V_new

# UCB1 on a k-armed bandit
def ucb(pull, k, T, c=2.0):
    Q, N = np.zeros(k), np.zeros(k)
    for t in range(1, T + 1):
        a = int(np.argmin(N)) if N.min() == 0 else int(np.argmax(Q + c * np.sqrt(np.log(t) / N)))
        r = pull(a); N[a] += 1; Q[a] += (r - Q[a]) / N[a]
    return Q, N

# the standard toolkit for RL environments
import gymnasium as gym
env = gym.make("FrozenLake-v1", is_slippery=True)
P = np.zeros((16, 4, 16)); R = np.zeros(16)
for s, acts in env.unwrapped.P.items():
    for a, outcomes in acts.items():
        for p, s2, r, done in outcomes: P[s, a, s2] += p; R[s2] = max(R[s2], r)
V, policy = value_iteration(P, R, gamma=0.99, terminal=[5, 7, 11, 12, 15])
