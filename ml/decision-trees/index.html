Decision Trees

Linear models draw one boundary through the whole space. A decision tree does something closer to how people reason: it asks a short sequence of yes/no questions like "is \(x_1\le0.4\)?" and each answer narrows things down. Geometrically, every question cuts a region in two, so the tree carves the plane into rectangles. What is a decision tree, in plain words?

The problem

A bank wants to flag risky loan applications and, crucially, explain each decision to the applicant. "Your score was −0.37" is not an explanation. "Your income is under 30k and you already have two loans" is. We want a classifier whose reasoning is a short list of readable rules.

The idea

A decision tree is a flowchart of yes/no questions about the features: "Is \(x_1 < 0.3\)? If yes, is \(x_2 > 1.2\)?" Each answer sends a point down one branch until it reaches a leaf, which holds the prediction: the majority class of the training points that ended up there.

Which questions? The tree is grown greedily: at every node it tries every possible question and keeps the split that makes the two groups as "pure" (single-class) as possible, measured by Gini impurity or entropy. Because every question is about one feature, the boundary is made of horizontal and vertical steps.

How it works

  1. Start with all training points in one node.
  2. Try every feature and every threshold; score each split by the drop in impurity.
  3. Keep the best split and repeat on each child.
  4. Stop at a maximum depth, a minimum leaf size or a pure node; optionally prune back.

An everyday picture

The game "20 questions", or a doctor’s triage chart: each question narrows the possibilities until the answer is obvious. A good first question ("is it alive?") splits the possibilities roughly in half; a bad one ("is it a giraffe?") almost never helps. Choosing good questions is the whole game.

Good at
  • Easy to explain and draw
  • No feature scaling needed
  • Handles mixed and non-linear data
  • Captures interactions between features automatically
Watch out for
  • Deep trees overfit badly
  • Small changes in the data can change the whole tree
  • Staircase boundaries for diagonal patterns

3The maths

Three questions: how do we measure how mixed a node is, how do we score a split, and when do we stop?

Step 1: measure how mixed a node is

We want a number that is 0 when a node holds only one class and largest when it is a 50/50 mix. With \(p\) the fraction of class 1 in a node, three common choices are:

$$\begin{aligned}\text{Gini}&=1-p^2-(1-p)^2=2p(1-p)\\ \text{Entropy}&=-p\log_2p-(1-p)\log_2(1-p)\\ \text{Error}&=\min(p,\,1-p)\end{aligned}$$

Each has a story. Gini is the chance that two points drawn at random from the node have different labels. Entropy is the average number of yes/no questions needed to identify a point's label (1 bit for a fair coin, 0 bits for a certain one). Error is the fraction you would get wrong by predicting the majority.

GiniEntropy (scaled by ½ to compare)Misclassification

Gini and entropy are strictly concave, so a split that makes children purer on average always reduces them. Misclassification error is piecewise linear: many useful splits leave it unchanged, which is why it is a poor criterion for growing trees.

Going deeper: why concavity matters, with numbers

Take a parent with 400 points of class 0 and 400 of class 1 (\(p=0.5\)). Split A gives children (300, 100) and (100, 300); split B gives (200, 400) and (200, 0). Both children-weighted misclassification errors are \(\tfrac12\cdot\tfrac14+\tfrac12\cdot\tfrac14=0.25\) for A and \(\tfrac34\cdot\tfrac13+\tfrac14\cdot0=0.25\) for B. Misclassification cannot tell them apart. Gini: A gives \(2\cdot\tfrac34\cdot\tfrac14=0.375\) in both children, so 0.375; B gives \(\tfrac34\cdot2\cdot\tfrac13\cdot\tfrac23+\tfrac14\cdot0=0.333\). Gini prefers B, which has a pure child that will never need splitting again.

In general, the weighted average of the children's \(p\) values is the parent's \(p\). For a strictly concave \(I\), Jensen's inequality gives \(\tfrac{n_L}{n}I(p_L)+\tfrac{n_R}{n}I(p_R)\le I(p)\), with equality only if \(p_L=p_R\). So any split that changes the class mix strictly reduces Gini or entropy, while a linear-piece criterion can stay flat.

Step 2: score a split

A split on feature \(j\) at threshold \(t\) sends \(n_L\) points left and \(n_R\) right. Its score is how much it lowers impurity, weighting each child by its size so that a tiny pure child cannot win on its own:

$$\Delta(j,t)=I(\text{parent})-\frac{n_L}{n}I(\text{left})-\frac{n_R}{n}I(\text{right}),\qquad (j^\star,t^\star)=\arg\max_{j,\,t}\Delta(j,t)$$

The search costs \(O(d\,n\log n)\) per node: sort each feature once and sweep the thresholds while updating class counts. With entropy, \(\Delta\) is the information gain: how many bits of uncertainty about the label the question removes.

Step 3: grow recursively, then stop (CART)

Algorithm: growing a classification tree (CART)
  1. function Grow(points \(S\), depth)
  2. if \(S\) is pure or depth = max depth or \(|S|<2\cdot\)min leaf then
  3. return Leaf(majority class of \(S\), class fractions)
  4. best \(\leftarrow\) none
  5. for each feature \(j\) do
  6. sort \(S\) by \(x_j\); start with all points on the right
  7. for each point in sorted order do move it to the left, update counts in O(1)
  8. \(t\leftarrow\) midpoint to the next distinct value
  9. if both sides ≥ min leaf and \(\Delta(j,t)>\) best then best \(\leftarrow(j,t)\)
  10. if best is none then return Leaf(majority class of \(S\))
  11. \(L\leftarrow\{x\in S:x_{j^\star}\le t^\star\}\); \(R\leftarrow S\setminus L\)
  12. return Node(\(j^\star,t^\star\), Grow(\(L\), depth+1), Grow(\(R\), depth+1))

Controlling complexity

A fully grown tree reaches zero training error on any data without duplicate points: it can always keep cutting until every leaf has one point. That is memorisation, not learning. Limit depth or leaf size, or grow fully and then prune by cost-complexity, which charges \(\alpha\) per leaf:

$$R_\alpha(T)=\sum_{\text{leaves }m}n_m\,I_m+\alpha\,|T|$$

Trees are unstable (high variance): small data changes can change the top split and everything below it. That weakness is exactly what bagging and random forests fix on the next page.

Going deeper: weakest-link pruning

For each internal node \(t\), compare keeping its subtree \(T_t\) with collapsing it to a leaf. The subtree is worth keeping only while \(\alpha<g(t)=\frac{R(t)-R(T_t)}{|T_t|-1}\), the impurity reduction it buys per extra leaf. Weakest-link pruning repeatedly collapses the node with the smallest \(g(t)\), giving a nested sequence of trees, one for each range of \(\alpha\). Cross-validation then picks the \(\alpha\) (and so the tree) with the best held-out score. This is scikit-learn's cost_complexity_pruning_path. It is better than stopping early because a split that looks useless now (XOR's root) can enable very useful splits below it.

4Depth and overfitting

training accuracytest accuracy (fresh 400 points)dashed: current max depth

Training accuracy climbs to 100% as the tree deepens. Test accuracy peaks and then falls, or flattens, as the extra leaves carve out noise. The gap between the two curves is variance. Raise the noise slider and watch the peak move to a shallower depth: noisier data has less real structure to find.

Trees have real strengths: they need no feature scaling, handle mixed feature types, capture interactions automatically and are easy to read. Their boundaries are always axis-aligned staircases, so a diagonal line needs many splits; compare Linear blobs here with logistic regression.

from sklearn.tree import DecisionTreeClassifier, plot_tree, export_text

tree = DecisionTreeClassifier(criterion="gini", max_depth=6, min_samples_leaf=1).fit(X, y)
print(export_text(tree, feature_names=["x1", "x2"]))
plot_tree(tree, filled=True)

# cost-complexity pruning path, then pick alpha by cross-validation
path = tree.cost_complexity_pruning_path(X, y)
pruned = DecisionTreeClassifier(ccp_alpha=path.ccp_alphas[-3]).fit(X, y)
