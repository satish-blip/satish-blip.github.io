Bagging & Boosting

A single decision tree is easy to read but unreliable: deep trees chase noise, shallow trees miss structure. This page shows two ways to turn many imperfect trees into one strong model. Bagging (random forests) trains deep trees independently on resampled data and averages them, which cuts variance. Boosting (AdaBoost) trains tiny trees one after another, each focusing on the points the previous ones got wrong, which cuts bias. Step through both algorithms on the same data.

What are bagging and boosting, in plain words?

The problem

On the decision tree page, pressing "New sample" gave a noticeably different tree each time. A model whose answer depends that much on which training points happened to be collected has high variance. On the other hand, a tree limited to one question (a stump) is stable but far too simple: it has high bias. Can we combine trees to get the best of both?

The idea

An ensemble combines many simple models into a stronger one. There are two big recipes, one for each problem.

Bagging fixes variance. It trains many models side by side, each on a slightly different random copy of the data (a bootstrap sample), and lets them vote. A random forest does this with deep decision trees, which are individually unstable but whose mistakes average out. Boosting fixes bias. It trains models one after another; each new one concentrates on the points the previous ones got wrong. AdaBoost does this with tiny one-question trees (stumps).

How it works

  1. Bagging: draw a bootstrap sample, train a tree, repeat many times, then take the majority vote.
  2. Random forest: also pick a random subset of features at each split so the trees differ more.
  3. Boosting: train a weak learner, raise the weight of the points it got wrong, train the next one on the re-weighted data.
  4. Give each boosted learner a vote in proportion to its accuracy, and sum.

An everyday picture

Bagging is asking 100 people to guess the number of sweets in a jar and taking the average: individual guesses are wild, but their errors partly cancel. It works best when the people think independently, which is what the random feature subsets in a forest try to ensure. Boosting is a study group where each new member focuses on the questions the group still gets wrong.

Good at
  • Among the most accurate methods on tabular data
  • Random forests need almost no tuning and give a free error estimate
  • Boosting turns very weak models into strong ones
Watch out for
  • Harder to interpret than one tree
  • Boosting can overfit noisy labels
  • More computation

2Why averaging works

Why should averaging many bad-ish trees give a good one? The answer is a two-line variance calculation, and it also explains why random forests deliberately hide features.

Step 1: averaging independent guesses

Suppose each tree's prediction at a point \(x\) is a random quantity (random because the bootstrap sample is random) with variance \(\sigma^2\). If the \(B\) trees were completely independent, their average would have variance \(\sigma^2/B\): a hundred trees would be ten times less wobbly (in standard deviation) than one.

Step 2: but the trees are correlated

Trees trained on overlapping data are not independent. If any two have correlation \(\rho\), the average has variance

$$\operatorname{Var}\Big(\frac1B\sum_{b=1}^B\hat f_b(x)\Big)=\rho\,\sigma^2+\frac{1-\rho}{B}\,\sigma^2$$

Adding trees kills the second term, but the first term stays: no number of trees can push variance below \(\rho\sigma^2\). Bagged trees are correlated because they all see similar data and grab the same strong splits, so \(\rho\) is large.

Step 3: decorrelate

Random forests lower \(\rho\) by hiding features at each split: trees are forced to differ. Each tree is a little worse, but the average is better. Switch between "1 of 2" and "2 of 2" above and compare the final test error.

Bias is unchanged by averaging: a forest of depth-1 trees is still a weak model. That is why forests use deep, low-bias trees, and why boosting (which fights bias) uses shallow ones.
Going deeper: deriving the variance of a correlated average

Let \(f_b\) have variance \(\sigma^2\) and \(\operatorname{Cov}(f_b,f_c)=\rho\sigma^2\) for \(b\ne c\). Variance of a sum is the sum of all covariances: \(\operatorname{Var}(\sum_bf_b)=\sum_b\operatorname{Var}(f_b)+\sum_{b\ne c}\operatorname{Cov}(f_b,f_c)=B\sigma^2+B(B-1)\rho\sigma^2\). Divide by \(B^2\): \(\frac{\sigma^2}{B}+\frac{B-1}{B}\rho\sigma^2=\rho\sigma^2+\frac{1-\rho}{B}\sigma^2\). Feature subsampling lowers \(\rho\) at the price of a slightly larger \(\sigma^2\) and bias per tree; the usual defaults, \(m=\sqrt d\) for classification and \(m=d/3\) for regression, are the empirical sweet spots.

The 63.2% rule

Each draw misses a particular point with probability \(1-1/n\), and there are \(n\) independent draws:

$$P(\text{point } i\text{ never drawn})=\Big(1-\frac1n\Big)^n\ \xrightarrow{n\to\infty}\ e^{-1}\approx0.368$$

So every tree leaves about a third of the data out-of-bag, which gives the OOB estimate for free: each point is judged only by trees that never saw it, just like a test set.

Variance shrinking, live

The curve is \(\rho\sigma^2+(1-\rho)\sigma^2/B\) with \(\sigma^2=1\) for \(\rho=\) 0, 0.2, 0.5 and 0.8. Lower correlation gives a lower floor.

Algorithm: random forest (classification)
  1. input data \(\{(x_i,y_i)\}_{i=1}^n\) with \(d\) features, number of trees \(B\), features per split \(m\)
  2. for \(b=1\) to \(B\) do
  3. \(S_b\leftarrow\) \(n\) indices drawn uniformly with replacement bootstrap
  4. grow tree \(T_b\) on \(S_b\) as in CART, except:
  5. at each node, choose \(m\) features at random and search splits only on those
  6. remember the out-of-bag set \(O_b\leftarrow\{1..n\}\setminus S_b\)
  7. to predict \(x\): \(\hat p(x)\leftarrow\tfrac1B\sum_b\hat p_{T_b}(x)\); return \([\hat p(x)\ge0.5]\)
  8. OOB error: for each \(i\), average only trees with \(i\in O_b\); compare with \(y_i\)

4The AdaBoost maths

The reweighting rule and the \(\alpha_t\) formula above look like clever tricks. They are not: both drop out of one loss function, minimised one tree at a time.

Step 1: pick a loss for the whole ensemble

Use labels \(y_i\in\{-1,+1\}\). The ensemble's score is \(F(x)=\sum_t\alpha_th_t(x)\), and \(y_iF(x_i)\) is positive when the point is classified correctly, large when confidently so. AdaBoost uses the exponential loss, which punishes negative values sharply:

$$L(F)=\sum_{i=1}^n e^{-y_iF(x_i)},\qquad F_t=F_{t-1}+\alpha_th_t$$

Step 2: add one learner at a time

We do not re-fit old learners; we only choose the next \(h_t\) and its weight \(\alpha_t\). Split the loss: \(e^{-y_iF_t(x_i)}=e^{-y_iF_{t-1}(x_i)}\cdot e^{-\alpha_ty_ih_t(x_i)}\). The first factor is fixed, so it acts as a weight on point \(i\): \(w_i\propto e^{-y_iF_{t-1}(x_i)}\). That is exactly \(D_t\), and it explains step ③: points the ensemble gets wrong have large \(w_i\).

Step 3: the best vote for that learner

For a fixed \(h_t\), correct points contribute \(e^{-\alpha}\) and wrong ones \(e^{\alpha}\), so the loss is \(e^{-\alpha}(1-\varepsilon_t)+e^{\alpha}\varepsilon_t\) up to a constant. Setting the derivative to zero:

$$-e^{-\alpha}(1-\varepsilon_t)+e^{\alpha}\varepsilon_t=0\ \Longrightarrow\ \alpha_t=\tfrac12\ln\frac{1-\varepsilon_t}{\varepsilon_t}$$

So AdaBoost is forward stagewise additive modelling with exponential loss, the idea that gradient boosting later generalised to any differentiable loss: each new tree is fitted to the negative gradient of the loss (for squared error, simply the residuals).

Algorithm: AdaBoost
  1. input data \((x_i,y_i)\) with \(y_i\in\{-1,+1\}\), rounds \(T\), weak-learner depth
  2. \(D_1(i)\leftarrow1/n\) for all \(i\)
  3. for \(t=1\) to \(T\) do
  4. \(h_t\leftarrow\) small tree fitted with point weights \(D_t\)
  5. \(\varepsilon_t\leftarrow\sum_iD_t(i)\,[h_t(x_i)\ne y_i]\)
  6. if \(\varepsilon_t\ge\tfrac12\) then stop no better than chance
  7. \(\alpha_t\leftarrow\tfrac12\ln\frac{1-\varepsilon_t}{\varepsilon_t}\)
  8. \(D_{t+1}(i)\leftarrow D_t(i)\,e^{-\alpha_ty_ih_t(x_i)}\) for all \(i\)
  9. divide \(D_{t+1}\) by its sum \(Z_t\)
  10. return \(H(x)=\operatorname{sign}\big(\sum_t\alpha_th_t(x)\big)\)

Training error falls exponentially

$$\begin{aligned}\frac1n\sum_i[H(x_i)\ne y_i]\ &\le\ \prod_{t=1}^TZ_t=\prod_{t=1}^T2\sqrt{\varepsilon_t(1-\varepsilon_t)}\\ &\le\ \exp\Big(-2\sum_t\gamma_t^2\Big),\quad \gamma_t=\tfrac12-\varepsilon_t\end{aligned}$$

In words: as long as each weak learner beats a coin flip by some margin \(\gamma\), training error goes to zero, and fast. Watch the purple bound in the chart above sit on top of the training error.

Going deeper: proving the training-error bound

Unroll the weight update: \(D_{T+1}(i)=\frac{1}{n}\frac{e^{-y_iF_T(x_i)}}{\prod_tZ_t}\). The weights sum to 1, so \(\frac1n\sum_ie^{-y_iF_T(x_i)}=\prod_tZ_t\). A mistake means \(y_iF_T(x_i)\le0\), so \(e^{-y_iF_T(x_i)}\ge1\): the exponential loss is an upper bound on the 0/1 loss, and the training error is at most \(\prod_tZ_t\). With the optimal \(\alpha_t\), \(Z_t=(1-\varepsilon_t)e^{-\alpha_t}+\varepsilon_te^{\alpha_t}=2\sqrt{\varepsilon_t(1-\varepsilon_t)}=\sqrt{1-4\gamma_t^2}\le e^{-2\gamma_t^2}\), using \(1+x\le e^x\).

Why does test error often keep falling after training error reaches zero? Boosting keeps increasing the margins \(y_iF(x_i)/\sum_t\alpha_t\) of the training points, and generalisation bounds depend on the margin distribution rather than on the number of rounds (Schapire et al., 1998). The same idea underlies the SVM.

Where stumps fail. On XOR, every single-feature stump has \(\varepsilon\approx0.5\), so \(\alpha\approx0\) and boosting stalls: no stump beats chance, and adding zero-weight stumps never helps. Switch the weak learner to depth 2 (which can represent an interaction) and it works. Weak learners must be weakly better than chance.
Sensitive to noise. Mislabelled points keep getting heavier, so on Noisy labels boosting eventually spends its rounds on them. Watch the test error curve.

5Bagging vs boosting at a glance

Bagging / random forestBoosting / AdaBoost
Base learnersDeep trees (low bias, high variance)Shallow trees, often stumps (high bias, low variance)
TrainingIndependent, in parallel, each on a bootstrap sampleSequential, each on reweighted data
CombinationEqual-weight averageWeighted vote with \(\alpha_t\)
Mainly reducesVarianceBias (and variance)
More learnersNever overfits by adding trees; error levels offCan eventually overfit noisy data; tune T
NoiseRobustSensitive (exponential loss up-weights outliers)
Free extrasOut-of-bag error, feature importanceMargin view, training error bound

In practice, the strongest tabular models today are gradient-boosted trees (XGBoost, LightGBM, CatBoost): boosting with a smooth loss, a small learning rate that shrinks each tree's contribution, and random row and feature subsampling borrowed from forests.
