Logistic Regression

Suppose you want to decide whether an email is spam, or whether a tumour is malignant. The answer is yes or no, so a straight line that can output 7.3 or −2 is the wrong tool. Logistic regression keeps the familiar weighted sum from linear regression but bends it through an S-shaped curve so that it outputs a probability. This page builds it step by step: why the S-curve, how the weights are learned, why the learning rule looks exactly like linear regression's, and how to turn probabilities into decisions.

What is logistic regression, in plain words?

The problem

We have examples with two features each, say the income and the existing debt of past loan applicants, and a label \(y\in\{0,1\}\): did they repay (1) or not (0)? Given a new applicant, we want more than a yes or no. We want a number like "73% chance of repaying", so the bank can choose how cautious to be. That is a classification problem with a probability as the output.

Why not just use linear regression?

We could fit a line to the 0s and 1s and call anything above 0.5 a "1". It half works, but the line happily predicts 1.4 or −0.3, which are not probabilities, and a single far-away example tilts the whole line and moves the boundary. We want something that stays between 0 and 1 and saturates gracefully.

The idea

Keep the weighted score \(z = w^\top x + b\) from linear regression, then squash it through the sigmoid \(\sigma(z)=1/(1+e^{-z})\). A very negative score gives a probability near 0, a very positive one gives near 1, and a score of 0 gives exactly 0.5. The set of points where the score is 0 is the decision boundary: a straight line, unless you add polynomial features. The weights are chosen so the predicted probabilities make the observed labels as likely as possible, which turns out to mean minimising the log-loss.

How it works

  1. Score: \(z = w^\top x + b\).
  2. Probability: \(p = \sigma(z) = 1/(1+e^{-z})\).
  3. Loss: penalise confident wrong answers heavily (cross-entropy).
  4. Minimise it with gradient descent or Newton’s method; add an L2 or L1 penalty to keep weights in check.
  5. Predict class 1 when \(p\) is above a threshold.

An everyday picture

A bank deciding whether to approve a loan: income and debt go in, a probability of repayment comes out, and the bank chooses how cautious to be by moving the threshold. A cautious bank lends only above 90%; an aggressive one lends above 40%. The model is the same; only the decision rule changes.

Good at
  • Gives calibrated probabilities, not just labels
  • Weights are interpretable as changes in log-odds
  • Convex: always finds the best weights
  • Fast, and a strong baseline for any yes/no task
Watch out for
  • Linear boundary unless you engineer features
  • Weights blow up on perfectly separable data without regularisation
  • Correlated features make individual weights hard to read

Learned weights

Features are polynomial terms \(x_1^ax_2^b\), standardised before fitting. For degree 1 the boundary is the line \(w_0+w_1\tilde x_1+w_2\tilde x_2=0\). Each weight says how much one standard deviation of that feature changes the log-odds: a weight of 1 multiplies the odds by \(e\approx2.7\).

2The sigmoid and the log-loss

Two small functions do all the work. The sigmoid turns a score into a probability; the log-loss scores that probability against the true label. Move the score and watch both.

Why this particular S-curve? Read it backwards: if \(p=\sigma(z)\) then \(z=\log\frac{p}{1-p}\), the log-odds. So the model is simply "the log-odds are a linear function of the inputs". Odds range over \((0,\infty)\) and log-odds over all real numbers, which is exactly the range a weighted sum can produce.

loss if the true label is 1: \(-\log p\)loss if the label is 0: \(-\log(1-p)\)

Confident and wrong is punished without limit: at \(p=0.01\) for a true 1, the loss is \(4.6\). That is why the optimiser fights hard for every misclassified point, and why perfectly separable data sends \(\lVert w\rVert\to\infty\) without a penalty. Confident and right costs almost nothing: at \(p=0.99\) the loss is \(0.01\).

3The maths

We follow the same three steps as for linear regression: write down the model, decide what "good weights" means, then find them. The surprise at the end is that the learning rule has exactly the same shape.

Step 1: the model is linear in the log-odds

$$P(y=1\mid x)=\sigma(w^\top x)=\frac{1}{1+e^{-w^\top x}}\qquad\Longleftrightarrow\qquad \log\frac{P(y=1\mid x)}{P(y=0\mid x)}=w^\top x$$

(We fold the intercept \(b\) into \(w\) by adding a constant feature \(x_0=1\).) The boundary \(P=0.5\) is where \(w^\top x=0\): a hyperplane in feature space, with \(w\) pointing towards class 1. The further a point is from that plane, the more confident the model. With polynomial features \(\phi(x)\) the boundary becomes a curve in the original space, but the model is still linear in \(w\), so all the maths below is unchanged.

Step 2: good weights make the data likely

For one example, the model says \(P(y_i=1)=p_i\) and \(P(y_i=0)=1-p_i\). A neat way to write both cases at once is \(P(y_i)=p_i^{\,y_i}(1-p_i)^{1-y_i}\): when \(y_i=1\) the second factor is 1, and vice versa. If the examples are independent, the probability of the whole training set is the product, and we pick \(w\) to make that product as large as possible (maximum likelihood). Products are awkward, so take logs, flip the sign, average, and add a penalty:

$$L(w)=-\frac1n\sum_{i=1}^n\Big[y_i\log p_i+(1-y_i)\log(1-p_i)\Big]+\frac\lambda2\lVert w\rVert^2,\qquad p_i=\sigma(w^\top x_i)$$

The bracket is the log-loss you saw in section 2: for each example, only one of the two terms is switched on. So "maximise the likelihood" and "minimise the cross-entropy" are the same instruction.

Step 3: find the minimum

Using the handy identity \(\sigma'(z)=\sigma(z)(1-\sigma(z))\), the gradient collapses to a remarkably simple form:

$$\nabla L(w)=\frac1n X^\top(p-y)+\lambda w$$

Read it as: for every example, take the error (predicted probability minus label) and push the weights along that example's features in proportion to it. That is word for word the LMS rule for linear regression, with \(x^\top\beta\) replaced by \(\sigma(w^\top x)\). It is not a coincidence; both are special cases of generalised linear models (see Going deeper).

Gradient descent: \(w\leftarrow w-\eta\,\nabla L(w)\). There is no closed form, unlike linear regression, because \(p\) depends non-linearly on \(w\), so setting the gradient to zero gives equations we cannot solve by hand. We iterate instead.

Algorithm: logistic regression by gradient descent (L2 penalty)
  1. input features \(X\) (\(n\) rows, first column all 1s), labels \(y\in\{0,1\}^n\), step \(\eta\), penalty \(\lambda\)
  2. standardise every non-constant column of \(X\)
  3. \(w\leftarrow 0\) every probability starts at 0.5
  4. repeat
  5. \(z\leftarrow Xw\); \(p\leftarrow 1/(1+e^{-z})\) elementwise
  6. \(g\leftarrow\tfrac1n X^\top(p-y)+\lambda w\) don't penalise the intercept in practice
  7. \(w\leftarrow w-\eta\,g\)
  8. until \(\lVert g\rVert\) is tiny or the loss stops falling
  9. return \(w\)
Going deeper: deriving the gradient, and the GLM view

The derivative of the sigmoid. \(\sigma(z)=(1+e^{-z})^{-1}\), so \(\sigma'(z)=e^{-z}(1+e^{-z})^{-2}=\sigma(z)\cdot\frac{e^{-z}}{1+e^{-z}}=\sigma(z)(1-\sigma(z))\).

The gradient of one term. Let \(\ell_i=-[y_i\log p_i+(1-y_i)\log(1-p_i)]\) with \(p_i=\sigma(z_i)\), \(z_i=w^\top x_i\). Then \(\frac{\partial\ell_i}{\partial p_i}=-\frac{y_i}{p_i}+\frac{1-y_i}{1-p_i}=\frac{p_i-y_i}{p_i(1-p_i)}\). Multiply by \(\frac{\partial p_i}{\partial z_i}=p_i(1-p_i)\): the awkward factors cancel and \(\frac{\partial\ell_i}{\partial z_i}=p_i-y_i\). Finally \(\frac{\partial z_i}{\partial w}=x_i\), so \(\nabla\ell_i=(p_i-y_i)x_i\). Average over \(i\) and stack: \(\frac1nX^\top(p-y)\).

Why the same shape as least squares. Linear regression (Gaussian \(y\)) and logistic regression (Bernoulli \(y\)) are both generalised linear models: the distribution of \(y\) is in the exponential family, \(p(y;\eta)=b(y)\exp(\eta\,y-a(\eta))\), and the natural parameter is linear, \(\eta=w^\top x\). For the Bernoulli, \(\eta=\log\frac{p}{1-p}\), which is where the sigmoid comes from: it is the inverse of the natural link, not an arbitrary choice. In every GLM the log-likelihood gradient is \(\sum_i(y_i-\mathbb E[y_i\mid x_i])x_i\), "observed minus expected, times the input". Poisson regression for counts gives the same rule with \(\mathbb E[y]=e^{w^\top x}\).

Convexity and Newton's method

Is the bowl a nice single bowl, like in linear regression? Differentiate once more:

$$\nabla^2L(w)=\frac1nX^\top S X+\lambda I,\qquad S=\operatorname{diag}\big(p_i(1-p_i)\big)\succeq0$$

The Hessian is positive semi-definite, so \(L\) is convex: any local minimum is global, and gradient descent with a small enough step will find it. Notice the weights \(p_i(1-p_i)\): they are largest (0.25) for points the model is unsure about and near zero for points it already classifies confidently. The curvature comes from the uncertain points near the boundary.

Gradient descent only uses the slope. Newton's method also uses the curvature: it fits a quadratic bowl at the current \(w\) and jumps straight to that bowl's bottom, \(w\leftarrow w-(\nabla^2L)^{-1}\nabla L\). Each Newton step is a weighted least-squares problem, which is why it is also called iteratively reweighted least squares (IRLS). It usually converges in under 10 steps. Press Solve (Newton) and compare with gradient descent.

Algorithm: Newton's method (IRLS)
  1. input \(X\), \(y\), penalty \(\lambda\)
  2. \(w\leftarrow 0\)
  3. repeat usually 5–10 times
  4. \(p\leftarrow\sigma(Xw)\); \(S\leftarrow\operatorname{diag}(p_i(1-p_i))\)
  5. \(g\leftarrow\tfrac1nX^\top(p-y)+\lambda w\)
  6. \(H\leftarrow\tfrac1nX^\top SX+\lambda I\)
  7. solve \(H\Delta=g\); \(w\leftarrow w-\Delta\) one (d+1)×(d+1) linear solve
  8. until \(\lVert\Delta\rVert\) is tiny
  9. return \(w\)
Going deeper: why Newton converges so fast, and when it costs too much

Near the optimum \(w^*\), a Newton step satisfies \(\lVert w_{t+1}-w^*\rVert\le C\lVert w_t-w^*\rVert^2\) (quadratic convergence): the number of correct digits roughly doubles each step. Gradient descent only shrinks the error by a constant factor per step, about \(1-1/\kappa\) where \(\kappa\) is the condition number of the Hessian. The price is the linear solve, \(O(d^3)\) per step, and storing the \(d\times d\) Hessian. With millions of features that is impossible, so large-scale solvers use quasi-Newton methods (L-BFGS keeps a low-rank approximation of the inverse Hessian) or stochastic gradients. Both are what scikit-learn's lbfgs and saga solvers do.

Separable data

If a hyperplane separates the classes perfectly, scaling \(w\) up always lowers the loss: every \(p_i\) moves closer to its label. So with \(\lambda=0\) the weights grow forever and probabilities become 0 or 1. Choose Linear blobs, set λ to its minimum and run GD: watch \(\lVert w\rVert\) climb. The L2 penalty fixes this by charging for size, so the optimum becomes finite.

L1 instead of L2. Replacing \(\tfrac\lambda2\lVert w\rVert^2\) by \(\lambda\lVert w\rVert_1\) makes the loss non-differentiable at 0, so Newton no longer applies. The page then uses proximal gradient descent: a gradient step on the cross-entropy, followed by soft-thresholding. Weights that do not earn their keep land exactly on 0. Pick degree 6, switch to L1 and raise λ: watch the number of non-zero weights fall. More on the L1 and L2 regularisation page.

Algorithm: proximal gradient descent for L1
  1. \(w\leftarrow 0\)
  2. repeat
  3. \(u\leftarrow w-\tfrac{\eta}{n}X^\top(\sigma(Xw)-y)\) plain step on the log-loss only
  4. for each \(j\) do \(w_j\leftarrow\operatorname{sign}(u_j)\max(|u_j|-\eta\lambda,\,0)\) shrink, snap small ones to 0
  5. until \(w\) stops changing
  6. return \(w\)

Compared with LDA

LDA also gives linear log-odds, but it gets \(w\) by modelling each class as a Gaussian with a shared covariance. Logistic regression fits \(P(y\mid x)\) directly (discriminative) and makes no assumption about how \(x\) is distributed, so it is more robust when the Gaussian assumption is wrong. LDA wins with very little data when the assumption is roughly right, because it uses more of the information in the data.

4Threshold, confusion matrix and ROC

The model gives probabilities; a decision needs a cut-off. Predicting class 1 when \(p\ge0.5\) is only a default, and it is right only if both kinds of mistake cost the same. Missing a cancer is far worse than an extra biopsy, so a hospital would use a lower threshold. Move \(t\) and see the trade-off on the current model and data.

ROC curve: true-positive rate vs false-positive rate over all thresholds. The dot is \(t\). AUC is the area underneath: the probability that a random class-1 point gets a higher score than a random class-0 point. 0.5 is guessing, 1 is perfect.

Predicted probabilities for each class. The threshold is the vertical line; everything right of it is predicted as class 1. The more the two histograms overlap, the less any threshold can do.

Reading the confusion matrix

Every prediction is one of four kinds: a true positive (said 1, was 1), a false positive (said 1, was 0), a true negative, or a false negative. Precision \(=\mathrm{TP}/(\mathrm{TP}+\mathrm{FP})\) asks "when the model says yes, how often is it right?". Recall \(=\mathrm{TP}/(\mathrm{TP}+\mathrm{FN})\) asks "of all the real yeses, how many did it find?". Lowering \(t\) finds more positives (recall up) but lets in more false alarms (precision down).

Going deeper: choosing the threshold from costs

Suppose a false positive costs \(c_{\mathrm{FP}}\) and a false negative costs \(c_{\mathrm{FN}}\). For a point with probability \(p\), predicting 1 has expected cost \((1-p)c_{\mathrm{FP}}\) and predicting 0 has \(p\,c_{\mathrm{FN}}\). Predict 1 when the first is smaller: \(p>t^*=\frac{c_{\mathrm{FP}}}{c_{\mathrm{FP}}+c_{\mathrm{FN}}}\). Equal costs give 0.5; if a miss is nine times worse than a false alarm, \(t^*=0.1\). This only works if the probabilities are calibrated, which is one of the real strengths of logistic regression over, say, an SVM.

Algorithm: ROC curve and AUC
  1. input scores \(p_i\), labels \(y_i\); \(P\) = number of 1s, \(N\) = number of 0s
  2. sort examples by \(p_i\), highest first
  3. \(\mathrm{TP}\leftarrow0\); \(\mathrm{FP}\leftarrow0\); curve \(\leftarrow[(0,0)]\)
  4. for each example in that order do lowering t past one score at a time
  5. if \(y_i=1\) then \(\mathrm{TP}\leftarrow\mathrm{TP}+1\) else \(\mathrm{FP}\leftarrow\mathrm{FP}+1\)
  6. append \((\mathrm{FP}/N,\ \mathrm{TP}/P)\) to curve
  7. AUC \(\leftarrow\) area under curve by the trapezoid rule
  8. return curve, AUC

from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.metrics import confusion_matrix, roc_auc_score

clf = make_pipeline(PolynomialFeatures(3, include_bias=False), StandardScaler(),
                    LogisticRegression(C=1 / (n * lam)))   # sklearn's C is the inverse penalty
clf.fit(X, y)
p = clf.predict_proba(X)[:, 1]
confusion_matrix(y, p >= 0.5), roc_auc_score(y, p)

# gradient descent by hand
w = np.zeros(d)
for _ in range(1000):
    p = 1 / (1 + np.exp(-X @ w))
    w -= eta * (X.T @ (p - y) / n + lam * w)

# Newton / IRLS by hand: a handful of steps
for _ in range(8):
    p = 1 / (1 + np.exp(-X @ w))
    H = X.T @ (X * (p * (1 - p))[:, None]) / n + lam * np.eye(d)
    w -= np.linalg.solve(H, X.T @ (p - y) / n + lam * w)
