Evaluation metrics: what “good” means

A model is only as good as the number you judge it by. Pick the wrong metric and a useless model can look excellent: a cancer test that always says “healthy” is 99% accurate. This page builds every common metric from one idea, counting what the model got right and wrong, and shows when each one misleads.

What is an evaluation metric, in plain words?

The idea

A metric is a number that summarises how well predictions match the truth on data the model has never seen (the test set). The loss is what the model is trained to minimise; a metric is what you care about. They are often different: a network is trained on cross-entropy, but you report accuracy, recall or revenue.

How it works

  1. Hold out data the model never trained on.
  2. Compare each prediction with the truth.
  3. Count or average the agreements and mistakes in a way that reflects their real cost.
  4. Report the number with its uncertainty, and compare with a simple baseline.

An everyday picture

Airport security can stop every bag (no bomb ever gets through, endless queues) or no bag (no queues, every bomb gets through). Both extremes are “perfect” by one measure and absurd by another. Every metric on this page is a different way of saying how to trade those two kinds of mistake.

Good habits
  • Choose the metric before looking at results
  • Always show a baseline (majority class, mean prediction)
  • Report uncertainty: a confidence interval
Classic traps
  • Accuracy on imbalanced data
  • Tuning on the test set
  • Comparing scores computed on different data

1The confusion matrix: four ways to be right or wrong

A classifier gives each example a score. Orange: true positives' scores; teal: true negatives'. Everything right of the threshold is predicted positive. Counts are per 1,000 test examples.

Every binary prediction lands in one of four cells. A true positive (TP) is a sick patient flagged as sick; a false positive (FP) is a healthy one flagged; a false negative (FN) is a sick one missed; a true negative (TN) a healthy one cleared. Every classification metric is a ratio of these four counts:

MetricFormulaQuestion it answers
Accuracy\(\frac{TP+TN}{\text{all}}\)How often is it right?
Precision\(\frac{TP}{TP+FP}\)When it says positive, how often is it?
Recall (sensitivity, TPR)\(\frac{TP}{TP+FN}\)Of the real positives, how many did it find?
Specificity (TNR)\(\frac{TN}{TN+FP}\)Of the real negatives, how many did it clear?
F1\(\frac{2PR}{P+R}\)Harmonic mean of precision and recall: low if either is low
Balanced accuracy\(\frac{\text{TPR}+\text{TNR}}2\)Accuracy as if the classes were equally common
MCC\(\frac{TP\cdot TN-FP\cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}\)A correlation between prediction and truth, −1 to 1; fair under imbalance
Going deeper: more than two classes, and F-beta

With \(K\) classes the confusion matrix is \(K\times K\). Precision and recall are computed per class (that class against the rest), then averaged. Macro averaging gives every class equal weight, so rare classes count. Micro averaging pools all the counts first; for single-label problems micro-F1 equals accuracy. Weighted averaging weights each class by its frequency.

\(F_\beta=(1+\beta^2)\frac{PR}{\beta^2P+R}\) treats recall as \(\beta\) times as important as precision. \(F_2\) suits screening, where a miss is worse than a false alarm; \(F_{0.5}\) suits spam filtering, where a false alarm (a lost real email) is worse.

2Every threshold at once: ROC and precision–recall curves

Sweep the threshold from high to low and plot each confusion matrix as one point. Left: ROC (recall against false-positive rate). Right: precision against recall. The dot is the threshold from section 1.

A single threshold is a business decision. To judge the model, look at all thresholds. The ROC curve plots recall (TPR) against the false-positive rate \(\text{FPR}=FP/(FP+TN)\). Its area, the AUC, has a clean meaning: the probability that a random positive gets a higher score than a random negative. 0.5 is coin-flipping; 1 is perfect ranking.

Now drag the prevalence in section 1 down to 1%. The ROC curve does not move at all, because TPR and FPR are each computed within one class. The precision–recall curve collapses: with 99 negatives per positive, even a small FPR means many false alarms per true find. For rare events (fraud, disease, defects), the PR curve and its area, average precision (AP), tell the truth that ROC hides.

Algorithm: precision–recall curve and average precision
  1. input scores \(s_i\) and labels \(y_i\in\{0,1\}\) for the test set, with \(P\) positives
  2. sort examples by score, highest first
  3. \(TP\leftarrow0,\ FP\leftarrow0,\ AP\leftarrow0\)
  4. for each example in that order do lower the threshold past it
  5. if \(y=1\) then \(TP\leftarrow TP+1\); \(AP\leftarrow AP+\frac{1}{P}\cdot\frac{TP}{TP+FP}\) else \(FP\leftarrow FP+1\)
  6. record the point (recall \(TP/P\), precision \(TP/(TP+FP)\))
  7. return the curve and \(AP\) precision averaged over the positions of the positives

3Are the probabilities honest? Calibration and log loss

A reliability diagram. Predictions are grouped by the probability the model gave; each bar shows how often the event actually happened in that group. A calibrated model lies on the diagonal.

When a weather model says “70% rain”, it should rain on about 70% of those days. That property is calibration, and it matters whenever the probability itself drives a decision: pricing, triage, or deciding when to ask a human. Accuracy and AUC ignore it completely: squash every probability towards 0.5 and the ranking, so the AUC, is unchanged.

Two metrics score probabilities directly. Log loss (cross-entropy) \(-\frac1n\sum[y\log p+(1-y)\log(1-p)]\) punishes confident mistakes without limit. The Brier score \(\frac1n\sum(p-y)^2\) is the mean squared error of the probabilities. ECE (expected calibration error) is the average gap between the bars and the diagonal, weighted by how many predictions fall in each bin.

Above 1 the model is over-confident (bars flatter than the diagonal), as modern deep networks typically are; below 1 it is under-confident. The fix, temperature scaling, divides the logits by one number fitted on validation data, which is exactly this slider.

4Regression: how far off, on average?

Predictions (line) against actual values (dots) for 30 houses. One prediction can be made badly wrong with the slider. Watch which metrics react.

MetricFormulaRead it as
MAE\(\frac1n\sum|y-\hat y|\)Typical error, in the target's units; robust to outliers
MSE / RMSE\(\frac1n\sum(y-\hat y)^2\), its square rootPunishes big misses much more; RMSE is in the target's units
R²\(1-\frac{\sum(y-\hat y)^2}{\sum(y-\bar y)^2}\)Share of variance explained; 0 = no better than predicting the mean
MAPE\(\frac1n\sum\big|\frac{y-\hat y}{y}\big|\)Percentage error; explodes when \(y\) is near 0
Median AEmedian of \(|y-\hat y|\)The typical miss, ignoring the worst half entirely

RMSE and R² follow the squared error, which is what least squares minimises, so one bad miss dominates them. MAE moves linearly and the median barely moves. Report the one whose notion of “cost” matches yours: an insurer pricing a portfolio cares about totals (MSE-like); a customer cares about their own quote (MAE-like).

5Ranking and retrieval: is the best stuff at the top?

A search engine returned these 8 documents in this order. The number is how relevant each really is (3 = perfect, 0 = useless). Use the arrows to reorder them and watch the metrics.

Search, recommendation and retrieval for RAG return a ranked list, and users mostly look at the top. So these metrics only look at the first \(k\) results and reward putting good items early.

  • Precision@k: share of the top \(k\) that are relevant. Recall@k: share of all relevant items that made the top \(k\).
  • MRR: \(1/\text{rank}\) of the first relevant result, averaged over queries. Good when one right answer is enough.
  • nDCG@k: uses graded relevance, discounts each position by \(\log_2(\text{rank}+1)\), and divides by the best possible score so a perfect order gets 1.
$$\text{DCG@}k=\sum_{i=1}^{k}\frac{2^{\text{rel}_i}-1}{\log_2(i+1)},\qquad \text{nDCG@}k=\frac{\text{DCG@}k}{\text{DCG@}k\text{ of the ideal order}}.$$
Algorithm: nDCG@k
  1. input relevance grades \(\text{rel}_1..\text{rel}_n\) in the order the system ranked them, cut-off \(k\)
  2. \(\text{DCG}\leftarrow\sum_{i=1}^{k}(2^{\text{rel}_i}-1)/\log_2(i+1)\) gain, discounted by position
  3. sort the grades from best to worst: the ideal ranking
  4. \(\text{IDCG}\leftarrow\) the same sum over the ideal ranking
  5. return \(\text{DCG}/\text{IDCG}\) 1 means no better order exists

6Generated text: BLEU, ROUGE, perplexity and beyond

Reference
Candidate

Text has no single right answer, so early metrics compared word overlap with human references. BLEU (for translation) asks what fraction of the candidate's 1-, 2-, 3- and 4-word sequences appear in the reference, with counts clipped so repeating “the the the” earns nothing. It takes the geometric mean and multiplies by a brevity penalty, since a two-word candidate could otherwise score perfectly. ROUGE (for summaries) flips the question to recall: how much of the reference does the candidate cover?

Algorithm: BLEU score
  1. input candidate \(c\) and reference \(r\), as word lists
  2. for \(n=1\) to \(4\) do
  3. \(p_n\leftarrow\dfrac{\sum_{g}\min(\text{count}_c(g),\text{count}_r(g))}{\#\text{n-grams in }c}\) clipped n-gram precision
  4. \(BP\leftarrow1\) if \(|c|>|r|\), else \(e^{1-|r|/|c|}\) brevity penalty
  5. return \(BP\cdot\exp\big(\tfrac14\sum_n\log p_n\big)\) geometric mean

Overlap metrics miss meaning: “the cat sat on the mat” and “a feline rested on the rug” share almost nothing. Modern evaluation of language models uses:

  • Perplexity \(=\exp(\text{average negative log-likelihood per token})\): how surprised the model is by real text. Only comparable between models with the same tokeniser.
  • Exact match / accuracy on questions with one answer (multiple-choice exams such as MMLU).
  • pass@k for code: generate \(k\) programs, count a success if any passes the unit tests. With \(n\ge k\) samples of which \(c\) pass, the unbiased estimate is \(1-\binom{n-c}{k}/\binom{n}{k}\).
  • Embedding similarity (BERTScore) and LLM-as-a-judge, where a strong model grades answers against a rubric; and human preference arenas that compare two answers side by side and fit Elo-style ratings.

7Vision: intersection over union

The green box is the true object; the orange box is the model's detection. Move and resize the detection.

A detector must say where, not just what. IoU measures box overlap: the area they share divided by the area they cover together. A detection usually counts as correct if IoU ≥ 0.5.

$$\text{IoU}=\frac{|A\cap B|}{|A\cup B|},\qquad \text{Dice}=\frac{2|A\cap B|}{|A|+|B|}.$$

Object detection is then scored like retrieval: rank all detections by confidence, mark each as TP or FP using the IoU rule, compute average precision per class (section 2), and average over classes: mAP. COCO reports mAP averaged over IoU thresholds 0.5, 0.55, …, 0.95, which rewards tight boxes. For segmentation, IoU and Dice are computed per pixel.

ProblemReportAvoid relying on
Balanced classificationAccuracy, F1, AUC—
Rare positives (fraud, disease)Precision and recall at the operating threshold, PR-AUC, MCCAccuracy, ROC-AUC alone

RegressionMAE and RMSE together, R² for contextMAPE when targets can be near 0

Whichever you choose, compute it on a test set that was never used for any decision, report a confidence interval, and test whether a difference between two models is real with a paired test.
