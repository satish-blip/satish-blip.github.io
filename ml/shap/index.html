SHAP values: why this prediction?

The previous page asked what a model does overall. Here the question is narrower and often more urgent: why did it price this house at 212 thousand, or turn down this loan? SHAP answers by splitting the prediction into one share per feature, using a 70-year-old idea from game theory about sharing a prize fairly. We build it by hand, run it on the same house-price model, then meet the other local methods: LIME, gradients and counterfactuals.

What is a SHAP value, in plain words?

The idea

Start from the model's average prediction over typical data, the base value. For one house the model predicts something else. A SHAP value is the part of that difference credited to one feature, and the parts add up exactly:

$$f(x)=\underbrace{\mathbb E[f(X)]}_{\text{base value}}+\phi_1+\phi_2+\dots+\phi_d .$$

“Area +31, age −18, distance −6, garden +9” is a complete account of why this prediction is 16 above average. The shares are Shapley values, the unique way of splitting a total that satisfies a short list of fairness rules.

An everyday picture

Three friends share a taxi home. Alone, each fare would differ; together the ride costs one amount. How much should each pay? Shapley's answer: imagine the friends joining the ride one at a time in every possible order, note how much each one adds to the fare when they join, and average over the orders. Replace friends by features and the fare by the prediction, and you have SHAP.

Why people like it
  • Adds up exactly to the prediction
  • One principled definition, any model
  • Local shares average into global plots
What to watch
  • Expensive without tricks
  • Depends on the background data
  • Credits the model, not the real world

1Shapley values: share the prize fairly

A tiny model with three features. \(v(S)\) is its prediction, relative to the average, when only the features in \(S\) are known. Edit the values or pick a preset; the table plays all 6 joining orders.

In game theory, \(d\) players can form any coalition \(S\), and a value function \(v(S)\) says what that coalition earns, with \(v(\varnothing)=0\). Lloyd Shapley (1953) asked how to divide the grand total \(v(\{1..d\})\) among the players. His answer averages each player's marginal contribution \(v(S\cup\{j\})-v(S)\) over every order in which the players could arrive:

$$\phi_j=\sum_{S\subseteq\{1..d\}\setminus\{j\}}\frac{|S|!\,(d-|S|-1)!}{d!}\,\Big[v(S\cup\{j\})-v(S)\Big].$$

The weight is just the fraction of orderings in which exactly the players in \(S\) arrive before \(j\). With three players there are \(3!=6\) orders, shown as the rows of the table.

Algorithm: exact Shapley values by orderings
  1. input players \(1..d\), value function \(v\) with \(v(\varnothing)=0\)
  2. \(\phi_j\leftarrow0\) for every \(j\)
  3. for each of the \(d!\) orderings \(\pi\) do
  4. \(S\leftarrow\varnothing\)
  5. for each player \(j\) in the order \(\pi\) do
  6. \(\quad\phi_j\leftarrow\phi_j+v(S\cup\{j\})-v(S)\); \(S\leftarrow S\cup\{j\}\) marginal contribution
  7. return \(\phi_j/d!\) for every \(j\) average over orderings

Shapley proved this is the only split with four properties:

  • Efficiency: the shares add up to the total, \(\sum_j\phi_j=v(\text{all})\).
  • Symmetry: two players who always add the same get the same.
  • Dummy: a player who never adds anything gets 0.
  • Additivity: for two games played together, shares add. (For models: the SHAP values of a sum of trees are the sums of each tree's values.)

Try the presets. Additive: each feature adds the same whatever else is known, so every order agrees. Interaction: area and garden are only worth 30 together; the 30 is shared equally between them. Redundant pair: area and bedrooms carry the same information, so whoever arrives first takes it; on average they split it.

2Explaining one prediction: the waterfall

Start at the base value (the average prediction over 40 background houses), add each feature's SHAP value, end at this house's prediction. Red pushes the price up, blue pushes it down. Exact values from all 64 coalitions.

To use Shapley values on a model we need \(v(S)\): what does the model predict when it only “knows” the features in \(S\)? A model cannot leave an input blank, so SHAP fills the unknown features in from real data and averages. Take a set of background houses \(z^{(1)},\dots,z^{(B)}\) (here 40 training houses):

$$v(S)=\frac1B\sum_{b=1}^{B}f\big(x_S,\;z^{(b)}_{\bar S}\big)\;-\;\frac1B\sum_{b}f\big(z^{(b)}\big),$$

that is, keep this house's values for the features in \(S\), take the rest from each background house, predict, average, and measure from the base value. Plug this \(v\) into Shapley's formula. With 6 features there are \(2^6=64\) coalitions, each needing 40 predictions: 2,560 predictions per house, fast enough to do exactly here.

Switch to the linear model. For a linear model the whole calculation collapses to one line, which the page checks for you:

$$\phi_j=\beta_j\,\big(x_j-\bar z_j\big):\quad\text{the coefficient times how far this house is from the average.}$$

So a SHAP value is not a coefficient. A large coefficient on a feature where this house is perfectly average gives a SHAP value of zero. With boosted trees the shares also absorb curves and interactions: a big house far from the centre gets a much more negative distance value than a small one at the same distance.

Going deeper: interventional or observational? Which “missing” do we mean?

The formula above replaces the unknown features independently of the known ones, the interventional (or marginal) value function \(\mathbb E_{Z}[f(x_S,Z_{\bar S})]\). The alternative, observational (conditional) SHAP, uses \(\mathbb E[f(X)\mid X_S=x_S]\), which respects correlations: knowing the area, it only fills in bedroom counts that go with that area. Janzing et al. (2020) argue the interventional version is the right one for explaining the model (it is the causal effect of the inputs on the output); the conditional one can give credit to features the model never uses, through their correlation with used ones. The conditional version is also much harder to estimate. The shap library's Explainer with a background masker and TreeSHAP's feature_perturbation="interventional" both compute the interventional values used here.

3From one house to all of them

Compute SHAP values for many houses and stack them. Three standard pictures, all from the same table of numbers (one row per house, one column per feature):

  • Beeswarm (summary plot). One row per feature, one dot per house, placed at its SHAP value and coloured by the feature's value (blue low, red high). Area: red dots on the right, so big houses are pushed up. Age: red on the left, but bunched, because the age effect levels off. The listing code stays close to zero; its small spread is noise the trees picked up.
  • Mean |SHAP|. Average the absolute SHAP values per feature: a global importance measured in the units of the prediction (thousands). Compare with permutation importance: similar ranking, different question (how much it moves predictions, not how much accuracy it buys).
  • Dependence plot. One feature's value across, its SHAP value up, coloured by a second feature. It is the SHAP cousin of the PD curve, but shows each house. Pick distance: the dots fan out by colour, because distance hurts large (red) houses more. Vertical spread at the same x is the signature of an interaction.
Going deeper: SHAP interaction values

The Shapley interaction index (Grabisch and Roubens 1999) splits each \(\phi_j\) further into a main effect \(\phi_{jj}\) and pairwise terms \(\phi_{jk}=\phi_{kj}\), so that \(\phi_j=\phi_{jj}+\sum_{k\ne j}\phi_{jk}\). For trees, Lundberg et al. (2020) compute the whole \(d\times d\) matrix per prediction in polynomial time (shap_interaction_values). Summed over houses, the area–distance cell would light up here, and only that one.

4Computing SHAP when there are many features

Error of two estimators against the exact values for the house picked in section 2, averaged over 8 runs, as the number of model predictions grows (log scale). Exact needs 2,560 predictions here; with 30 features it would need 43 billion.

The exact sum has \(2^d\) terms: fine for 6 features, impossible for 100. Three ideas make SHAP practical.

1. Sample orderings (Monte Carlo)

Štrumbelj and Kononenko (2014): instead of all \(d!\) orders, draw random ones. For each, start from a random background house, switch its features to this house's values one at a time in that order, and record how much the prediction moves at each switch. Every ordering costs \(d+1\) predictions and gives one noisy sample of every \(\phi_j\); the error shrinks like \(1/\sqrt{\text{samples}}\) and the shares still add up exactly.

Algorithm: Monte Carlo Shapley values (permutation sampling)
  1. input model \(f\), instance \(x\), background data, number of samples \(T\)
  2. for \(t=1\) to \(T\) do
  3. draw a random ordering \(\pi\) and a random background row \(z\)
  4. \(r\leftarrow z\); \(p\leftarrow f(r)\)
  5. for each \(j\) in the order \(\pi\) do
  6. \(\quad r_j\leftarrow x_j\); \(\phi_j\leftarrow\phi_j+f(r)-p\); \(p\leftarrow f(r)\) switch one feature
  7. return \(\phi_j/T\) for every \(j\)

2. KernelSHAP: a weighted regression

Lundberg and Lee (2017) proved that Shapley values are the solution of a weighted least-squares problem. Code each coalition as a 0/1 vector \(z'\), fit a linear model \(g(z')=\phi_0+\sum_j\phi_jz'_j\) to the values \(v(S)\), and weight each coalition by the Shapley kernel

$$\pi(z')=\frac{d-1}{\binom{d}{|z'|}\,|z'|\,(d-|z'|)} .$$

Very small and very large coalitions get the most weight: they tell you the most about a single feature. Sampling a few hundred coalitions often gets close; with all of them the regression returns the exact Shapley values, which the orange curve reaches at 2,560 predictions.

Algorithm: KernelSHAP
  1. input value function \(v\), \(d\) features, number of coalitions \(K\)
  2. for \(k=1\) to \(K\) do
  3. draw a size \(s\) with probability \(\propto\frac{d-1}{s(d-s)}\), then a random coalition \(z'_k\) of that size
  4. evaluate \(v(z'_k)\) with the background data \(B\) predictions
  5. solve \(\min_\phi\sum_k\big(v(z'_k)-\phi_0-\sum_j\phi_jz'_{kj}\big)^2\) subject to \(\sum_j\phi_j=f(x)-\phi_0\)
  6. return \(\phi_1,\dots,\phi_d\)

3. TreeSHAP: exact and fast for trees

For tree ensembles, Lundberg et al. (2020) push all coalitions through each tree at once, tracking what fraction of each subset reaches each leaf. The result is exact in \(O(TLD^2)\) time (trees × leaves × depth²) instead of exponential: milliseconds per row for XGBoost, LightGBM and scikit-learn forests. This is why SHAP became the default explanation for tabular models. For deep networks, DeepSHAP and GradientSHAP use the gradient ideas of section 6.

5LIME: a simple model that is right nearby

A black-box loan model: shaded green where it approves. Click any point to explain it. Dots are LIME's random samples, sized by their weight; the dashed line is the local linear surrogate's 50% boundary, the arrow the true local direction (the gradient).

LIME (Ribeiro, Singh and Guestrin, 2016) explains one prediction by fitting an easy model, usually a sparse linear one, that only has to be right near that point. Any curved boundary looks straight if you zoom in far enough.

Algorithm: LIME for tabular data
  1. input black box \(f\), instance \(x\), kernel width \(\sigma\), samples \(N\)
  2. for \(i=1\) to \(N\) do
  3. draw a perturbed point \(z_i\) from the features' spread
  4. \(y_i\leftarrow f(z_i)\); \(w_i\leftarrow\exp\!\big(-\lVert z_i-x\rVert^2/\sigma^2\big)\) nearby counts more
  5. fit a weighted linear model \(g\) to \((z_i,y_i)\) with weights \(w_i\) often with a feature limit
  6. return the coefficients of \(g\) as the explanation

It works for text and images too: perturb by deleting words or greying out patches of pixels (super-pixels). That flexibility is why LIME spread fast.

Now drag the kernel width. Small: only the nearest samples count, the surrogate tracks the gradient, but with few effective samples it jitters each time you resample. Large: the surrogate fits the whole curved boundary with one line and can point the wrong way. There is no principled choice of width, and Alvarez-Melis and Jaakkola (2018) found explanations of nearby points can disagree. The fidelity number tells you whether to trust a given explanation at all.

SHAP and LIME are related: KernelSHAP is LIME with one particular choice of kernel, loss and sampling, the choice that makes the coefficients Shapley values.

6Neural networks: gradients and Integrated Gradients

A small saturating model \(f=\sigma(2.5x_1+1.5x_2+x_1x_2-2)\). Drag the input (filled dot) and the baseline (ring). Bars compare gradient × input with Integrated Gradients; IG's bars always add up to \(f(x)-f(\text{baseline})\).

A network is differentiable, so its gradient is the obvious explanation: how much would the output change per unit nudge of each input? For an image, the gradient's size per pixel is a saliency map (Simonyan et al., 2014). Multiply by the input and you get gradient × input, an attribution in the units of the output.

Gradients have a blind spot: saturation. Put the input at (2, 2), deep in the flat top of the sigmoid. The model is certain, its output far above the baseline's, yet the gradient is almost zero, so gradient × input says no feature mattered. Integrated Gradients (Sundararajan, Taly and Yan, 2017) fixes this by walking a straight line from a baseline \(x'\) (a black image, all-zero embedding, or a reference input) to \(x\) and adding up the gradients along the way:

$$\mathrm{IG}_j(x)=(x_j-x'_j)\int_0^1\frac{\partial f\big(x'+\alpha(x-x')\big)}{\partial x_j}\,d\alpha .$$

By the fundamental theorem of calculus for path integrals, the attributions satisfy completeness: \(\sum_j\mathrm{IG}_j=f(x)-f(x')\), the same efficiency property as SHAP. In fact IG is the Aumann–Shapley value from game theory, the continuous version of Shapley.

Algorithm: Integrated Gradients
  1. input differentiable model \(f\), input \(x\), baseline \(x'\), steps \(m\)
  2. \(g\leftarrow0\)
  3. for \(k=1\) to \(m\) do
  4. \(z\leftarrow x'+\frac km(x-x')\) a point on the straight path
  5. \(g\leftarrow g+\nabla f(z)\) one backward pass
  6. return \((x-x')\odot g/m\) check: sum \(\approx f(x)-f(x')\)

Lower the step count to 2 or 3 and watch the completeness gap grow: the integral is a sum, and 20 to 300 steps are typical in practice. Move the baseline and the attributions change: the explanation is always relative to a reference, just as SHAP's is relative to the background data.

The wider toolbox for deep nets

  • SmoothGrad averages gradients over noisy copies of the input to cut speckle. Grad-CAM weights a CNN's last feature maps by their gradients to get a coarse heat-map of where the network looked.
  • DeepSHAP and GradientSHAP approximate SHAP for networks with back-propagation rules or IG from several baselines.
  • Attention weights (see self-attention) show where a transformer reads, but are not by themselves explanations of the output (Jain and Wallace, 2019).
  • Mechanistic interpretability opens the network itself: probes, concept vectors (TCAV), and sparse autoencoders that break a language model's activations into millions of human-readable features, then follow how they connect (Anthropic, 2023 to 2025).

7Counterfactuals: what would have to change?

The same loan model. Click a declined applicant (outside the green). The arrow is the smallest change that gets them approved; with the lock on, credit history cannot change.

To the person who was declined, “income −0.21, history +0.05” is less useful than “with 1,200 more a month you would have been approved”. A counterfactual explanation (Wachter, Mittelstadt and Russell, 2017) is the closest input that gets the outcome you want:

$$x^{\text{cf}}=\arg\min_{x'}\;d(x,x')\quad\text{subject to}\quad f(x')\ge0.5,$$

usually solved with a penalty \(\lambda\,(f(x')-0.5)^2+d(x,x')\) and gradient steps, or by search. Here the page searches every direction and keeps the nearest approved point, with distance measured after scaling each feature by its spread, so one unit means the same in both directions.

Good counterfactuals are actionable (do not ask anyone to get younger or change their history: tick the lock), sparse (change as few features as possible), and plausible (land where real applicants live). DiCE (Mothilal et al., 2020) returns several diverse ones. They need no access to the model's insides and match how lending rules phrase “reasons for decline”, but they say what would flip the model, which may not be what would change the real outcome.

8Using SHAP well: pitfalls and good habits

Things that go wrong

  • The background is part of the answer. SHAP values explain the gap from the background's average. Explain a loan against all applicants or against approved applicants and you get different numbers. Choose it on purpose, and say what it was.
  • Correlated features. Interventional SHAP fills in impossible combinations, as PD does; credit between near-copies can be shared out arbitrarily. Group them, or explain the group.
  • The output scale. For classifiers, TreeSHAP explains the log-odds by default, where effects add; in probability space the same feature can look weaker at the extremes. Say which you plot.
  • Not causal. A large SHAP value means the model leans on a feature, not that changing it would change the world. Shoe size predicts reading skill in children because both track age.
  • Explanations can be gamed. Slack et al. (2020) built models that behave badly on real data but innocently on the off-manifold points LIME and KernelSHAP probe, so the explanations look clean.

Good habits

  • Check the model is accurate before explaining it.
  • Use TreeSHAP for trees (exact, fast); KernelSHAP or permutation sampling with a few hundred background rows otherwise.
  • Look at the beeswarm and dependence plots, not only the bar of means: the spread and the colours carry the story.
  • Cross-check with a second method (permutation importance, PD/ALE) and a second good model (the Rashomon effect).
  • For decisions about people, give reasons people can act on: counterfactuals or “top reasons” (in insurance and credit these are often required) and check explanations per group as part of a fairness review.
