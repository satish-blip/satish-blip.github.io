How to read this page

The question

After reading about each method on its own, the natural question is: which one should I use? The honest answer is "it depends on the shape of your data", and this page lets you see exactly how. Think of each dataset as a different kind of problem and each algorithm as a different set of assumptions about what boundaries look like. A method wins when its assumptions match the problem.

Every classifier on this site is trained here on every dataset, using the same training points, and scored on the same held-out test points. Each small plot shows one model’s decision boundary: colour is the predicted class, dots are the data.

No model wins everywhere. Linear models are perfect on blobs and hopeless on circles; trees and forests handle almost anything but draw staircases; kernel SVMs and boosted ensembles adapt to curves. That is the "no free lunch" idea in one picture.

What the grid teaches

Linear models (least squares, logistic, LDA, linear SVM) agree with each other almost everywhere. They are excellent on linear blobs and noisy labels and collapse to coin-flipping on XOR and circles, because no straight line can help there.
Features or kernels fix linearity. Logistic with polynomial features, QDA (quadratic by construction) and the polynomial/RBF SVMs bend the boundary. QDA nails circles (a Gaussian inside a ring), but not moons or spirals, which are not Gaussian at all.
Trees and ensembles carve axis-aligned boxes. A single tree is jagged and overfits noisy labels; a random forest smooths it; AdaBoost with stumps cannot do XOR because no single-feature stump beats chance there (see the boosting page).
No free lunch. No algorithm wins every column. Check the average column: the most flexible models (RBF SVM, forests) are usually near the top on average, but lose to simple linear models when the true boundary is a line and the data is noisy.
Where is PCA? PCA is unsupervised: it never sees labels, so it is not a classifier. It is often used before one of these to reduce dimensions. See the PCA page and its PCA-vs-LDA section.

How this grid is built (and how to compare models fairly yourself)

Every cell follows the same recipe, and the important rule is that the test points are never used for anything except the final score. If you tune hyperparameters by looking at test accuracy, the test score stops being an honest estimate of performance on new data.

Algorithm: a fair model comparison
  1. input dataset \(D\), list of models, test share \(q\)
  2. shuffle \(D\); hold out a fraction \(q\) as the test set same split for every model
  3. for each model \(m\) do
  4. choose \(m\)'s hyperparameters by cross-validation on the training part only
  5. fit \(m\) on the whole training part
  6. record train accuracy and test accuracy
  7. repeat with several random splits; report mean ± spread one split can mislead
  8. call a difference real only if it beats the split-to-split noise

Press New random sample a few times and watch the numbers move by a few points: that is the noise any single comparison carries. The hypothesis testing page shows how to test whether one model really beats another.

Why no model wins everywhere

Every learner has an inductive bias: the kind of boundary it finds easy to draw. Linear models assume a hyperplane; QDA assumes Gaussian blobs; trees assume axis-aligned boxes; an RBF SVM assumes the answer changes smoothly over a length scale \(1/\sqrt\gamma\). When the true boundary matches the assumption, a little data goes a long way. When it does not, the model either cannot fit (bias) or needs a lot of data and tuning to compensate (variance).

Going deeper: the bias–variance decomposition and "no free lunch"

For squared error at a point \(x\), averaging over random training sets: \(\mathbb E[(y-\hat f(x))^2]=\underbrace{(f(x)-\mathbb E\hat f(x))^2}_{\text{bias}^2}+\underbrace{\operatorname{Var}\hat f(x)}_{\text{variance}}+\sigma^2\). Linear models on circles have huge bias; a depth-12 tree on noisy labels has huge variance; the irreducible \(\sigma^2\) is the label noise, which no model can remove. (The linear regression page derives this.)

The no-free-lunch theorem (Wolpert, 1996) makes "no universal winner" precise: averaged uniformly over all possible labelling functions, every learning algorithm has the same expected accuracy on points it has not seen. Any algorithm that does better on some problems must do worse on others. Learning works in practice only because real problems are not uniform: they have smoothness and structure, and a good choice of model is a good guess about that structure.
