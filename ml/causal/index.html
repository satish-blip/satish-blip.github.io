Causal inference: what did the action actually cause?

Prediction asks what will happen. Decisions ask what will happen if we act: if we send this discount, change this price, ship this feature. Those are different questions, and data collected without an experiment can answer the second one badly while answering the first one well. This page shows why, then works through the tools: randomised A/B tests and how to size them, propensity scores when you cannot randomise, difference-in-differences for policies that hit one group at a time, and uplift models that find who responds to a treatment. Every lab runs on simulated data whose true effect we know, so you can see each method hit or miss it.

What is causal inference, in plain words?

The problem

Customers who got a discount spent more. Did the discount cause it, or did we give discounts to customers who were going to spend more anyway? A model trained on this data will happily predict that discounted customers spend more, and still tell you nothing about what a discount does. The variable that drove both the treatment and the outcome (here, how engaged the customer already was) is a confounder.

The idea

Write down what each person's outcome would have been under each choice, their potential outcomes \(Y(1)\) and \(Y(0)\). The effect for that person is \(Y(1)-Y(0)\), but we only ever see one of the two: this is the fundamental problem of causal inference. We can still estimate the average effect, either by randomising who gets treated (an experiment) or, without randomisation, by comparing like with like under assumptions we must state and defend.

How it works

  1. State the question as a contrast: effect of T on Y, for whom.
  2. Randomise if you can: an A/B test makes the groups comparable by design.
  3. If not, adjust for confounders: regression, propensity scores, or a natural experiment such as difference-in-differences.
  4. Check the assumptions (overlap, parallel trends) with plots, not hope.
  5. For targeting, estimate how the effect varies: uplift.

An everyday picture

Hospitals with the best surgeons often have higher death rates, because the hardest cases are sent to them. Comparing raw death rates would tell you to avoid the best surgeons. Comparing patients of the same severity across hospitals gives the right answer. Causal inference is the discipline of making that “same severity” comparison carefully, and of knowing when it cannot be made.

Good at
  • Answering “what if we do X?”, the question decisions need
  • Experiments give unbiased answers with honest error bars
  • Uplift targets only people the treatment actually changes
Watch out for
  • Unmeasured confounders cannot be adjusted for from data alone
  • Peeking at A/B tests inflates false positives
  • Assumptions (overlap, parallel trends) can fail quietly

1Simpson's paradox: the same data, two answers

Two treatments for kidney stones. Treatment A is better for small stones and for large stones. Change how doctors allocate hard cases and watch the pooled comparison flip.

The numbers are modelled on a famous 1986 study of kidney-stone treatments: within each stone size, open surgery (A) succeeded more often than the less invasive treatment (B), yet over all patients B looked better. The reason is allocation. Large stones are harder to treat, and doctors gave the hard cases to A. Stone size affects both which treatment you get and whether it works: it is a confounder.

The pooled success rate of A is a weighted average of its within-group rates, with weights set by who got A:

$$P(Y{=}1\mid A)=\sum_{s}P(Y{=}1\mid A,s)\,P(s\mid A).$$

If A's patients are mostly large-stone cases, A's average is pulled towards the lower large-stone rate, whatever A's quality. The fix is to compare within strata and then average with the same weights for both treatments, the population's mix \(P(s)\). This is adjustment (or standardisation), and it estimates the average effect of switching everyone from B to A:

$$\text{ATE}=\sum_s\big[P(Y{=}1\mid A,s)-P(Y{=}1\mid B,s)\big]\,P(s).$$

Which answer is right depends on the causal story, not on the numbers. Here severity causes the treatment choice, so we adjust for it. If instead the variable were caused by the treatment (say, a side effect), adjusting for it would be a mistake. Data cannot tell these stories apart; a diagram of what causes what can.

Going deeper: causal diagrams and the back-door criterion

A causal diagram (DAG) draws an arrow from every cause to its effect: size → treatment, size → success, treatment → success. A back-door path is a path from treatment to outcome that starts with an arrow into the treatment (treatment ← size → success). Pearl's back-door criterion says: adjust for a set of variables that blocks every back-door path and contains no descendant of the treatment, and the adjusted comparison is causal. Here, adjusting for size does exactly that.

Adapted from: Charig et al., Comparison of treatment of renal calculi (BMJ, 1986), via Julious and Mullee (1994); Pearl, Glymour and Jewell, Causal Inference in Statistics: A Primer (2016), ch. 1 and 3.

2A/B tests: how many users, and why not to peek

Size a test for a conversion rate, then run 2,000 simulated A/A tests (no real difference) and stop each one the first time it looks significant.

Randomisation is the gold standard because it breaks every arrow into the treatment: a coin decides who sees version B, so nothing about the users can be related to which version they got, measured or not. The difference in average outcomes is then an unbiased estimate of the average treatment effect. What remains is noise, and the question is how many users you need to see through it.

For conversion rates \(p_0\) (control) and \(p_1=p_0(1+\text{lift})\), a two-sided test at level \(\alpha\) with power \(1-\beta\) needs about

$$n\ \text{per arm}\approx\frac{\Big(z_{1-\alpha/2}\sqrt{2\bar p(1-\bar p)}+z_{1-\beta}\sqrt{p_0(1-p_0)+p_1(1-p_1)}\Big)^2}{(p_1-p_0)^2},\quad \bar p=\tfrac{p_0+p_1}{2}.$$

The lift you choose is the minimum detectable effect. Because it is squared in the denominator, halving it quadruples the sample. Small baselines are expensive too: a 10% lift on a 1% conversion rate needs far more users than on 20%.

The second chart is the most common way A/B tests go wrong. A p-value is valid for one look at a sample size fixed in advance. If you check every day and stop as soon as \(p<0.05\), you get many chances for noise to cross the line, and the false positive rate climbs far above 5%. This is peeking. Each grey path is one A/A test's z-statistic over time; red ones crossed ±1.96 at some check.

Going deeper: sequential tests, CUPED and the guardrails

If you must look early, use a method designed for it: group-sequential boundaries (O'Brien–Fleming spend little α early and most at the end), or always-valid p-values and confidence sequences, which stay correct however often you look. CUPED reduces variance, and so sample size, by adjusting each user's outcome for their pre-experiment value of the same metric. Also check the sample ratio (a 50/50 split that comes back 48/52 signals a bug), and watch guardrail metrics such as latency and unsubscribes, not just the one you hope to move.

Adapted from: Kohavi, Tang and Xu, Trustworthy Online Controlled Experiments (2020), ch. 2, 17 and 22; Johari et al., Always valid inference (2015); Deng et al., CUPED (WSDM 2013).

3Propensity scores: comparing like with like

Observational data: more engaged customers are more likely to get a coupon, and spend more anyway. The true effect of the coupon is +1.0. See how far each estimate lands from it.

Without randomisation, the treated and untreated groups differ before treatment. If we have measured every confounder \(X\), we can compare them within groups that share the same \(X\). With many covariates that becomes impossible directly, but Rosenbaum and Rubin showed a single number is enough: the propensity score, each unit's probability of being treated given its covariates,

$$e(x)=P(T=1\mid X=x).$$

If treatment is as good as random once \(X\) is known (no unmeasured confounders) and every kind of unit had some chance of either choice (overlap: \(0<e(x)<1\)), then comparing treated and untreated units with the same \(e(x)\) is like comparing within a small randomised experiment. Two ways to use it:

  • Matching: pair each treated unit with the untreated unit whose score is closest, and average the differences.
  • Inverse probability weighting: weight each unit by one over the probability of the treatment it actually got, which builds a pseudo-population in which treatment no longer depends on \(X\):
$$\widehat{\text{ATE}}_{\text{IPW}}=\frac{\sum_i T_iY_i/\hat e_i}{\sum_i T_i/\hat e_i}-\frac{\sum_i (1-T_i)Y_i/(1-\hat e_i)}{\sum_i (1-T_i)/(1-\hat e_i)}$$
Algorithm: inverse probability weighting
  1. input covariates \(X\), treatment \(T\), outcome \(Y\)
  2. fit \(\hat e(x)\), e.g. logistic regression of \(T\) on \(X\)
  3. check overlap: histograms of \(\hat e\) for treated and control; trim extremes
  4. weights \(w_i\leftarrow T_i/\hat e_i+(1-T_i)/(1-\hat e_i)\)
  5. check balance: weighted means of \(X\) should match across groups
  6. return weighted mean of \(Y\) for treated − weighted mean for control

Raise the confounding in the lab: the naive difference drifts far from +1, while IPW and matching stay close, until the score histograms stop overlapping and a few units with tiny \(\hat e\) carry enormous weights. Propensity methods fix measured confounding only; nothing on this page can adjust for a confounder you did not record.

Going deeper: doubly robust estimators and double ML

A doubly robust (AIPW) estimator combines an outcome model \(\hat\mu_t(x)\) with the propensity model and is consistent if either one is right. Double/debiased machine learning (Chernozhukov et al., 2018) fits both with flexible ML models using cross-fitting, then estimates the effect from the residuals, which keeps valid confidence intervals even when the nuisance models are random forests or boosted trees.

Adapted from: Rosenbaum and Rubin, The central role of the propensity score (Biometrika, 1983); Hernán and Robins, Causal Inference: What If (2020), ch. 12–15.

4Difference-in-differences

A new policy starts in one region in month 7; a similar region does not get it. Set the true effect and how far the regions' trends differ, and see what diff-in-diff recovers.

Many changes cannot be randomised per user: a law passes in one state, a store layout changes in one city. A before-and-after comparison in the treated group mixes the effect with everything else that changed over time. A comparison between groups after the change mixes it with pre-existing differences. Difference-in-differences subtracts both:

$$\hat\tau_{\text{DiD}}=\big(\bar Y_{\text{treated,after}}-\bar Y_{\text{treated,before}}\big)-\big(\bar Y_{\text{control,after}}-\bar Y_{\text{control,before}}\big).$$

The control group's change stands in for what would have happened to the treated group without the policy (the dashed line). That only works under parallel trends: without treatment, both groups would have moved by the same amount. Levels may differ; trends may not. Push the trend slider and the estimate absorbs the trend gap as if it were effect. The usual check is to plot the months before the change and see that the lines run parallel, as you can in the lab.

In regression form, with a treated-group dummy \(G\) and an after dummy \(A\), \(Y=\beta_0+\beta_1G+\beta_2A+\tau\,(G\times A)+\varepsilon\); the interaction coefficient is the DiD estimate, and the regression gives its standard error (cluster it by group).

Going deeper: staggered adoption and synthetic control

When groups adopt a policy at different times, the classic two-way fixed-effects regression can give badly weighted, even wrong-signed, answers if effects change over time (Goodman-Bacon, 2021); newer estimators (Callaway and Sant'Anna, 2021) compare each cohort only with not-yet-treated units. When there is a single treated unit and no obvious control, the synthetic control method builds one as a weighted mix of untreated units that tracks the treated unit before the change.

Adapted from: Card and Krueger, Minimum wages and employment (AER, 1994); Angrist and Pischke, Mostly Harmless Econometrics (2009), ch. 5.

5Uplift modelling and Qini curves

A randomised campaign: half of 4,000 customers got an offer. The offer helps some, does nothing for others and annoys a few. Compare targeting by predicted uplift with targeting by predicted purchase.

Persuadablesbuy only if treated. Target these.
Sure thingsbuy either way. The offer is wasted money.
Lost causesnever buy. Wasted, but harmless.
Sleeping dogsbuy only if left alone. The offer costs you sales.

An A/B test gives one number, the average effect. Targeting needs the effect for each customer, the conditional average treatment effect \(\tau(x)=\mathbb E[Y(1)-Y(0)\mid X=x]\). A model of who will buy is not enough: the customers most likely to buy are often “sure things” who would have bought anyway. Uplift modelling estimates the difference the offer makes.

The simplest version is the two-model (T-learner) approach: fit one model on the treated customers and one on the controls, and score each customer with the difference,

$$\hat\tau(x)=\hat P(Y{=}1\mid X{=}x,T{=}1)-\hat P(Y{=}1\mid X{=}x,T{=}0).$$

We can never check \(\hat\tau\) for one customer, but we can check a ranking on a group. Sort customers by predicted uplift, and for the top fraction compare purchases among the treated with purchases among the controls, scaled to the same size. That cumulative gain is the Qini curve:

$$Q(k)=Y_T(k)-Y_C(k)\,\frac{N_T(k)}{N_C(k)},$$

where \(Y_T(k)\) and \(N_T(k)\) are the purchases and count of treated customers in the top \(k\), and likewise for controls. A random targeting order gives the straight diagonal; the area between a model's curve and the diagonal is the Qini coefficient. In the lab the uplift model's curve rises steeply (persuadables first) and then falls at the end (sleeping dogs last), so treating everyone is worse than treating the best part of the list. The purchase model mixes sure things and sleeping dogs into its top ranks.

Algorithm: a Qini curve
  1. input randomised data \((x_i,T_i,Y_i)\), uplift scores \(\hat\tau(x_i)\)
  2. sort customers by \(\hat\tau\), highest first
  3. for \(k=1,\dots,n\): count \(Y_T(k), N_T(k), Y_C(k), N_C(k)\) in the top \(k\)
  4. \(Q(k)\leftarrow Y_T(k)-Y_C(k)\,N_T(k)/N_C(k)\)
  5. draw the line from \((0,0)\) to \((n,Q(n))\) for random targeting
  6. return \(Q\) and its area above the line (Qini coefficient)

Pricing is a causal question too. The GLM Pricing Studio fits how claims or conversions vary with customer features, which is prediction. How customers would respond to a different price is a treatment effect: estimating price elasticity from historical quotes is confounded by how prices were set, so it needs price tests or the adjustments above.

Going deeper: S-, X- and R-learners, causal trees and forests

The S-learner fits one model with \(T\) as a feature; it can shrink small effects to zero. The X-learner (Künzel et al., 2019) imputes individual effects from the other group's model and works well when one group is much smaller. Causal trees (Athey and Imbens, 2016) choose splits that maximise differences in treatment effect rather than in outcome, using separate samples to choose the splits and estimate the effects (“honest” trees); causal forests average many such trees and give confidence intervals for \(\tau(x)\). Libraries: EconML, CausalML, DoWhy and grf.

Adapted from: Radcliffe, Using control groups to target on predicted lift (2007) for the Qini curve; Gutierrez and Gérardy, Causal Inference and Uplift Modeling: A review of the literature (2017); Athey and Imbens, Recursive partitioning for heterogeneous causal effects (PNAS, 2016).

6The same thing in Python

Sample size with statsmodels, inverse probability weighting with scikit-learn, difference-in-differences as a regression, and a two-model uplift with a Qini curve.

# pip install numpy pandas scikit-learn statsmodels
import numpy as np, pandas as pd
import statsmodels.formula.api as smf
from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import GradientBoostingClassifier

rng = np.random.default_rng(0)

# ---- 1. A/B test: users per arm for 10% -> 11% at alpha 0.05, power 0.8 ----
es = proportion_effectsize(0.11, 0.10)                       # Cohen's h
n = NormalIndPower().solve_power(effect_size=es, alpha=0.05, power=0.8, ratio=1)
print(f"about {np.ceil(n):,.0f} users per arm")

# ---- 2. Propensity scores and IPW on confounded data (true effect = 1) ----
N = 5000
x = rng.normal(size=N)                                       # engagement: the confounder
t = rng.random(N) < 1 / (1 + np.exp(-1.5 * x))               # engaged customers get the coupon more often
y = 1 + 1.0 * t + 2 * x + rng.normal(size=N)
print("naive difference:", y[t].mean() - y[~t].mean())       # biased upwards

e = LogisticRegression().fit(x[:, None], t).predict_proba(x[:, None])[:, 1]
e = np.clip(e, 0.01, 0.99)                                   # trim extreme scores
w1, w0 = t / e, (~t) / (1 - e)
ate_ipw = (w1 * y).sum() / w1.sum() - (w0 * y).sum() / w0.sum()
print("IPW estimate:", ate_ipw)

# ---- 3. Difference-in-differences as a regression with an interaction ----
df = pd.DataFrame({"region": np.repeat([0, 1], 24), "month": np.tile(np.arange(24), 2)})
df["after"] = (df.month >= 12).astype(int)
df["y"] = 10 + 2 * df.region + 0.3 * df.month + 3 * df.region * df.after + rng.normal(0, 0.5, len(df))
did = smf.ols("y ~ region * after", data=df).fit(cov_type="cluster", cov_kwds={"groups": df.region})
print("DiD effect:", did.params["region:after"])

# ---- 4. Two-model uplift (T-learner) and a Qini curve on randomised data ----
X = rng.normal(size=(8000, 3)); T = rng.random(8000) < 0.5
tau = 0.15 * (X[:, 0] > 0) - 0.10 * (X[:, 1] > 1)            # who is persuadable, who backfires
Y = rng.random(8000) < 0.10 + 0.05 * X[:, 2].clip(-1, 1) + tau * T
m1 = GradientBoostingClassifier().fit(X[T], Y[T])
m0 = GradientBoostingClassifier().fit(X[~T], Y[~T])
uplift = m1.predict_proba(X)[:, 1] - m0.predict_proba(X)[:, 1]   # use held-out data in practice

order = np.argsort(-uplift)
Yt, Tt = Y[order], T[order]
nt, nc = np.cumsum(Tt), np.cumsum(~Tt)
qini = np.cumsum(Yt & Tt) - np.cumsum(Yt & ~Tt) * nt / np.maximum(nc, 1)
print("incremental buyers if we treat the top 30%:", qini[int(0.3 * len(qini))])

For production work, DoWhy (modelling and refutation tests), EconML (double ML, causal forests) and CausalML (uplift learners and metrics) implement these methods with confidence intervals.
